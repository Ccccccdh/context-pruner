## 1. 本轮唯一改动：宿主层工具轮守卫

| 项目 | 值 |
|---|---|
| 实现 | `experiments/runners/crewai_loop_guard_v16.py`（SHA256 `857af92b…`） |
| 计数口径 | 只数**宿主自己**的 `^Action: <name>` 标记，按冻结工具表**顺序**推进，遇缺失或次序不符即停止计数 |
| 拒绝条件 | 工具表未走完时出现 `Final Answer:` |
| 拒绝动作 | 拒绝该收尾，追加**一条**控制消息（冻结工具表 / 已完成前缀 / 仍缺工具 / 下一步该调哪个），并**重新发起同一次请求** |
| 上限 | 每角色 `max_rejections = 6`（`limits.guard_max_rejections`） |
| 不可绕过 | 守卫状态存放在模块注册表（`register_guard_state`），按 `id(llm)` 键；模型文本无法读写它；守卫**不读模型输出里的任何声明**，只读宿主的动作标记 |

**负面控制（零 API，`tests/test_crewai_handoff_v16.py` 断言）**：① 模型提前收尾 → 被拒并继续（`rejections` 计数、`completed_rounds` 记录正确）；② 模型在**正文里声称**"我已经调用过其余工具" → 计数**不前进**（正文无动作标记）；③ 模型**重复调用**已调过的工具 → 计数**不前进**（该位置期望的是另一个名字）。

**失败语义（不得算作节省）**：达到上限仍不产出 `HANDOFF` 的角色 → `guard_exhausted: true`，该单元记为**失败单元**并**从任何节省主张中剔除**；额外的拒绝重发请求**全额计入该臂与全局账本**（`api_request_attempts`）。守卫**永不**把耗尽单元重新打分成功。

**视图不变的逐字节断言**：同一边界、同一 prepared messages，压缩后模型可见内容与 r15 所用机制（冻结 r13）**SHA256 相同**；且 `GUARD_PREFIX`（`Host control: the evidence loop is not finished.`）**不出现在任何被服务的视图里**——控制消息只存在于拒绝路径。无违规的运行与 r15 逐字节一致。

## 4. 预注册验收线（三条全中才算"有效节省候选"）

1. **行为等价**：`pruner_v1` 臂 `tool_sequence_consistent` **= 12/12**，且逐任务不低于同任务基线；`first_pass_facts` 不低于基线；`guard_exhausted` = 0。
2. **质量不劣**：严格与语义成功数**逐任务 ≥ 基线**且全批 ≥ 基线。
3. **成本为正（改正后的口径）**：**同工作量**（两臂 agent 调用数相同且第一角色工具轨相同）前提下，
   `bound(unit) = Σ_calls (无压缩每调用输入 − 压缩后每调用输入) − 保护成本`，
   保护成本 = 钉住字符 ÷ 2.41 + 受保护整轮重读字符 ÷ 2.41 + 整份回退 token + 摘要 token；
   **配对多数为正且全批配对均值为正**。**少调工具、少调用模型一律不计作收益**（该单元记 `not_pairwise`／失败）。

> **作废口径声明**：r15 预注册的"首帧**一次性**文本上界 +10.247%"**已作废**（实测同工作量 +35.16% = 3.43×）。本协议及本批审计**不得**再引用该值作为成本门。
