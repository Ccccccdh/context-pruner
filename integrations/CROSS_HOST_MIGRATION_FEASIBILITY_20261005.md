# 跨宿主工作点迁移：零 API 可行性卡（2026-10-05）

## 决策

**当前不启动付费迁移实验。** 已有材料能够验证三个适配器能运行，但还没有一个可作为“宿主 A 有效工作点”的配置：按四判据（多任务、多重复、质量不降、稳定正节省），三个宿主均未同时过线。若现在把一套数字照搬到另一宿主，即使出现收益或损失，也不能解释为“有效工作点迁移损失”。这是前置条件未满足，不是迁移不可行的实验证明。

## 现有候选的逐项核对

| A → B 候选 | 真实共同任务形态 | 工作点 / 单位是否可原样解释 | 质量与审计前提 | 判定 |
|---|---|---|---|---|
| OpenAI Agents v11 → OpenHands | 两宿主都曾用 SWE-bench `django__django-16263`，但 Agents v11 是固定源码片段的**只读根因诊断**；OpenHands v38/v39 是**改代码并跑宿主目标测试** | v11 的 `M=4` 是最近 4 次 `function_call` 与应答配对；OpenHands v38/v39 压缩的是事件视图，v61 的 28,000 是宿主视图估计 token 阈值。原样写入并没有同一省略语义 | v11 质量 2/3 < 无压缩 3/3；v38 三臂目标测试均失败。共同 issue ID 不构成共同质量尺子 | **不合格** |
| OpenHands v61 → OpenAI Agents | v61 用 `django__django-16661` 等 Django **代码修复**；Agents v11 仍是 `django__django-16263` **诊断** | v61 用真实事件前缀与 28,000 视图阈值；Agents 历史被包装为 chat-completions 消息与工具调用。没有定义事件到调用的保真映射 | v61-01 三臂宿主判定均失败，且独立审计未签署；v61-02 未越阈值 | **不合格** |
| CrewAI r9 → 另两宿主 | r9 是模拟运维双角色决策；另两宿主用公开 Django 源码。无共享任务合同 | r9 压缩角色间历史与工具轮；其事实固定、首轮事实与严格合同守卫不能直接映射到源码诊断或修复 | r9 独立审计完整，质量三门不劣、配对 +8.01%，但收益主要集中在一个任务，后续新任务未稳定复现 | **保留为机制参考，不做原样迁移** |

`django__django-16263` 的共同 ID 已核对 `integrations/openai_agents/REPO_DIAGNOSTIC_V11_ELISION_RATIO_PROTOCOL.md`、`integrations/openhands/PILOT_PROTOCOL_V39.md` 和 `integrations/openhands/V38_PILOT_REVIEW.md`。源代码问题相同，任务合同与输出产物不同，因此不能配对比较质量或 token。

## 数值不能直接移植的另一原因

`experiments/runners/token_policy.py` 按已记录批次给出的供应商计费 token / 本地估算 token 中位比值为 OpenHands **0.900**、OpenAI Agents **0.368**、CrewAI **0.389**。例如同样写本地估算阈值 28,000，按各自的**历史标定**约对应 25,200、10,304、10,892 供应商 token；这只是量纲换算示例，不是新任务的实测阈值或可迁移配置。新实验必须先在相同模型、传输路径和真实载荷上重新记录阈值两种单位，再比较触发与候选省略量。

## 若继续填 L2，按此顺序准备

1. **先定共同任务合同。** 优先选同一公开 Django issue、同一任务目标、同一可用工具与同一质量判据，分别由两个宿主执行；不能把“诊断成功”与“修复测试通过”当同一标签。CrewAI 若加入，必须先有同形的源码任务适配与对等验收。新任务不能参加工作点选择后再冒充盲测。
2. **先得到 A 的可引用工作点。** 在 A 上用未参与调参的多任务多重复批，预注册质量不劣、完整供应商总 token 多数配对为正和任务间离散限制。审计必须完成；失败与触顶全部计入。
3. **写配置映射表。** 把 A 的省略单位、近度窗口、受保护事实、回退条件、soft/target/hard 的 provider token 与 estimator token、请求预留逐项映射到 B；无等价单位就记为“不能原样迁移”，改为研究适配机制，不强算迁移效果。
4. **用两边真实载荷零 API replay。** 对同一任务记录真实模型输入结构、触发是否可达、守卫后安全候选集合、压缩前后工具调用配对与关键证据、恢复成功、前缀后验证预算。真实载荷筛查方法见 `REAL_PAYLOAD_PRESCREEN_20261005.md`。任一安全集合为空、质量证据丢失或预算不足即停。
5. **最后冻结付费比较。** 同任务、同重复种子、相同臂顺序规则，至少比较 B 无压缩、B 本地重调配置、B 直接迁入 A 配置；若评估原生摘要则加第四臂。新 ID、新失败线、新审计，报告完整成本、质量、触发率与调整工作量。不能把跨宿主百分比合并为一个节省率。

现阶段最值得做的零 API 后续工作是**共同任务合同与单位映射草案**。在它们成立以前，不预注册付费样本数，也不解除三宿主各自的失败停止线。本卡只核对现有证据，不修改旧结果或冻结文件。
