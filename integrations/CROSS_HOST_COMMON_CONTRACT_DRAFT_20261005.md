# 跨宿主共同任务合同与单位映射草案（2026-10-05，零 API）

本文件是 `CROSS_HOST_MIGRATION_FEASIBILITY_20261005.md` §「若继续填 L2」第 1、3 条的**准备件**，不是付费预注册，也不解除任何宿主现有的停止线。它只定义"若要比较迁移损失，两边必须先同构到什么程度"，以及"哪些数字必须重测而不能照搬"。

**前置条件状态（不变）**：按四判据（多任务 / 多重复 / 质量不下降 / 稳定正节省），**三个宿主都没有可引用的工作点**，因此**当前不启动付费迁移实验**。本草案的作用是把这个前置条件本身做成可执行的清单。

---

## 1. 共同任务合同（两宿主必须在同一标签下比较）

**选择：只读诊断合同（diagnosis-only），不是"诊断 vs 修复"。**

理由：`CROSS_HOST_MIGRATION_FEASIBILITY` 已判定"诊断成功"与"修复测试通过"不能算同一标签；而 OpenAI Agents 适配器在当前设计上**只读**，OpenHands v61 的强制只读调查阶段已证明"只用 `view` + `symbols`"是可运行的受限模式。因此最低成本的同构方式是把两边都约束成只读诊断。

| 合同项 | 规定 | 理由 |
|---|---|---|
| 任务来源 | 同一公开 Django issue（同一 base commit），**且未参与任一宿主的调参** | 参与过调参的任务不能事后冒充盲测 |
| 可用工具 | 两边都只给：查看文件 / 按符号定位 / （OpenHands：跑目标测试只读） | 工具集不同则省略单位不可比 |
| 交付物 | 同一文本合同：失败测试 id + 归属文件与符号 + 一行根因 + 依据字面（`research_files` 逐字出现的证据） | 使"严格格式"判据可跨宿主复用 |
| 质量判据 | **同一判据器**：严格格式 + 语义等价（语义轨仅接受同事实同决策的措辞差异，不接受缺事实/错数值） | 三把不同的尺子不能比较迁移损失 |
| 矩阵 | 同任务 × 同重复数 × 同臂顺序规则；臂 = B-无压缩 / B-本地重调 / B-迁入 A 配置（原生摘要可选第四臂） | 只比较三方才能把"迁移损失"与"本就无效"分开 |
| 禁止 | 不把跨宿主百分比合并；不用单任务高收益替代确认 | 既有纪律 |

CrewAI 若要加入，必须先有**同形的源码任务适配与对等验收**（当前它是合成运维双角色，仅作机制参考、不做原样迁移）。

## 2. 省略单位映射（当前无等价单位，逐条记"不能原样迁移"）

| A 宿主 | A 的省略单位（实测形态） | B 宿主的对应单位 | 是否同构 | 若要研究适配 |
|---|---|---|---|---|
| OpenHands v61 | 事件视图里的**旧事件/轮**；v61-01 真实 replay 可省略单位 209（v58 为 183） | Agents：`function_call` + 应答**配对**；CrewAI：角色历史 + 工具轮 | **否**——事件含文件状态与观察文本，没有定义过的"事件→消息"保真映射 | 先写事件→消息映射器并逐边界断言：映射后工具配对唯一、观察文本可定位、文件状态无丢失 |
| OpenAI Agents v11 | **最近 M 次工具调用**（M\*=4）之外的可省略调用 | OpenHands：事件视图阈值（28,000 视图估计 token）非"最近 K 轮" | **否**——一个是"序号窗口"，一个是"预算阈值 + 事件序列" | 在 OpenHands 侧定义"保护最近 K 轮"等价规则并 replay 验证候选集合 |
| CrewAI r13 | 角色间历史 + **最近 K 个工具轮**（K=3） | 另两宿主 | **否**（任务形态不同） | 只作为机制参考；不复用其百分比 |

**结论**：三对候选**目前全部记为"不能原样迁移"**；迁移实验的第一步产物应是**单位映射器 + replay 断言**，而不是付费批。

## 3. 阈值与量纲映射（必须重测，禁止照搬）

- 既有标定（**旧批**中位比值，仅供量纲说明）：OpenHands **0.900**、OpenAI Agents **0.368**、CrewAI **0.389**（`experiments/runners/token_policy.py`）。
- 同一句本地估算阈值 28,000 按旧标定约折合 25,200 / 10,304 / 10,892 供应商 token——**这不是新任务的实测阈值**。
- **规则**：新实验必须先在**相同模型、相同传输路径、相同真实载荷**上重新记录"供应商计费 token ↔ 本地估算 token"两种单位，再比较触发与候选省略量；阈值一律以 provider token 申报并写入 manifest，估算值只作内部换算。

## 4. 保护集与回退的等价接口（草案）

| 概念 | OpenAI Agents | CrewAI | OpenHands | 统一接口草案 |
|---|---|---|---|---|
| 当前决策所需的字面证据 | 注册字面（registry literal）+ 承载单元 | `handle_facts` 冻结列表 | `research_files` 逐字 + allowed paths | `protected_units(task, boundary)`：返回**字面 + 其承载单元**，逐边界快照 |
| 工具调用边界 | `function_call` ↔ 应答配对 | 工具轮（tool round） | 事件（action/observation） | `tool_boundary(unit)`：任何压缩不得切断配对 |
| 失败时的行为 | 整份前缀回退（`whole_prefix_fallbacks`） | 整份回退 | 整份回退 | 回退必须**记账**且计入成本（三宿主一致） |
| 辅助调用 | 原生摘要请求 | 摘要请求（23 次/批量级） | 原生摘要 | 摘要与补救请求全额计入本臂与全局账本 |

## 5. 请求额度映射（OpenHands 的恒等式要迁移成通用形式）

v61 的 `132 = 42 + 30 × 3` 对应"前缀预算上限 + 每臂保留额度 × 臂数"，且 v61-01 实测前缀只用了 38 次（`132 − 38 = 94 ≥ 90`）——**跨宿主通用形式**建议写成：

```
总 cap ≥ 共享前缀上限 + 每臂保留额度 × 臂数
共享前缀实际用量 + 每臂保留额度 × 臂数 ≤ 总 cap
每臂保留额度 ≥ (一次纠错 + 一次宿主/判据验收) 的最小请求数
```

分支/分叉**不得**重新获得已消耗的请求额度（OpenHands 已有前缀账本深拷贝门控，另两宿主需实现等价物）。

## 6. 迁移批的预注册清单（等前置条件成立后才可启动）

1. 共同任务合同（§1）冻结：issue、base commit、工具集、交付物文本合同、判据器、重复数与臂顺序规则。
2. A 侧工作点必须**已是可引用工作点**（多任务多重复、质量不劣、审计完成、失败与触顶全计入）——**当前不满足，这就是本实验的阻塞点**。
3. 单位映射器 + 两边真实载荷 replay：逐边界断言触发可达、守卫后安全候选非空、工具配对与关键证据保留、恢复记账、前缀后验证预算充足（任一为空/丢失/预算不足即停）。
4. 阈值双单位重测（§3），写入 manifest。
5. 付费比较（三臂/四臂）用新 ID、新失败线、新审计；报告**完整成本、质量、触发率与调参工作量**；跨宿主百分比不合并。

---

## 7. 本草案的边界

- 它是**设计件**：不含付费样本数，不含新实验 ID，不修改任何旧批结果、冻结文件或评分。
- 它**不**主张迁移会成功或失败：它只把"前置条件不满足"这一现状变成可勾选的清单。
- 与 `REAL_PAYLOAD_PRESCREEN_20261005.md` 的五条顺序门控配合使用：预筛负责"该不该付费"，本草案负责"若要比迁移，两边必须同构到什么程度"。
