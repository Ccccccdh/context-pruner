# OpenHands v54：同前缀分叉的实施门控（草案，零 API）

状态：已完成 SDK `fork()`、文件隔离与真实 Django 树恢复的零 API 门控；**没有运行付费样本**，也没有把 v53 的独立轨迹当作同前缀比较。

## 为什么先做分叉

v53 的 `referenced_window_wrapping` 最大负号在第一次压缩前已超过同重复基线的全程输入量。三臂独立起跑会产生不同的源码导航和纠错路径，无法把成本差异归因于压缩。下一次机制实验从一条无压缩的真实代码任务历史复制出相同事件前缀，再比较继续执行。

## 已验证的 SDK 能力和限制

- 安装版 OpenHands SDK `LocalConversation.fork(agent=..., reset_metrics=True)` 复制事件、HEAD 与 Agent 状态；本项目的 `tests/test_openhands_same_prefix_fork_v54.py` 用真实 SDK 会话验证事件 ID 相同、无模型请求。
- SDK 的 fork **默认复用原工作区**。`same_prefix_fork_v54.py` 验证了拷贝文件并重绑 `conversation.workspace`、`conversation._state.workspace` 可隔离写入，但这两个状态字段不是 SDK 的稳定公开接口，升级后必须重新运行门控。
- v53 初始提示和一些工具结果含**绝对工作区路径**。直接把旧事件前缀接到不同路径的分叉，会引入路径差异。因此正式实验应在同一个绝对工作区路径上**顺序**运行各分叉：每条分叉开始前从只读快照恢复，并核对完整文件哈希；每条分叉的会话状态、LLM、用量账本和输出目录彼此分开。不能同时运行这些分叉。`capture_workspace` / `restore_workspace` 的零 API 测试已覆盖新增、修改、删除文件与工作区外路径拒绝；真实 Django 20,129 文件恢复后完整哈希相同。
- fork 构造器没有继承调用方的 event callback。`attach_branch_callback` 已在真实 SDK 的 `send_message()` 零 API 测试中验证分支回调收到一次事件、前缀及源会话不变、重复挂载被拒绝；这尚不能证明一次真实工具执行与模型续跑中的用量统计完整。
- SDK 的 Agent 序列化往返会丢失本项目 `BudgetAwareLLM` 的私有用量账本和预算对象。`fork_with_agent` 在 fork 后重新绑定独立 Agent，并在真实 SDK 测试中核对 LLM、账本、预算对象均保持原身份；同一 Agent 被两个分支共用会被拒绝。该处理也依赖 SDK 私有状态，升级后必须重新门控。

## 拟冻结的实验流程

1. 从 `none` 臂独立运行**共同前缀**，在第一阶段结束后立即保存事件 ID 序列、源文件哈希、整个工作区快照和 provider 用量。先用宿主测试选择预先规定的“需要纠错”状态；若通过，按协议记录为不适用，不事后挑一个有利前缀。
2. 从同一个 prefix fork 三次，分别配置 `none`、原生摘要和候选插件。三次使用相同的宿主失败反馈、同一绝对工作区路径、相同工具边界与请求预算；顺序轮换。每次开始前恢复快照，恢复后哈希必须等于冻结值。
3. 分叉后按原宿主测试与不变上游回归测试评估质量。主机制统计量为**分叉后的**含所有辅助请求总 token，另报告将共同前缀费用各计一次的全程总量。失败和触顶分叉都进入配对结果。
4. 先 1 个真实任务×1 个前缀×3 臂的小试，再在 3 个任务×3 个共同前缀上复验。若同前缀节省和质量门控通过，再把机制带回独立起跑的多任务、多重复全程批次。小试不得用于估计插件在所有任务上的平均效果。

## 付费前还必须过的零 API 门控

- 相同绝对路径的快照恢复：包含**新增、修改、删除**文件，恢复前后完整哈希相同；任何工作区外路径一律拒绝。小型树与 SDK 分叉测试 5/5、真实 Django 树 1/1 已通过。首次串行门控耗时 989.38 秒；并行哈希和复制后的真实树门控耗时 412.07 秒。这是单机前后实现比较，不是控制了缓存条件的严格加速比。准备函数 `prepare()` 仍按旧实现串行复制与哈希基线，也是剩余耗时来源。
- 源会话事件前缀、三分叉事件前缀、Tool 的工作区参数与宿主反馈逐项相同；分叉内部状态和产物不得互写。
- SDK 回调补接的单事件交付已过真实 SDK 零 API 测试；还须在模拟工具执行与模型续跑的 loopback 中证明事件持久化一次、预算统计一次、请求用量独立记录一次，并核对三个分支的工具作用范围。
- 三种 condenser 在分叉后的第一轮具有相同输入前缀；插件确实触发至少一次压缩，否则该小试只报告为未触发机制。
- 固定任务、模型、脚本哈希、请求和摘要上限、成功判定及审计脚本，再发送任何模型请求。

以上门控未全部完成前，不启动 v54 付费运行；这与用户已授权付费实验的范围无冲突，目的是避免花费后发现比较条件不同。
