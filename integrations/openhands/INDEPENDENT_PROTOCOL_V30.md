# v30：预算提示与验证、收尾预留

这是运行框架的开发复验协议。沿用 v29 已接触的 Click/packaging 合同与验收、冻结的 v11 压缩器；不称独立盲测。三个组都使用相同预算控制器，不能将共同框架改动归为插件独有效果。v29 源码及原始结果保留。

## 请求预算

每样本最多 36 次 Agent 请求，首次与纠错共享计数。最多前 34 次用于工作；未提前结束时第 35 次仅允许 scoped_tests，第 36 次仅允许 Finish。已经观察到当前代码版本公开验证通过时，可以提前 Finish。验证失败或缺失时，收尾必须报告未完成，不能计为成功；公开回归通过也不能代替宿主功能验收。修改代码后验证失效。

每次 Agent 请求在压缩之后、调用接口之前追加临时宿主预算消息，显示包含本次的剩余请求数、剩余工作请求数、剩余估计输入和验证状态；不写入原始会话历史。ledger 保存实际提示、工具限制、估计输入和响应校验。提示不新增模型请求。

单请求估计输入上限 80k，总估计输入上限 2m；工作及摘要不能消耗为两个收尾请求预留的最多 160k 输入。单请求估计输入到 68k 时提前关闭工作，留 12k 余量。原生摘要最多 16 次，不占 Agent 请求计数，但计入共享输入预算。估计输入不是供应商计费 token 或余额；超大验证输出仍可能超过单次上限，预留不能保证任何上下文都可执行。

保留模型、输出上限、零重试、故障熔断、轮转顺序、文件边界和验证工具限制等 v29 设置。纠错仅在存在未预留工作请求且输入预算足够时执行，不重置预算。响应执行前检查工具名及收尾阶段限制，阻止编辑与 Finish 混合批次使用旧验证。

## 本地门控与后续实验

先用模拟模型响应驱动真实 OpenHands SDK 会话，验证 34 次工作后验证及 Finish、成功和失败验证、代码版本变化、输入预留、历史不变和非法工具响应阻断。此门控不发送 API 请求，也不证明真实模型成功率提升或供应商 tool_choice 兼容性。

后续付费复验另建输出目录，先 --check，后 --run --resume；默认 2 任务 × 3 重复 × 3 组。首次请求前冻结协议和源哈希。保留失败、负收益、未压缩样本；主指标仍为全部六对逐对输入节省率均值。新结束口径加入当前代码公开验证通过，以 crosscheck_budget_completion.py 校验；宿主验收仍需通过。不能用改变预算规则后的 v30 与 v29 差异证明插件因果收益。真实运行结束后再做独立复测、审计及汇总。
