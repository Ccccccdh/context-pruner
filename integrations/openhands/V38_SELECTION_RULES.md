v37 首个候选 `pylint-dev__pylint-8898` 功能门控通过，但没有自然长上下文适配证据；决定不用付费样本，完整原因见 [v37 复核](V37_CONTEXT_FIT_REVIEW.md)。本规则在查看下一候选源码前记录；依据 v36/v37 开发观察制定，所以 v38 也不称严格独立盲测。

## 候选次序

使用同一 SWE-bench Verified Parquet 元数据，排除已用的 `pytest-dev__pytest-10356` 和开发性筛过的 `pylint-dev__pylint-8898`。仅考虑参考修复涉及 3～4 个 Python 源码文件、至少 1 个目标测试、难度 1–4 小时或更长的实例。按问题创建时间从新到旧检查；不以模型结果、修复是否容易或预期节省率调整顺序。单个候选的公开仓库可获取后，先计算**不查看参考修复正文**的相关源码总字节数，并只读检查是否确有跨模块调用或状态流。若合计不足 50 KB，或调用链实际上局限一个短函数，记录原因，按顺序检查下一个。50 KB 是筛选代理，不能证明一定会达到 20k token。

## 零 API 门控与停止

通过自然长度初筛后，在隔离环境验证固定基线、公开回归、目标测试原版失败、参考实现通过、宿主补丁隔离和源码哈希稳定。任何环境或门控失败都保留日志，按相同顺序继续。首个同时通过长度初筛和功能门控的候选才可制定冻结三组协议。新任务的 payload、模型调用与费用需要单独授权；本规则不授权付费运行。首轮仍限 1×1×3，若未压缩或质量失败，停止扩大。无论结果正负都保留完整样本。

DeepSeek 可只读梳理公开基线的调用链和自然阅读量；主 Agent独立复核筛选、门控和结果。参考修复与目标补丁仅在宿主副本。下一版运行器还需修复 v36 的重复全树哈希，完成零 API 检查后再冻结源码。
