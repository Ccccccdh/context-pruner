# v41 Django 已见任务开发小试：负结果与协议偏差

用户授权后，使用 v41 新目录完成 1 任务×1 次×3 组。任务仍为
`django__django-16315`，已在 v40 查看结果，故本轮仅是开发复验。
零 API 正负门控和本地回放先完成；三组模型运行未覆盖 v40 原件。

| 组别 | 最终宿主验收（51 项） | Agent 请求 | 供应商输入 token | 压缩事件 |
|---|---|---:|---:|---:|
| 无压缩 | 通过 | 21 | 321,151 | 0 |
| 原生摘要 | 通过 | 17 | 228,665 | 0 |
| v41 插件 | 失败：1 失败、11 错误 | 36 | 582,341 | 4 |

插件相对无压缩**多用 81.33%** 输入，相对原生摘要多用
154.67%；原生摘要没有触发摘要。三组 API 请求均成功。
v41 插件 4 次压缩的 `task_contract_chars` 均为 109，范围提示
确实进入压缩记忆且无硬预算超限；插件组没有尝试越界编辑，
但这不能证明范围提示改变了模型选择。无压缩与原生摘要在首次
宿主验收即通过；插件首次仍有 1 个错误，修正后回归扩大。

独立复测确认三组最终结果、编辑边界、归档引用和密钥扫描。
审计还发现**协议偏差**：冻结说明与原审计器规定宿主反馈后的
修正请求最多 10 次，插件实际用了 16 次。根因是共享
`FeedbackReserveBudgetPolicy` 将首次阶段提前结束后省下的请求
全部释放给修正阶段，虽未超过每样本 36 次总上限，仍违反
预定的阶段上限。原审计脚本保持不改；另存的事后审计
`audit_validation_v41_actual.py` 把 `protocol_valid=false` 和
逐样本偏差写入 `audit.json`。本轮不能作为合规的效果验证。

最终代码的直接失败原因可由与公开基线的差异核对：插件组把
`QuerySet._check_bulk_create_options()` 的返回值由单个
`OnConflict`/`None` 改为三元组，但调用方仍将整个返回值作为
`on_conflict`；同时 SQL 编译器只改了字段转列名。三元组使
普通和冲突批量插入路径均改变，最终出现多项唯一约束错误。
这属于生成代码语义与回归错误；无法仅凭时序断言由压缩造成。

已新增共享 `StrictFeedbackReserveBudgetPolicy`，显式以修正开始时
的请求数设定最多 10 次修正，保留最后验证与 Finish；相关
新旧本地预算、范围测试 6 项通过。它未参与 v41 付费结果，
不能事后修正本轮。下一轮冻结协议时才接入，并先做零 API
门控。建议停止在此已见 Django 任务上的重复付费筛选，
转向未参与调参的新任务与跨宿主验证。
