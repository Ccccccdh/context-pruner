# CrewAI r25 覆盖守卫有界开发小试

r24 只完成了零 API mock，审计器误将 mock 的模拟角色调用当成真实供应商调用，按 API 捕获规则拒绝 9 行。该冻结批原样保留、未付费。r25 区分 mock 与 API 的账本规则：mock 必须 0 供应商槽且全网格质量检查通过；API 必须逐调用捕获与 token 总量吻合。付费入口只接受最终写一次冻结，mock 可用 `.tooling/tmp` 草稿冻结做门控。

目的：验证全臂一致的顺序无关覆盖守卫能否修复 r23 插件臂第一角色提前交接。只用 `ledger_lock_attestation` 一项已暴露开发任务 × 3 重复 × `none/pruner_v1/native_summary` 三臂，共 9 样本。属于**开发小试**，任何正结果都不能称独立确认。

冻结行为：DeepSeek `deepseek-v4-flash`、thinking disabled、每次最大输出 512、每样本摘要最多 4 次、全批累计最多 **120 次**供应商尝试。每次尝试在发送前写入并 fsync 持久槽；不允许 `--resume`，中断批保留。三个臂的第一角色均安装同一覆盖守卫：每个来源至少由该角色实际调用一次，调用顺序与重复不限制；漏读时最多拒绝 6 次，每次重发与摘要均全额计费。第二角色照旧完成决策。

独立审计先核冻结源码、9 格网格、120 次上限、持久槽连续且等于三臂记录请求数、三臂 Agent 与摘要逐调用捕获完整且 token 总数相符、守卫确实全臂安装。质量门：三个臂各 3/3 第一角色来源覆盖、插件严格和语义成功数均不低于无压缩、无守卫触顶。成本门：插件对无压缩的完整供应商 token 配对至少 2/3 为正、配对总差为正。**两门同时通过**才算开发小试通过；`can_be_quoted_as_saving` 始终 false。

付费前：CLI `--plan` 不创建批次；完整 mock 九格审计通过；真实 r23 的“成本正但质量失败”与“原生摘要捕获为空”两条负控制被新审计拒绝。若任何门失败，停止在该批，不扩任务或重复。若小试通过，另选全新任务集做前瞻确认。
