## 3.5 为什么**不能**用"可省略单位数量"论证收益（预筛反例 + 本宿主的第四个反例）

预筛 `integrations/REAL_PAYLOAD_PRESCREEN_20261005.md` §1–§2 已给出本宿主的反例：
**"候选旧单位数量非零"不能预测可接受收益**。本协议把该结论当作**设计前提**，而不是注意事项：

| 批次 | 旧单位候选上界 | 插件 / 基线严格成功 | 插件完整总 token 配对 | 结论 |
|---|---:|---|---:|---|
| v9 | 0、0、0 | 3/3 / 3/3 | −0.000004 % | 候选为零 → 不值得付费（**筛除**信号有效） |
| v10 | 5、5、5 | **0/3** / 3/3 | +27.68 % | 候选非零，收益出现，质量坍塌 |
| v11 | 2、2、2 | **2/3** / 3/3 | +5.81 % | 候选非零，收益小，质量仍掉 |
| **v12** | **守卫后 3** | **0/1** / 1/1 | **+14.63 %** | **不变量门全绿**，严格失败＝答复长度（模型侧措辞） |

因此本协议的规则是：

1. **两个数必须分开报**（预筛 §2 第 3 条）：`potential_old_units_upper_bound`（冻结机制可能碰到的更早单位）
   与 **守卫后安全候选（guard-filtered safe candidates）**——后者在**判定边界**上、按真实载荷逐边界
   通过五项守卫后才计数：①每个注册字面 presence ≥ 1；②每个唯一源仍有一份全文；③去 id 工具组哈希不变；
   ④源指针指向同一 payload 内更新的全文副本；⑤无恢复/整份回退，且无未记账回退。
2. **候选为零 → 停止付费**（v9 模式）；**候选非零 → 不作任何收益或质量预测**。v10/v11/v12 三行按
   同一方向证伪了"候选数量→可接受收益"这一推断，**禁止**把它写进任何收益预期或验收论证。
3. 能不能继续，由**两个不同通道**分别决定：**机制侧**看**不变量门**（丢失或未记账回退＝先修机制，
   不得改判质量）；**模型侧**看**双轨质量**（必须实测，不能由候选数量推断）。v12 正是"门干净、质量照样
   不达标"的实例。
4. 付费路径按预筛 §2 的**顺序门控**走：证据门 → 曝光门 → 非零收益空间门（上面两个数）→ **不变量门**
   → 小试与确认门。任一门失败即停止该候选并记录原因；全部通过也只允许进入小试。

## 4. 双轨质量判据（预注册）

**Track A（严格，验收主轨）**：`final_output` 满足全部四条——以
`RESULT issue=requests-1766 cause=` 开头、不含换行、长度 ≤ 160 字符、且
`re.fullmatch(pattern_A, output, flags=re.IGNORECASE)` 命中。`pattern_A` 在 Stage 0 与字面表一并冻结，
含**必需字面**（issue 与基线源码中真实存在的标识符）与**顺序 + 边界**约束。

**Track B（语义等价，诊断副轨）**：同一前缀、同单行；`cause=` 与 `fix=` 两个字段都在；
每个必需字面以"词边界 + 顺序"方式出现（字段内分隔符可放宽为非字母数字，允许 `cause=` 内
有额外解释文字）；`cause=` 与 `fix=` 合计长度 ≤ 400 字符；**禁止字面**不得出现。

**适用边界（硬性，写在冻结里，不允许事后放宽）**：
> Track B **只**覆盖"同一批事实、同一决策下的措辞差异"——语序、标点、连接词、在 `cause=`
> 内补写解释。它**不得**覆盖：必需字面缺失、`fix=` 字段缺失、数值/标识符错误、决策标签不同、
> 或补充解释与注册事实相矛盾。Track B 通过而 Track A 不通过时，结论必须写成
> **"严格轨未达；语义轨通过（措辞差异）"**，**不得**写成"质量不降"，也不得据此把该批
> 升格为确认结果。

**报告规则**：Track A 与 Track B 的成功数分别报告，任何汇总表都不得把两条轨道合并成一个
"质量"数字；跨宿主百分比同样不得合并。

## 5. Replay 门（付费前置，五项缺一不可）

1. **Stage A 记录运行**（有界、单臂）：只跑 `none` 臂，1 任务 × 1 重复，请求上限 **12**。
   目的只有一个：取得该新任务的**真实模型输入**记录——逐边界 `input_sha256`、`input_bytes`、
   `item_count`、`message_items`、`output_items`、`turn_count`，以及**每个源码输出的 SHA256 与字符数**。
   Stage A 不含插件臂，因此不产生任何插件的成本或质量信息，不构成对机制的调参。
2. **零 API 重建必须复现记录**：逐边界复现结构、工具项连续性、每个输出的 SHA256/字符数。
   **不得使用自造桩**（v9 教训：自造桩能错"载荷结构"，不只是轮次数）。
3. **插件臂逐项可复算**：保留项与被替换前逐字节相同；指针项必须**恰好等于**
   `[Exact duplicate output; full source is at call_id=<最新副本 call_id>; sha256=<源码 SHA256>]`，
   且其指向的全文副本仍在同一 payload 内、位置更新。被替换位置集合必须与记录中
   "字符数/哈希与基线不同"的位置集合逐一相同。
4. **事实 presence 检查（fail-closed）**：任一必需字面在缩减侧的 presence（出现次数 > 0）
   归零即门失败。**负控制**必须同时通过：把一个**唯一**证据项替换为指针时，检查必须报出
   丢失字面（即该检查不是恒真断言）。

5. **不变量门（预筛 §2 第 4 条，逐边界，判定边界为准）**：必须产出五列机械证据——
   **任务约束**（注册字面 presence/计数，两侧）、**当前证据**（每个唯一源的全文副本仍在）、
   **工具组哈希**（去 id 的有序结构哈希，两侧相同）、**恢复/整份回退记账**（每次恢复失败或整份
   回退都要有计数与原因，且不能有"有计数无原因"或"有原因无计数"）、**源定位**（每个指针都能在同一
   payload 内解析到更新的全文副本，且摘要与目标一致）。
   **规则（硬性）**：任一丢失或回退未记账 → **先修机制**，不得改判质量；反过来，门干净也**不等于**
   质量可接受（v12 即门干净而严格质量仍不达标）。v12 的五列证据见
   `integrations/openai_agents/V12_DECISION_BOUNDARY_ANALYSIS_20261005.md`，其逐边界实现为
   `experiments/runners/openai_agents_decision_boundary_v12.py`，可复用于新任务。

通过后，冻结文件一次性写入（写定后不得修改；需要修订时另建
`V13_*_FREEZE_AMENDMENT_<日期>.json`，并在批次 manifest 里记录**冻结文件自身 SHA256**）。

### 7.1 本轮为什么**没有**执行有界"载荷获取"运行

本轮获授权可执行一次有界载荷获取（新 ID、仅无压缩臂、单任务×1 重复、请求上限写死、不得表述为
节省证据）。**未执行**，因为它的前置（证据门）在本轮不可满足，而证据门未满足就花钱违反预筛 §2 第 1 条：

1. 本仓库内**没有**未被三宿主使用过的公开 instance：`.tooling/swebench-verified/` 的 10 个实例要么
   属于本宿主 v1–v12 的任务（`django-16263`、`pylint-8898`、`pytest-10356`），要么已被 OpenHands 的
   协议/校验文件引用（`django-15563/15957/16032/16100/16315/16661/17084`）。
2. 取新 instance 需要检出或取源：本轮**禁止 git**；`raw.githubusercontent.com` 在本机 DNS 解析为
   `0.0.0.0`（被阻断），`github.com/.../raw/...` 会 302 到该主机而不被跟随。
3. 退一步用 `github.com/<repo>/blob/<commit>/<path>` 网页取源也不可作为**可核对 SHA256**的基线：
   返回的是页面外壳且被截断，无法得到整份文本，因而无法登记哈希。

因此本轮结论只能是"草案 + 门控结论"，而不是"新任务的真实载荷"。一旦允许有界检出（或恢复 raw 取源），
按 §7 清单顺序执行：Stage 0 → 冻结 → Stage A 载荷获取 → replay/不变量门 → 才谈 Stage C。
