# OpenHands 修复与复跑记录

## 版本隔离

v6 的原适配器、运行器、任务集和原报告保持不变。后续修复通过新模块及独立目录保存，manifest 中记录源码哈希。每轮源码快照用于复现，已有实验开始后不要改写该版本的源码。

| 轮次 | 适配器 | 样本数 | 定位 |
|---|---|---:|---|
| v6 | openhands.py | 27 | 原始三组实验 |
| v7 | openhands_v2.py | 9 | 正文投影、任务状态、统一结束规则试运行 |
| v8 | openhands_v3.py | 27 | 压缩路径表示后的重复验证；包含 API 中断 |
| v9 | openhands_v4.py | 9 | 已有记忆保护的试运行 |
| v9 validation | openhands_v4.py | 27 | 最新版本完整三组重复验证 |

这些数据都用于开发或验证。旧任务已参与调试，后续独立验证需使用新任务，不能把重跑旧任务当成新的泛化证据。

## 修复内容

1. 从 SDK TextContent 提取正文；源事件 ID 留在持久化日志与映射中，不重复嵌套整个消息 JSON。
2. 文件工具正文分成较小的源码片段，使用内核识别的 `文件=` 标记；保留实际源码换行。
3. 将初始任务及后续用户要求传给 middleware 的 task_state。
4. 已有 CondensationSummaryEvent 直接读取 summary，避免 JSON 逐层转义。
5. 派生记忆中工作区路径变成相对路径；原始 SDK 事件保持绝对路径。
6. 只剩旧记忆可处理、没有新历史时直接返回原视图；参与下一轮的已有记忆作为受保护状态保留，避免再次单独删减。
7. 三组统一：宿主测试通过后直接 Finish，失败后才继续修正。工作区采用同长度、不含组名的 ID。
8. 保留安全工具批次检查及不减少 token 时的回退，拒绝把膨胀候选发送给模型。

## 离线与回放门控

- 主环境 unittest：256 项，16 项跳过，结果通过。
- OpenHands 专项：8 项通过；包括正文/旧记忆投影、任务状态、批次完整性、只压缩旧记忆的负对照。
- 固定 v6 反斜杠 r3 历史的 19 个来源事件，无模型请求回放。
- v4 投影 6573、派生记忆 5667 token，采用本地 GPT-4o tokenizer，仅用于机制核对。
- decode_escapes、_single_quote_escapes、parse_value 均保留；decode_escapes 和 parse_value 的完整函数体逐行检查通过。
- 本地计数不是提供商最终账目，也不是全任务节省比例。

## 故障与结果口径

v7 插件三项全过，但无压缩候选被接受，全配对平均输入增加 1.91%。这轮未满足节省目标，保留后继续修复路径开销。

v8 有连续 API 连接失败。基线输入为零的配对收益记为 null；不能将提前失败的低 token 用量视为裁剪收益。应同时读取 REPORT.md 与 REVISION_ANALYSIS.md。API 均正常的配对中，插件平均输入增加 6.43%；这轮也不能支持稳定收益。重压缩旧记忆造成证据风险的路径已在 v4 增加保护。

v9 有一个请求前 Windows 原子替换权限错误，零模型调用。原样归档到 pre-request-failures，重新准备该工作区后继续。run_windows_retry.py 仅给实验目录内原子文件替换增加最多四次短重试，不增加模型请求重试；补丁哈希和重试记录在 windows-compatibility.json。原始失败报告没有被覆盖。

v9 试运行插件 3/3 正常完成，基线和原生摘要各 2/3。插件总输入加总虽少于基线，三项逐对平均输入却增加 5.53%；不能以加总指标替代配对指标。最新完整验证的结果以 REPAIR_REVIEW.md 为准。

## 仍有的限制

当前只接入 SDK 的模型视图压缩，不是完整自动恢复闭环。task_state 传入了任务与宿主反馈，但没有完整映射所有生命周期钩子。文件证据仍来自不同时间点，后续应完善文件版本与成功编辑后证据更新。已有记忆的保守保护可能限制压缩空间。

三项缺陷均来自同一个库，两个短任务可能完全不触发压缩。模型独立轨迹产生的调用数波动不能全部归因于裁剪。选取的上游回归通过不代表整个上游测试集通过。SDK 金额字段缺少价格映射，不能把零金额当作免费。

下一阶段应冻结不同项目的长任务、质量与输入预算判据，再独立验证。30% 是待验证目标，不能作为已有结论写入结项材料。
