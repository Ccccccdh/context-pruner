# 真实载荷适用性预筛：回溯分析（2026-10-05，零 API）

运行 `python -m experiments.commands.prescreen_real_payloads_20261005`，只读取已有批次 `samples.jsonl` / `results.jsonl`、真实模型输入证据、OpenHands 前缀 `comparison.json` / `select.json` 和审计；新输出为 `integrations/REAL_PAYLOAD_PRESCREEN_20261005.json`。脚本不调用模型、不重跑宿主测试、不改旧批质量与冻结。源批次分别有自己的任务、机制和预算，以下只检验**必要条件与可排除情形**，不合并跨宿主收益率。

## 1. 观察结果

### OpenAI Agents：可省略单位是成本收益的必要条件，不是质量保证

均为同一个 Django 公开源码诊断任务的 3 次重复。特征来自每个无压缩臂**真实最终模型输入**，不是虚构桩。`potential_old_units_upper_bound` 为冻结机制按近度可能碰到的更早单位数量；它未扣除所有事实守卫，不能叫“安全可删数量”。

| 版本 | 单位 / 保留最近数 | 各重复候选旧单位上界 | 插件 / 基线严格成功 | 插件完整总 token 配对均值 |
|---|---|---|---|---:|
| v9 | 连续工具轮 / N=1 | 0、0、0 | 3/3 / 3/3 | 约 **0%**（−0.000004%） |
| v10 | 工具调用 / M=1 | 5、5、5 | **0/3** / 3/3 | **+27.68%** |
| v11 | 工具调用 / M=4 | 2、2、2 | **2/3** / 3/3 | **+5.81%** |

三个批次的独立 `audit.json` 均 `complete: true`、`issues: []`。v9 的“候选集合为零→几乎零收益”是有用的**不值得付费筛除信号**。v10/v11 的候选集合非零→出现成本收益，但质量低于基线，说明“旧单位数量”本身无法预测可接受收益。既有 v9 假模型曾虚构 6 个工具轮并投影 +34.15%，真实载荷实际只有 1 个连续轮；今后必须用真实载荷 replay 再做新策略投影。

### CrewAI：初始历史量不能单独预言收益

特征来自各无压缩臂首个真实模型输入中的历史 assistant 文本字符数；配对结果仍从原始完整 token 行独立计算。r4 与 r9 的任务合同不同，只看**各批内部**的变化。

| 批次任务 | 初始 assistant 历史字符均值 | 插件配对节省均值 | 插件 / 基线严格成功 |
|---|---:|---:|---|
| r4 `incident_triage` | 572 | +11.85% | 3/3 / 3/3 |
| r4 `release_readiness` | 573 | +3.99% | 2/3 / 3/3 |
| r4 `customer_migration` | 573 | +0.55% | 3/3 / 3/3 |
| r9 `queue_backlog_replay` | 641 | +22.25% | 3/3 / 3/3 |
| r9 `schema_migration` | 641 | +2.04% | 3/3 / 3/3 |
| r9 `region_failover` | 646 | −0.26% | 0/3 / 0/3 |

r4、r9 的独立审计均完整无错误。历史字符数相近却有从负到 +22% 的任务差异，表明“垫料多”不能当作有效节省或质量等价的充分判据。r9 汇总质量不劣、成本 +8.01%，但收益主要来自一项任务；随后 r10 新任务未复现严格质量。因此预筛至少要区分**历史可删量、当前证据/工具轮、角色决策行为和任务间离散度**，不能只看总长度。r14 已有更直接的离线上界 +0.86%（低于预注册 3% 付费门），应继续遵守其停止结论。

### OpenHands：超过触发阈值仍不等于有效结果

| 批次 | 真实前缀视图 / 触发阈值 | 零 API 重放省略单位 | 插件分叉后成本节省 | 可用质量/审计 |
|---|---:|---:|---:|---|
| v58 | 29,490 / 28,000 | 183 | +46.29% | 独立审计完整；**无分叉后宿主判定** |
| v61-01 | 38,390 / 28,000 | 209 | +44.73% | 三臂宿主判定都取得且**都失败**；独立审计未签署（冻结后审计器漂移） |
| v61-02 | 最大 21,745 / 28,000 | 无分叉 | 无 | 未选出合格前缀；不得记为压缩试验 |

v58/v61-01 表明触发和大量候选省略单位可以带来成本侧收益，但缺乏成功质量或完整审计的同时支撑；v61-02 表明当真实视图低于阈值时，连机制曝光都没有。对真实代码任务，选定前缀还需留有足够请求预算做纠错与宿主验收；不能靠延长无效调查历史去跨阈值。

## 2. 下一轮可执行的预筛门

这是**顺序门控**，不是成功概率模型。任一项失败，就停止该候选的付费开发并记录原因；通过全部也只允许进入小试，不允许直接写结项收益。

1. **证据门**：输入来自已记录的真实模型输入或真实 OpenHands 事件前缀；已付费批必须有独立审计，若审计未签署只能用于机制诊断，不能当有效结果。假模型桩只验证接口，不提供“可省略量”估计。核对任务、模型、预算、触发器、输入结构指纹和冻结哈希。
2. **曝光门**：真实载荷达到冻结软阈值，或同前缀重放明确将触发。低于阈值则先记录“未触发”，不能用三臂微小差异证明压缩效果。OpenHands 还须同时满足“需要纠错”和前缀后留有验证请求。
3. **非零收益空间门**：按宿主实际省略单位测量候选旧轮/调用/工具输出，扣除当前任务约束、字面证据和工具调用配对。集合为空（OpenAI v9）或保住质量后的离线上界低于预注册成本门（CrewAI r14 的 0.86% < 3%）就停止付费。必须把“潜在旧单位上界”和“守卫后安全候选”分开报告。
4. **不变量门**：用真实载荷 replay 逐边界检查任务约束、当前证据、工具组哈希、恢复/整份回退和源定位。任一丢失或回退未记账即修机制；即使无丢失，模型仍可能更早停工具或答错，不能自动判定质量等价。
5. **小试与确认门**：先 1 任务×多重复×三臂，所有失败/触顶进入质量和完整成本配对；通过后再用未参与调参的多任务多重复确认。只在质量不劣、触发实际发生、完整成本多数配对为正且跨任务不过度集中时谈“适用工作点”。

## 3. 预筛本身的限制及下一决策

- 这是回溯分析：OpenAI 的最终无压缩输入和 CrewAI 的首轮输入来自已运行批次，不能声称是“运行前已经验证”的预测准确率。v9/v10/v11 仍是同一任务的机制迭代；CrewAI 仅 6 个任务层观测；OpenHands v61-01 审计未签署。无置信区间，也没有跨宿主统一分数。
- 当前数据支持**避免显然无效的付费批**（不触发、无安全可省略项、离线上界过低），尚不支持筛出“必然质量等价且省钱”的任务。OpenAI v10/v11 是明确反例。
- 下一步若要填补 L2 跨宿主迁移空白，先只做**零 API 迁移可行性卡**：选相同公开源码诊断形态，明确 A 的工作点在 B 中映射为何种省略单位和 provider token 阈值；用双方真实载荷 replay 核对触发、候选集合、保护不变量与预算。若没有同构安全候选，不开付费迁移批。CrewAI 是合成双角色任务，不能直接拿其 +8.01% 配置移到 Django 代码修复后宣称迁移。

本报告与 `REAL_PAYLOAD_PRESCREEN_20261005.json` 是**新分析**，不修订任何旧批 `RESULTS.md`、`audit.json`、冻结文件或评分。文档勘误另见 `crewai/R9_QUALITY_NON_INFERIOR_ERRATA_20261005.md` 与 `openai_agents/OPENHANDS_V58_V59_CROSS_HOST_ERRATA_20261005.md`。

## 4. 勘误：§2 第 3 条的收益上界口径**已被实测证伪**（2026-10-05，由 CrewAI r15 触发）

> **§2 第 3 条中"保住质量后的离线上界"的算术在此之前是错的；该数值不得再用于筛除或放行任何批次。**

- **证据**：CrewAI r15 载荷批按该口径给出"可实现上界 **+10.247%**"，而三臂小试的**同工作量**实测配对节省为 **+35.16%（6/6 正）**，是上界的 **3.43 倍**（见 `runs/stage5-crewai/crewai-two-role-r15-release-gate-3arm-resume-a-01/R15_TOOL_LOOP_MECHANICAL_DIAGNOSIS.json` 的 `bound_audit`、`integrations/crewai/R15_SPLIT_DIAGNOSIS_AND_BOUND_ERRATUM_20261005.md`）。
- **错因（实测分解）**：该上界只记账"首帧**一次性**文本"（约 1,267 token），而**整段首帧在之后每次调用被重复投递**——这一项约占实测节省的 **42.6% / 40.3%**（1,878 / 1,869 token 每调用），完全不在其记账范围内；其余差额来自少调工具与逐单元波动。
- **正确形式**：按**逐调用累计** `Σ_calls (无压缩每调用输入 − 压缩后每调用输入)`，再显式扣除钉住 / 受保护轮 / 整份回退 / 辅助摘要成本。"首帧一次性文本"只是其中一个分量，**不能单独当作上界**。
- **仍成立的部分**：§2 第 1、2、4、5 条不变；"潜在旧单位上界"与"守卫后安全候选"仍必须分列——但前者是**单位计数**，与 token 上界不可互相替代。
- **影响面**：`REAL_PAYLOAD_PRESCREEN_20261005.json` 是按旧口径计算的**回溯描述**，其"候选集合是否为空"的判断仍可用，**数值不得再作成本门**；三宿主后续门控一律改用上述逐调用口径。旧批结果一律不改、不重打分。
