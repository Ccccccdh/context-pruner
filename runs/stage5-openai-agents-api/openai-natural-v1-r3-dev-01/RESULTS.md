# OpenAI Agents：固定同输入三任务三重复开发批

状态：27/27 付费样本完成，独立审计 27/27 通过。三项任务是人工策划的模拟运维工具流程，不是实际仓库修复任务；每项任务的三次重复有相同历史、工具返回和验收合同，重复索引只轮换三臂顺序。冻结参数见 `integrations/openai_agents/NATURAL_V1_R3_DEV_FREEZE.json`。

| 臂 | 成功 | 平均每样本完整总 token | 辅助调用 | 相对无压缩的配对总 token 节省 |
|---|---:|---:|---:|---:|
| 无压缩 | 9/9 | 8,852.33 | 0 | — |
| 插件 | **9/9** | **2,670.11** | 0；36 次视图压缩 | **+69.84%，正 9/9** |
| 原生摘要 | 9/9 | 11,548.67 | 36 次摘要请求 | **−30.46%，正 0/9** |

插件逐任务均值：事故处置 +69.25%、账单对账 +70.38%、发布门控 +69.88%（各 3 次）。三臂均按指定顺序读取三项工具证据，结构门控和答案门控全通过。全批实际 144 次 Agent＋摘要请求，低于冻结的 300 次上限；失败和重试没有被排除。完整成本把摘要请求的输入和输出都计入本臂，金额仍以供应商账单为准。

付费后首次调用冻结审计器时，出现唯一一条 `provider budget mismatch`：该脚本误读 `budget_calibration.provider`，而运行前 manifest 实际写的是 `budget_calibration.provider_tokens`。脚本原字节保存为 `audit_pre_run_snapshot.py`，其 SHA256 与付费前冻结值一致。另建的 `experiments/audits/audit_openai_agents_natural_r3.py` **只修正这一字段读取，并从原字节快照校验冻结审计器哈希**；重审计 `audit.json` 为 `complete: true`、`issues: []`，27 样本、144 请求、三臂成功率与 9 对总 token 均逐项吻合。这个付费后审计修正没有改变 runner、任务或原始结果。

本批较旧 v2cal 的优势是重复使用同一输入；仍是单模型、三个策划模拟任务的开发验证。+69.84% 不能外推到 OpenAI Agents 的真实软件任务。下一阶段须另选未参与调参的自然长任务，预先冻结质量门控与预算，再做确认批。
