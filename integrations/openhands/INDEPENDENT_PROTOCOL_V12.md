# 独立项目验证 v12：工作流修正后重新冻结

沿用 INDEPENDENT_PROTOCOL.md 的两个公开项目、任务合同、外部测试、三组参数、轮换顺序和 18 个独立样本。ContextPruner v5 保持原样，任务和测试也未调整。

## 与 v11 的差异和依据

v11 的只读调查阶段依赖 Agent 主动结束；实际轨迹出现持续阅读，多个组在进入实现前耗尽预算。该结果原样保留。v12 将读取与实现合并为一个自然开发阶段：读取 TASK.md、调查相关代码、实现、finish；仅在外部测试失败时再提供反馈进行一次修正。通过后不增加模型请求。此轮在观察 v11 轨迹后修正工作流，属于自适应复验，不能伪称第一次未接触任务的盲测。

上限仍是 36 次 Agent 请求、8 次摘要请求，每次最多输出 2,048；单次估计输入上限提高到 80,000，总上限 2,000,000，使无压缩组可在更大的上下文预算下正常实现。各组一致；这改变了预算条件，不直接混合两轮统计。

## 冻结和判定

首次 v12 模型请求前冻结本文件、运行器、工具兼容层、任务代码、参考检查代码和全部 context_pruner Python 源码。所有 API 失败和任务失败保留，不自动重试或替换失败样本；全部 18 个样本完成后停止请求并审计。

质量依照最终验收和选定回归，输入使用供应商计数并包含摘要开销。展示全部配对、API 正常配对和双方通过且 API 正常配对；未知失败请求消耗不当作零。没有压缩的样本不得宣称由压缩带来收益。30% 是待验证目标。两个自编任务和三次重复仍不足以证明普遍有效或统计质量等价。

允许自选必要读取，禁止强制重复读或填充日志。参考实现只在主机隔离目录，可解性检查保留；不向 Agent 提供。凭据不传给测试进程。金额未知。
