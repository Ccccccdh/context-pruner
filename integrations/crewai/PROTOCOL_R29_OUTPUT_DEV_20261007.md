# CrewAI r29 全臂输出合同开发小试

r28 的 18 个付费轨迹已暴露 `HANDOFF:` 标记变体和 `ttl=60s` 缩写；本批使用同两任务验证一个**预先固定的宿主输出层**，故明确是开发小试，不能作为独立确认或追溯改判 r28。

三臂都安装同一输出层。第一角色只把最终交接开头的 `HANDOFF:` 转为 `HANDOFF `。第二角色仅在必需事实为 `*_seconds N`、模型原文写出对应的 `*=Ns`、且本次已执行工具确实返回相同字段和值时，扩展该单位缩写。任何没有唯一可靠对应关系的缩写均不自动补值。若最终 RESULT 仍缺必需字段名，宿主最多重新请求一次，只提示**缺失字段名**并让模型查已观察证据；不在提示中给出期望值。错误决定、错误数值和缺失工具均不得被规范化为成功。所有额外请求计入成本与硬预算，逐次保留原文、服务文本、变更及重试记录。

设计：r28 的 3/5 来源两任务 × 3 重复 × 3 臂，共 18 样本；模型 `deepseek-v4-flash`、thinking disabled、单次输出上限 512、每样本摘要最多 4 次、全批供应商请求硬上限 300，发送前持久化请求槽，不续跑中断批。覆盖守卫与任务尺度 K 均保持 r28 冻结行为。

零 API 门：旧轨迹离线正反控制通过；18 格 mock 网格严格/语义通过；独立审计核变更记录可从原文复算、重试上限、逐调用捕获及来源覆盖，再写一次最终冻结。质量门：三臂各任务来源覆盖 3/3、守卫和工具组恢复零失败；每任务基线严格至少 2/3、Pruner 严格与语义均不低于基线。成本门：每任务至少 2/3 配对完整供应商 token 为正且差额总和为正，全批至少 5/6 为正且总差为正。即使双门通过，仍仅为已知任务上的开发证据，`can_be_quoted_as_saving=false`。
