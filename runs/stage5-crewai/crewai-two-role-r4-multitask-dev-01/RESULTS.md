- 插件 `release_readiness` repeat 0 输出了 `NO-GO`、Atlas-2.4、184、0 与 migration lock 等事实，但把冻结答案词组 `0 failed` 改写为 `fail 0`，故冻结严格门控失败。调查角色的交接事实齐全，单行格式由零 API 规范化；未触发缺事实补救。
- 原生摘要 `customer_migration` repeat 1 输出正确目标、时间、方案及 `PROCEED`，却把冻结词组 `28%` 写作 `28 percent`，同样严格失败。

- 任务是同一套策划的模拟运维双角色流程。单任务 r4 pilot 插件 +10.45% 且 3/3；本批多任务成本收益降至 +5.46%，其中迁移任务近零，说明单任务结果不能代表跨任务稳定收益。没有真实代码修复、生产 CrewAI 工作流或跨 Agent 的质量结论。
