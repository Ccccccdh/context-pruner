## 实验范围与结果

从原记录顺序中选择每任务最早两个满足干预条件的不同 H，最终只有 django-15569、django-15572 两任务、4 个 H 符合条件；第三任务没有替换补选。每 H 比较 `none`、`k1_guarded`、`k0_guarded`，各重复 3 次，每组 12 个样本。模型为 `deepseek-flash`，thinking disabled，temperature 0，最多输出 2048 token。

这是**局部下一动作**实验：模型提出 `read` 时只记录，不执行后续读取；模型提出补丁时在独立工作副本运行目标测试和既定回归模块。没有运行完整任务，也没有测自然生命周期 A0/A1/A2。

| 指标 | none | k1_guarded | k0_guarded |
|---|---:|---:|---:|
| 样本 | 12 | 12 | 12 |
| 首次动作：patch / read / invalid | 6 / 5 / 1 | 4 / 6 / 2 | 2 / 5 / 5 |
| 格式修复次数 | 1 | 2 | 5 |
| 最终动作：patch / read | 7 / 5 | 5 / 7 | 6 / 6 |
| 验收通过补丁 | 4 | 2 | 5 |
| 其中首次输出直接通过 | 3 | 1 | 2 |
| 其中格式修复后通过 | 1 | 1 | 3 |
| 补丁不能应用 | 3 | 3 | 1 |
| 返回的 provider 请求 | 13 | 14 | 17 |
| 首次请求输入 token（不含修复） | 19,449 | 19,407 | 19,899 |
| 全部请求输入 token | 20,561 | 21,548 | 25,353 |
| 全部请求输出 token | 1,521 | 1,360 | 1,564 |

11 个通过补丁均通过指定目标测试和回归模块；7 个未通过补丁均因不能应用。`read` 是继续探索的建议，不能计为完整任务失败或成功。首次动作和修复后动作分开报告，避免把额外格式提示的效果计为压缩效果。

两组 django-15572 H 上 `k1_guarded` 与 `none` 实际请求体完全相同，不能视为压缩干预；这两组均观察到相同动作类型及验收结果。其余相同输入的重复试验仍存在输出差异，temperature 0 不足以保证逐字确定性。每 H 的重复和初次/最终动作见 `analysis.json`。

**当前不能证明压缩改善修复质量或节省成本。** `k0_guarded` 的最终通过数较高，但 3 个来自格式修复后输出，且格式修复和累计输入成本增加；首次输入 token 总量也高于 none。`k1_guarded` 首次输入只减少 42 token，累计输入反而增加。4 个 H 来自两个历史开发任务，相关性较强，不能当作独立任务样本推断泛化。缓存命中、顺序和模型波动也限制账单差异的因果解释。

## 请求、费用与失败记录

有效批次返回 44 个 HTTP 200 响应，其中 36 次初始请求、8 次显式格式修复。原始 usage 全部通过一致性和预留上限检查：输入 67,462、输出 4,445、合计 71,907 token；输入缓存命中 50,432，未命中 17,030。

按本轮核查的 [DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing/) 和返回缓存字段，44 个返回请求的用量估价为 **0.005373–0.010746 美元**（低峰至高峰范围），不是已核对的最终账单。

首次受限网络批次在第一个请求发生 APIConnectionError，诊断为 Windows 网络访问限制，没有 provider 响应、没有完成样本。该批次原样保留，费用未知，不能算作零费用。确认网络限制后经自动审批执行剩余预算批次，未重置总额度：累计 **45 次 HTTP 尝试、0.2422764 美元保守预算预留**，均低于原 72 次 / 1 美元上限。预留额是安全上限，不是实际消耗。

另有一次 successor 准备目录不完整及一次缺少冻结文件的启动失败，均未发送 HTTP 请求；保留证据。有效 successor 存放于 `frozen-network03/`、`paid-network03/`，逻辑实验编号为原实验编号加 `-network02`。
