# OpenAI Agents v4 选择性保留机制小试

2026-10-04 完成。冻结审计 `audit.json`：`complete: true`、`issues: []`、`evidence_checked: 9`、9/9 样本、**23 次 API 请求尝试**（全局上限 100）。协议 `integrations/openai_agents/REPO_DIAGNOSTIC_V4_SELECTIVE_RETENTION_PROTOCOL.md`（SHA256 `0ab31f3132faa908cb9d9c63a7b09c4079798175986e160c9ac99354e608c64f`）；冻结 `integrations/openai_agents/REPO_DIAGNOSTIC_V4_SELECTIVE_RETENTION_FREEZE.json`（SHA256 `6e344f238c2a40dd5d474d38ba942267c36af4b0b3e6c53ecc899c7f0933d53e`），含 17 份源码/测试/协议脚本与 3 份公开输入哈希。

## 1. 这批做了什么

v2 证明插件臂在模型边界丢掉了公开问题陈述里的字面约束；v3 用「逐字保留最初两条 user 消息」修好了字面丢失，却因此完全没有压缩空间（完整总 token −33.79%）。v4 换成**只压缩可证冗余文本**的确定性机制（`experiments/runners/openai_agents_selective_retention_v4.py`）：注册任务陈述被切成单元并逐个保护；完全重复行只留第一个副本；**已在本次运行更早的模型调用中逐字发送过的工具输出文本**被替换为确定性短注释（保留 item、`call_id` 与 call/output 配对）。任何受保护单元缺失、工具组变化或「过滤后没有严格变小」都触发**该次模型调用整份回退**并计数。v4 同时补上 v3 的缺口：`task_anchor_restore_failures` 逐样本、逐模型调用持久化并被独立审计核对。

矩阵与 v1/v2/v3 相同：`django_count_annotations` 1 任务 × 3 重复 × `none`/`pruner_v1`/`native_summary` 3 臂 = 9 样本；`deepseek-v4-flash`、禁隐藏 thinking、provider soft/target/hard 2000/1500/6000、输出上限 1024、全局请求上限 100、三臂轮换、逐样本落盘。仅发送公开问题陈述、固定公开基线源码范围与工具结果；`manifest.json` 的 `data_class` 已改为诚实的 `public_source_diagnostic`（v2 误标为 `synthetic_only`）。

## 2. 主结果

| 臂 | 冻结严格成功 | 实际输入 token 均值 | 完整总 token 均值 | 配对完整总 token 节省 | 正收益对数 |
|---|---:|---:|---:|---:|---:|
| 无压缩 | **3/3** | 2,874 | 2,961.3 | 基线 | — |
| pruner_v1（选择性保留） | **0/3** | 2,643.7 | 2,748.0 | **+7.21%**（95% CI −64.08%…+42.87%） | **2/3** |
| 原生摘要 | **3/3** | 2,874 | 3,372.3 | **−13.88%** | 0/3 |

逐对（重复 0/1/2）插件完整总 token 变化：**+42.88%、+42.85%、−64.08%**；无压缩臂三次各 2 次模型调用、2,874/2,874/2,874 输入 token。原生摘要三次各 1 次摘要调用（960 输入 + 271 输出 token），其辅助开销单列并计入本臂。

**插件质量 0/3，基线 3/3，因此 +7.21% 只是描述性成本差异，不是有效节省。**本批结论为**机制仍未通过质量门槛**。

## 3. 约束保留与恢复失败证据

九个样本的每次模型边界都有证据文件（`input-evidence/*.jsonl`），只含哈希、长度、布尔与计数。

| 重复 | 插件最终 `model_input` 字面命中 `filter` / `other annotations` / `ordering` | `existing_annotations` | 压缩注释数 | `task_anchor_restore_failures` |
|---|---|---:|---:|---:|
| 0 | 全 True | **False** | 3 | 0 |
| 1 | 全 True | **False** | 3 | 0 |
| 2 | 全 True | **False** | 2（第 3 次调用） | **1** |

- 三条被点名的约束（`filter`、`other annotations`、`ordering`）**三次都保留在最终模型输入中**，并且同时出现在「非受保护普通消息」集合里 —— 这正是 v2 丢失、v3 修复的那一条，v4 没有回退。
- 受保护的 Responses 工具组在每次过滤前后组 id 与 call/output 配对数一致；工具输出文本的每一次变化都伴随一条本模块的压缩注释，没有出现「无注释的输出改写」。
- **`task_anchor_restore_failures` 已逐样本持久化**：总数为 1（仅在重复 2 的第三次调用），并写入 `restore_failures_by_model_call` 逐次序列、证据文件每次 `model_input` 记录与审计核对。**该次失败触发整份回退**（`restore_failure_is_whole_prefix_fallback: true`，`task_restore_fallbacks` +1，`fallback_reason = protected_tool_group_changed:baseline:...`），该次调用字节数与过滤前完全相同（9,428 → 9,428），没有发生部分恢复，也没有声称压缩成功。这就是 v3 无法排除的情形，v4 把它变成了可核对的账目。
- 三个插件样本的**实际输入确实下降**（重复 0/1 峰值输入 2,212 → 约 1,376 token；重复 2 最后一次调用回退因此总量上升）。压缩不是「原封不动保留全部任务文本」：重复 0/1 的插件总输入 1,603/1,601 token，低于基线 2,874，压缩在模型边界真实发生。

## 4. 机制诊断：真实缩减同时发生了证据丢失

质量退化不是格式巧合，证据指向一个具体缺陷：

1. v4 的「可删」判定基于**该文本是否已在本运行中逐字发送过**，而**没有**检查这段工具输出本身是否承载已注册的字面约束。
2. 本任务的工具输出中，`existing_annotations` 只出现在 `read_django_aggregation` 的源码视图里（任务陈述里没有这个词）。三次插件样本在第 1 或第 2 次调用把它替换成注释后，**最终模型输入的 `existing_annotations` 命中由 True 变为 False**（基线 3/3 始终为 True）。
3. 三次插件最终答案都变长（均值 189.3 字符 vs 基线 145.3，冻结上限 160）：重复 0/1 改说「count() reuses annotations without pruning」（缺 `existing_annotations force subquery` 这条冻结因果），重复 2 给出机制的详细描述 —— 内容方向正确，但**超出 160 字符单行合同**，与 v3 重复 2 的失败形态相同。冻结评分 0/3，不回写、不重判。
4. 该任务形状是「一批工具调用 → 立刻给结论」，因此被压缩掉的正是**结论所依据的证据**；这不是「节省换质量」的等价交换，而是把信息搬出了模型可见范围。**机制必须改成「只压缩可证无关的证据」，而不是「压缩一切已经送达过的证据」；否则不能称为仅压缩冗余。**

## 5. 与既有批次的关系与边界

- 与 v2 相比：v2 丢的是**问题陈述**中的字面条件（`other annotations`），v4 保住了；v4 新丢的是**工具输出**中的字面条件（`existing_annotations`）。两者都是「模型边界上的字面丢失」证据，不能互相替代。
- 与 v3 相比：v3 全量锚定 → 零节省、−33.79%；v4 选择性保留 → 真实输入缩减、配对 +7.21% 但质量 0/3。**两版都不能称为有效节省**，方向相反的两类失败。
- 质量口径：主质量仍是冻结严格答案合同；本批 9/9 样本全部报告（无失败尝试、无触顶），未做任何事后改判或样本筛选。
- 本批只有 **1 个任务、3 个重复**，且 Django 任务在 v1–v3 已参与调参，**不是**未参与调参的盲测确认批；禁止把 +7.21% 外推到多任务、其他宿主或真实软件修复，也禁止与 CrewAI / OpenHands 的百分比合并。
- 证据只有哈希、长度、布尔与计数，不保存原文；独立审计通过只说明冻结哈希、账本、质量口径与恢复失败计数一致，**不证明语义等价，也不构成质量或成本有效的结论**。

## 6. 下一步（明确不扩大样本）

按交接约定，本批出现质量下降，**不扩样**，先改机制。最小、可零 API 复验的改进方向：

1. 压缩资格必须包含「该工具输出文本中没有承载任何已注册字面约束」；承载约束的输出必须整体保留，若预算不允许则整份回退并计数（v4 的回退路径已就绪）。
2. 压缩注释必须携带**结构性指针**（文件路径与行范围、行数），使模型不必重新调用工具；本轮注释只给字符数与行数，不足以支撑引用判定。
3. 至少保留**最近一次工具组**的全文：本任务形状下「刚读到的证据」正是结论依据。
4. 新机制必须用 v4 的门控（真实 SDK + 假模型的 9 样本栅格、字面约束断言、工具组哈希断言、注入缺失的计数与整份回退断言）先行验证，并以**新版本号、新协议、新冻结、新批次 ID** 运行；v4 源码、协议、冻结与本批次结果保持不动。
