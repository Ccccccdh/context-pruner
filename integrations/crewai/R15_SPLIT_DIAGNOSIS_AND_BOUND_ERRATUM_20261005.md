### 2.3 机械判定

```
mechanism_withheld_required_content = false   （6/6 单元）
```

**判定：机制侧无缺陷，属模型行为。** 六个失败单元在决定性调用上同时具备：完整工具清单与 schema 块、工具选择行、已执行工具的证据字节、输出合同，且没有任何钉住/保护/回退把内容拿走——**角色是在内容齐备的前提下提前结束了工具循环**。另外两点佐证：① 6/6 单元首轮事实齐全（交接事实不缺，缺的是那一次工具调用）；② `contract_placeholder_echo` 全程为 0（r13 的合同措辞修正继续有效）。

**机制侧仍有一条"记账口径"问题（不是缺陷，但需修）**：`tool_sequence_consistent` 与 `strict_success` 都要求"4 个工具各调用一次"，因此"少调一个工具"会同时打掉两个门；诊断显示这不是视图缺内容，而是**运行期行为**。若后续仍要在该形状上试，唯一未被证伪的方向是**不改视图内容、只改运行控制器**（例如把"必须调用全部证据源"从提示词层提升为宿主层的工具轮计数守卫，达到上限才允许输出 HANDOFF）。**本文件只提议，不在任何留出任务上直接调参、不发付费请求。**

## 3. 上界方法作废（实测验证）

| 量 | 数值 |
|---|---:|
| 载荷批"可实现上界"（预筛第 3 门口径） | **+10.247%** |
| 本批同工作量子集实测配对均值 | **+35.16%** |
| 比值 | **3.43×** |

**用实测数字验证错在哪**（逐任务，service_release_gate 为例子）：

| 量 | service_release_gate | schema_migration_gate |
|---|---:|---:|
| 首帧 provider 输入 token | 1,878 | 1,869 |
| 首帧字符数 | 4,535 | 4,574 |
| 后续调用的**新增**字符数（该上界只扣这个） | 1,475 | 1,466 |
| 上界记账的"一次性文本"token | **1,267** | 1,270 |
| 每次调用实际被**重复投递**的整帧 token | **1,878** | 1,869 |
| 实测基线均值 token | 12,815.3 | 12,921.0 |
| 实测插件均值 token | 8,402.7 | 8,280.0 |
| 实测节省 token | **4,412.7** | **4,641.0** |
| 实测节省 % | +34.43% | +35.92% |
| 「整帧重投」占实测节省的比例 | 42.6% | 40.3% |

**结论（用户初判成立且被实测确认）**：该上界只记账了"首帧里**只出现一次**的文本"（1,267 token），却忽略了**整段首帧（或压缩后的替代视图）在之后每一次模型调用中都被重复投递**：插件把 4,535 字符的视图换成约 1,500 字符的固定视图并在后续 3 次第一角色调用与 2 次决策者调用中反复受益，因此"整帧重投"一项就占实测节省的 **约 40–43%**，而这一项**完全不在旧上界的记账范围内**；其余差额来自少调工具（本批不可计）与逐单元波动。

**因此：`REAL_PAYLOAD_PRESCREEN_20261005.md` §2 第 3 条的"收益上界"口径在此之前是错的，不得再用它筛除或放行任何批次。** 正确的成本门必须**至少**按 `(无压缩每调用输入 − 压缩后每调用输入) × 调用数` 逐调用累计，并显式扣除钉住/受保护轮/回退/摘要成本；本文件给出上述实测分解作为重写口径的起点，**本轮不重写门控代码**（避免影响其他宿主正在使用的预筛件），仅在本文件与 RESULTS 中作废旧口径并记录正确形式。
