# OpenAI Agents v3 任务锚点机制小试

2026-10-04 完成。冻结审计 `audit.json`：`complete: true`、`evidence_checked: true`、`issues: []`，Django 1 任务×3 重复×3 臂共 9/9 样本、23 次 API 请求。

| 臂 | 冻结严格成功 | 配对完整总 token 节省 |
|---|---:|---:|
| 无压缩 | 3/3 | 基线 |
| 原生摘要 | 3/3 | −14.02% |
| pruner_v1 + 两条初始用户消息锚点 | 2/3 | **−33.79%**，正 0/3 |

插件 repeat 0、1 与基线同为 2 次模型调用、2,962 总 token，严格成功；repeat 2 使用 4 次模型调用、5,965 总 token，最终答案语义包含过滤、其它注解、排序的引用判定，但超出冻结 160 字符单行合同，故严格失败。不得事后改判。三次插件最后模型输入均保留 `other annotations`、`filter`、`ordering` 的字面条件，受保护的 Responses 组哈希与过滤前一致。**本批结果行没有单列任务锚点的恢复失败计数**，不能排除某次触发了安全回退；后续版本必须把该计数写入样本账本。v2 的明确输入丢失在模型边界得到修复，但**没有压缩节省**：前两对输入和总量与基线完全相同，第三对轨迹变长。不能据此称插件有效。

本轮说明“逐字保留两条初始用户消息”过于保守，原先 135 token 的 Django 输入缩减几乎完全来自对任务文本的删减。继续优化应只针对可证冗余的文本做选择性保留，同时维持真实模型输入中的全部引用条件；新的版本须先零 API 验证，再前瞻性冻结和付费小试。此批仅 1 任务、3 重复，不能推断多任务或其他 Agent 的效果。
