## 4. 本轮回答了什么

1. **v47 的单点 +41.03% 方向正确但不稳定**：v48 三次重复为 +63.16% / +48.32% / +59.43%，
   均值 **+56.97%**，**样本标准差 7.72%**，三次**全部为正**，区间 [48.32%, 63.16%]。
2. **原生摘要极不稳定**：一次为正 31.46%、一次**为负 −22.49%**，标准差 26.99%。
   与 Pruner 的 7.72% 相比，**离散度相差约 3.5 倍**。
3. **峰值上下文首次达标**：Pruner 峰值降至基线的 **−52.94%**，**超过 README 的 ≥30% 目标**
   （v47 仅为 −17.7%，未达标）。原生摘要 −35.30%，也达标。
4. **成功率无下降**：Pruner 3/3 对无压缩 2/3，即插件臂成功率**不低于**基线。

## 5. 必须同时报告的保留意见

1. **双方成功配对只有 2/3**：r1 的无压缩臂失败。按协议**失败样本必须计入主统计**
   （上表已计入），但"双方成功且 API 正常"子集只有 2 对，不得用来替换主指标。
2. **仍限于单任务**：结论只覆盖 `django__django-17084` 这一个实例，不得外推为跨任务普遍有效。
   多任务（≥3 实例）是下一步。
3. **沙箱 ACL 干扰仍在**：本批 `AgentErrorEvent` 分布为无压缩 2、原生摘要 0、Pruner 2
   （合计 4 次，比 v47 的 5 次略少），**仍不对称**。本批仍在 DSH 沙箱内运行，
   结果与 v26–v43 普通终端批次不可直接混算。
4. **不得与其它实例合并**：v45（−255.09%，基线早停伪影）、v46（+12.98%）、v43（+10.22%）
   使用的实例与协议不同，禁止合并成一个总节省率。
5. **已知统计口径缺陷（本次发现）**：`summary.json` 的 `condensation_events` 恒为 0，
   是计统代码的 bug——回调把事件类名写在 `type` 字段，汇总却在找 `Condensation` 类对象上的
   `type` 属性。**正确口径应读 `report.json` 的 `condensations` 或 `events` 中的 `Condensation` 类名**。
   v45–v47 同源，其 summary 里该字段同样不可用（v47 的 report 显示实际有 1 次压缩）。
   本报告的压缩事件数取自 `report.json`。
