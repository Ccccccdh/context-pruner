对象批次：`runs/stage5-crewai/crewai-two-role-r10-fresh-multitask-01`（48 样本、319 次 API 请求、独立审计 `complete: true`、`rows: 48/48`，但 `errors` 非空，见 §4）。本文件**只读**该批次的 `results.jsonl` / `manifest.json` / `audit.json` 与冻结任务文件、冻结判据，**不重跑、不重打分、不覆盖任何结果、不发任何 API 请求**。复算入口：

## 1. 结论：质量下降不是"事实被压掉"，而是"决策合同被压掉"和"工具序列被压断"

| 判定项 | 无压缩 `none` | 插件 `pruner_v1` | 原生摘要 `native_summary` |
|---|---:|---:|---:|
| 严格质量 | **16/16** | **6/16** | 13/16 |
| 语义质量 | **16/16** | **6/16** | 13/16 |
| 首轮事实齐全（补救前） | 16/16 | **16/16** | 16/16 |
| 补救调用 | 0 | **0** | 0 |
| 工具序列与冻结任务一致 | 16/16 | **10/16** | 16/16 |
| 全前缀回退 | 0 | 0 | 0 |
| 完整总 token | 135,487 | 119,667 | 169,777 |
| 配对均值 | — | **+11.81%** | **−25.45%**（0/16 正） |

**插件臂的 10 个失败样本全部通过首轮事实齐全门、且补救调用为 0**：必需字面量一条不缺地交给了决策者，失败发生在**决策者那一次调用**。因此这不是 r8 型"事实丢失"，而是 r9 机制修好事实呈现之后**暴露出来的下一层问题**。

失败可分成两类，互不重叠（合计 4 + 6 = 10；插件 10 个，原生摘要 3 个）：

| 类别 | 插件样本 | 原生摘要样本 | 记录中的直接证据 |
|---|---:|---:|---|
| A. 决策者答案错误，工具序列正常 | **4** | 3 | `answer_wrong_decision` |
| B. 第一角色工具序列被压断（少调工具或顺序不符） | **6** | 0 | `tool_evidence_consistent: false` |

判定顺序为**先工具边界、后答案**：`window_gate` 的四个插件样本答案本身正确（`decision_seen='clear'`），它们失败只因为工具序列被压断，因此只计入 B 类。工具序列被压断是**插件臂独有**现象（`none` 与 `native_summary` 均 16/16 一致）。

### A 类：答案里出现合同的字面占位符或错误决策（4 个插件样本 + 3 个原生摘要样本）

| 臂 | 任务 | 重复 | 决策者答案中的 `decision=` 字段 | 冻结期望 |
|---|---|---|---|---|
| 插件 | `batch_replay` | 1、2、3 | `decision=<RETRY>`（`decision_seen` 为空） | `RETRY` |
| 插件 | `shard_split` | 3 | `decision=PROCEED` | `FORK` |
| 原生摘要 | `window_gate` | 0、2、3 | `decision=<CLEAR>`（`decision_seen` 为空） | `CLEAR` |
| 无压缩 | — | — | 无 | — |

`<RETRY>`/`<CLEAR>` 正是**冻结决策合同句里的占位符写法**（`run_crewai_handoff_v8.latest_task_prompt`：`decision=<{decision}>`，并附带 "Do not output angle brackets"）。即：当模型没有真正完成决策时，它会回抄合同模板本身。这是**模型行为**，不是判据误判——判据只把 `decision` 标签后的值当作决策，`<RETRY>` 折叠后不是 `retry`，因此 `decision_seen` 记录为空串。原生摘要臂在同一任务上也出现 3 次 `<CLEAR>`（严格质量 13/16，三个失败全部是它），说明该失败模式与插件无关，属于**该模型在新任务合同上的不稳定**。

### B 类：第一角色工具序列被压断（这一条直接决定 r10 的显性收益是假的）

| 任务 | 重复 | 第一角色实际工具序列 | 冻结要求 |
|---|---|---|---|
| `credential_rotation` | 2、3 | `get_credential_status` → `verify_failover_region` → `check_trust_chain` | 三个工具按冻结顺序各一次 |
| `window_gate` | 0、1、2、3 | 只有 `check_window_lock` | 三个工具按冻结顺序各一次 |

`window_gate` 的四个插件样本**整个第一角色只调用了一次工具**，因此每次会话只有 4 次模型调用（无压缩臂 6 次）：agent 输入合计从 31,973 降到 18,127 token（−43%），agent 输出甚至略升（1,393 → 1,459）；这四个样本的**答案本身是正确的 `decision=CLEAR`**，失败完全来自工具边界。**`window_gate` 的 +41.34% 配对均值来自"少做了一次工具调用 + 少了两轮会话"，不是压缩收益**。这是本批最重要的方法学发现：只报成本不报工具边界，会把"没干活"记成"省了钱"。

## 3. 与 r9 的直接比较：+22% 没有在新任务上复现

| 指标 | r9（r8 任务集，v9 机制） | r10（新任务集，同一 v9 机制） |
|---|---:|---:|
| 任务 / 重复 / 样本 | 3 / 3 / 27 | 4 / 4 / 48 |
| 插件配对均值 | +8.01% | +11.81%（**不有效**，见 §4） |
| 最大任务配对均值 | +22.25%（`queue_backlog_replay`） | +41.34%（`window_gate`，**由少调工具制造，无效**） |
| 除最大任务外的次高配对均值 | +2.04% | +3.11% |
| 任务间离散度 | 22.50 pp | **40.37 pp** |
| 插件严格 / 语义 / 首轮齐全 | 6/9 / 9/9 / 9/9 | **6/16 / 6/16 / 16/16** |
| 基线严格 / 语义 / 首轮齐全 | 6/9 / 9/9 / 9/9 | 16/16 / 16/16 / 16/16 |
| 插件工具序列与冻结任务一致 | 9/9 | **10/16** |
| 补救调用 | 0 | 0 |

r9 的 27 个样本工具序列全部一致（`tool_evidence_consistent` 27/27），r10 插件臂只有 10/16，基线仍是 16/16：**"工具序列被压断"是 r10 才出现的失败模式**，它与任务集合有关，而不是与机制版本有关（机制哈希在 r9 与 r10 完全相同）。

**读法**：r9 的 +22.25% 级配对值在 r10 的**有效**收益里不存在。r10 里唯一量级接近的 `window_gate` 是**质量违规造成的假收益**；三条工具序列合规的任务只有 +0.98% / +1.83% / +3.11%。同时 r9 的"三臂质量齐平"在 r10 破裂（基线 16/16，插件 6/16），**所以 r10 不构成"质量等价节省"**。

## 4. 独立审计状态（不得含糊）

`experiments/audits/audit_crewai_handoff_v10.py` 对**付费批**的判定是 `complete: true`、`rows: 48/48`、`request_attempts: 319`（全局上限 440 未触顶）、`freeze_checked: true`，但 **`errors` 非空**，共 6 条，全部是 `tool evidence mismatch`：

```
credential_rotation/2/pruner_v1: tool evidence mismatch
credential_rotation/3/pruner_v1: tool evidence mismatch
window_gate/0/pruner_v1: tool evidence mismatch
window_gate/1/pruner_v1: tool evidence mismatch
window_gate/2/pruner_v1: tool evidence mismatch
window_gate/3/pruner_v1: tool evidence mismatch
```

含义：审计**独立复算**出的工具序列与冻结任务不一致，而它正是 §1 B 类失败的机器判定。也就是说，"插件臂少调工具"不是本文件的人工解读，而是冻结审计列出的错误项；`window_gate/0` 同时被计入 `semantic_success: false`（`answer_wrong_decision`）。**审计未通过（exit 1），本批不得被引用为有效结果。**

## 5. 边界

- 全部为**合成运维任务**（固定工具返回、模拟双角色流程）；不含真实代码修复或生产工作流。
- 4 任务 × 4 重复仍然只有 4 个任务层观测点，不能给出置信区间；本文件的结论只在"这 4 条新任务上是否复现方向与量级"这一层级成立。
- 温度 0 仍有独立轨迹差异；r8/r9/r10 是三次独立付费运行，跨批差值不是自动因果证据。
- 本文件不改写任何 r5–r9 评分，也不把 r10 的失败回填成对 r9 结论的否定：r9 的 +8.01% 仍按其自身冻结口径成立，只是**其量级未被新任务复现**。
- `<X>` 占位符回抄在**两个臂**都出现过（插件 4 次、原生摘要 3 次，无压缩 0 次），因此不能把它归因于压缩或钉住机制本身；而"第一角色工具序列被压断"只出现在插件臂（10/16 一致），无压缩与原生摘要都是 16/16。
