## 门控为何停住

本地 Django 仓库是 **promisor 部分克隆**：四个候选的 commit 对象在位，所需的精确源码 blob 均不在本地。`git grep <base_commit> -- <path>` 触发的官方仓库懒加载因 Schannel 凭据错误失败；`curl` 到官方 raw 域名无法解析，web 官方 raw/blob 页也未取回内容。因此无法给三个源码视图计算真实 SHA256、登记可复算字面与指针，更无法进行仅供载荷获取的付费基线请求。预选脚本及结果已更正为“commit 可见，源码 blob 未验证”；早先“完整 Git 仓库”的说法不适用。

此外，当前全臂包装层虽通过离线调用和账本反例，还未接入带**新任务真实载荷**的完整 runner 与独立回放审计。旧任务上的手工截短不能证明事实与因果信息不丢失，故不得把本轮离线检查视为付费放行。

## 成本上界与下一步

若未来登记三任务 × 三重复 × 三臂，每样本七个原诊断调用、至多一次格式重试，原生摘要臂每样本至多三次摘要：逻辑请求上界 **243**；原模型和格式重试沿用至多两次传输重试时，尝试数最坏 **675**。单任务 × 单重复 × 三臂的小试对应 **27** 逻辑请求、**75** 最坏尝试。这些是冻结前预算算术，不是获准运行的批次。

恢复源码后，先把每个候选的精确基线 commit、三段只读范围、逐文件哈希、问题陈述哈希、答复正则和准入规则落盘；零 API 运行结构/事实/指针/配对回放与源漂移负控制。载荷获取批必须单列新 ID、上限、`citable_* = false` 并独立审计。三项任务各有非零安全空间且全臂重试记账在**真实载荷**上复算通过，才冻结下一次小试；未过门就继续停付费。
