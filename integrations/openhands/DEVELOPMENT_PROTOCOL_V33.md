# v33 已见任务开发复验协议

v32 的三项目任务与验收、失败轨迹和结果已经被开发者查看。本轮属于开发复验，不能称新任务、盲测或独立确认。保留 v32 的原始目录、冻结代码和负结果。

在第一次 v33 模型请求前冻结运行器、三组共用的编辑重试护栏、候选压缩阈值、任务、验收、预算和源哈希。三组沿用 v32 的 Click、packaging、python-dotenv 合同与选定公开回归。无压缩、SDK 原生摘要、v33 候选组共用 v31 导航和 36 次 Agent 请求上限、验证与 Finish 预留。新增共用编辑护栏：`old_str == new_str` 时返回简短错误；连续两次无变化编辑后，要求先查看当前函数再编辑。候选组仍采用 v11 的证据选择算法，但触发/目标/硬上限改为 16k/13k/24k token。仅候选组使用此阈值；全组共用编辑护栏和提示。两个变化一起评估，无法把结果直接归因于其中一个模块。

先运行 1 重复 × 3 任务 × 3 组 = 9 样本小试，审核原始结果和编辑错误；若没有接口/结构错误，再冻结另一个新目录运行 5 重复 × 3 任务 × 3 组 = 45 样本开发复验。两轮各自全部保留，不用小试筛除失败后宣称独立效果。每样本最多 36 次 Agent 与 16 次摘要请求；失败请求不重试，不覆盖旧结果。SDK 用户级状态重定向到实验目录，避免向工作区外写锁。第一次小试在任何模型请求前因 SDK 用户目录锁权限失败；第二次在首个请求因本机 `WinError 10013` 网络权限失败，供应商未返回结果。两个失败目录原件保留，后续使用新目录与新冻结哈希。

主要指标仍为所有任务/重复逐对 `(1 - 候选组供应商总输入 / 无压缩组供应商总输入)` 的平均，包含失败、未压缩和负收益样本；摘要输入计入总输入。并列报告正常完成、最终代码通过、编辑失败次数、触发压缩次数、估计峰值、工具结构/边界/凭据/预算审计。正常完成口径与 v32 相同。小试仅用于检查修复方向，不作为 30% 达标证据。完整开发复验也只能说明已见任务上的变化；需要另外冻结外部新任务进行结项效果判断。真实货币费用以供应商账单为准。
