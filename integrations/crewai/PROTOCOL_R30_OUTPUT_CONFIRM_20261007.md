# CrewAI r30 输出合同全新任务确认协议

r29 在已暴露的 r28 任务上通过开发小试。本批固定 r29 输出层、任务尺度 K、三臂守卫与审计规则，在全新的三来源构件签名发布和五来源副本重建审核上前瞻确认；两个任务均未用于 r29 输出层开发。仍为合成两角色任务族。

2 任务 × 3 重复 × 3 臂，共 18 样本。三臂均安装相同输出层；只规范化可验证的 `HANDOFF:` 和有实际工具证据的 `*_seconds N` 缩写，缺字段最多一次只提示字段名的已计费纠正请求。覆盖守卫要求第一角色读取所有来源，Pruner 保护最近 K=来源数个工具轮。模型 `deepseek-v4-flash`、thinking disabled、单次输出上限 512、每样本摘要最多 4 次；全批最多 300 次供应商请求，发送前持久化槽，不续跑中断批。

零 API 门：任务静态合同无冲突、旧 r27 冲突负控制仍失败；18 格 mock 严格/语义通过，独立审计无错；最终冻结与演练草稿一致。付费后审计从逐调用捕获重建来源覆盖，核 Agent/摘要及额外纠正请求总量，并由模型原文复算输出变更。质量门：每任务三臂来源覆盖 3/3、工具组恢复和守卫触顶 0；基线严格至少 2/3，Pruner 严格与语义均不低于基线。成本门：每任务至少 2/3 配对完整供应商 token 为正且总差为正，全批至少 5/6 为正且总差为正。质量与成本同时通过才算本批确认通过。

本批无论结果如何均不在相同任务调整规则重跑。即使通过，`can_be_quoted_as_saving=false`，因为自然任务和跨 Agent 外部效度仍未验证。
