# CrewAI：双角色固定同输入三任务三重复开发批

状态：27/27 付费样本完成；独立 `audit.json` 为 `complete: true`、`errors: []`，126 次 Agent＋摘要请求均在冻结的 180 次上限内，任务文件及付费前源码哈希一致。每任务三次重复的输入不变，三臂顺序轮换。两个角色分别读取一个工具，第二角色接收第一个角色实际产生的交接文本。

| 臂 | 冻结质量门控成功 | 配对完整总 token 节省 | 正收益配对 |
|---|---:|---:|---:|
| 无压缩 | 3/9 | — | — |
| 插件 | **3/9** | **+4.46%** | 8/9 |
| 原生摘要 | 5/9 | **−29.36%** | 0/9 |

**本批没有通过质量门控，不能把 +4.46% 宣称为有效节省。** 插件在事故任务的第 3 次重复把调查交接输出成单独的 `HANDOFF`，缺失实时工具事实；对应无压缩臂通过。另有一个客户迁移配对插件通过而无压缩失败，所以总成功数相同也不代表逐配对质量等价。

付费后复核该失败样本的 `model_input_traces`：调查角色调用工具后的第二次模型输入，插件臂仍含 `degraded`、`3.8` 和 `HANDOFF` 指令，原始臂也含这些内容；插件臂把该调用的消息数从 22 压到 6。可确认模型最终没有把可见事实写入交接，**不能据此断定插件删除了事实**。这是一次提示格式、压缩呈现与模型输出共同作用的失败样本；新实验须在输出前检查交接事实，并单独记录补救成本。

三臂完整总 token 合计依次为无压缩 35,831、原生摘要 46,309、插件 34,191。原生摘要实际请求 18 次，插件实际压缩 9 次；这些事件和输出都已纳入账本。表中的 +4.46% 是九个配对百分比的简单平均，不是把合计 token 相除后的值。

付费后的 `diagnostic.json` 将失败拆开：三个任务的两角色工具配对均 9/9 正确；发布与客户迁移任务的调查交接事实在三臂各 3/3 出现，但许多输出写成 `HANDOFF:`、`HANDOFF：` 或直接叙述，与冻结门控要求的字面 `HANDOFF ` 不符。此语义/格式拆分只用于定位，不修改本批原质量结果。事故任务的插件失事实样本是实质性失败，不能以放宽格式检查掩盖。

下一步先保持本批原始报告不变，明确分列“交接事实正确”和“交接格式正确”的质量维度，再在开发协议中修复格式合同，针对插件失事实样本检查压缩后模型输入与恢复路径。任何修改都要新建批次、先过零 API 门控；最后仍需未参与调整的新任务确认。三个任务目前均为策划模拟运维任务，不能外推到生产多 Agent 流程。
