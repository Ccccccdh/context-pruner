# Agents V5 零 API 诊断（2026-10-15）

## 结论

本轮没有调用模型，也没有修改 V5 候选、协议或正式数据。重新关联了 45 个样本、304 个请求的 SDK 输入边界、实际请求体、响应 usage 和工具执行序列，并与结项审计对齐。正式运行目录的 4182 个文件在分析前后哈希一致。

找到了一个确定的信息缺口：45 份模型摘要均未保存两份源文件的完整 SHA；A1/A2 各十五个样本，在首次拿到工单后的模型输入中都找不到这两个 SHA，而工单要求最终产物填写它们。A0 十五个样本都仍可从原始回执读取 SHA。因此，归档移除的不只是大段事实，也包括产物必需的来源标识。

这说明重读具有实际的信息补充价值，但不能证明来源 SHA 是模型选择重读的唯一动机，或补齐 SHA 就一定消除重读。恢复入口本可以补齐原始回执，模型没有调用它；工具选择动机仍未被实验识别。

## 成本的精确分解

下表沿用冻结实验价格，金额为 USD 低时段估价；高时段各项为两倍，非当前价格查询或账单核销。

| 计费项 | A0 | A1 | A2 | A2−A0 |
|---|---:|---:|---:|---:|
| 缓存命中输入 | 0.001180416 | 0.000794112 | 0.000774528 | -0.000405888 |
| 缓存未命中输入 | 0.010564650 | 0.012126600 | 0.013871100 | +0.003306450 |
| 输出 | 0.018507000 | 0.019618200 | 0.019951800 | +0.001444800 |
| 合计 | 0.030252066 | 0.032538912 | 0.034597428 | +0.004345362 |

A2 少了 113253 个输入 token，实际是命中输入减少 135296、未命中输入增加 22043，另增加 2408 个输出 token。按冻结单价，未命中输入每 token 是命中输入的 50 倍，输出是 200 倍。少量昂贵 token 的增加足以超过大量便宜 token 的减少。上表是核算恒等分解，不是归档导致缓存变化的随机化因果估计。

请求次数从 A0 的 90 增加至 A1 的 105、A2 的 109。请求数本身不另加固定费用；影响通过实际输入/输出 usage 计入，不能在表外再加一笔“请求费用”。A2 十五个配对样本中十个估价高于 A0；不将此探索性计数替代正式的三任务聚类统计。

## 成本发生在哪个阶段

阶段按本次请求发出前已经执行的工具划分；请求生成的工具参数和文本输出计入本次请求。

| 请求前阶段 | A0 请求/估价 | A1 请求/估价 | A2 请求/估价 |
|---|---:|---:|---:|
| 尚未关闭研究 | 30 / 0.011026128 | 30 / 0.009649728 | 30 / 0.009038328 |
| 研究关闭、工单未到 | 15 / 0.004363446 | 15 / 0.002303226 | 19 / 0.003903828 |
| 工单可见、尚未写产物 | 15 / 0.009056088 | 30 / 0.014532882 | 30 / 0.015542484 |
| 已写产物、检查及结束 | 30 / 0.005806404 | 30 / 0.006053076 | 30 / 0.006112788 |

主要增加发生在工单到达后的实现阶段：A2 比 A0 多十五次请求、估价多 0.006486396 USD；其他阶段的差值部分抵消了它。研究阶段输入及缓存计数三臂相同，输出长度已有差异，所以不能把所有组间输出差异归因于后续归档。

宿主阶段提示在各臂都随“研究关闭”和“工单到达”而改变。提示变化与可见历史裁剪都可能影响前缀复用；供应商日志只报告总命中/未命中 token，不提供具体缓存段、驱逐原因或全局状态。无法从现有数据分别确定两者的因果贡献，也不能重算“如果没有归档会命中多少”。

## 来源缺口与重读轨迹

| 观察 | A0 | A1 | A2 |
|---|---:|---:|---:|
| 摘要保留两个当前来源 SHA | 0/15 | 0/15 | 0/15 |
| 首次工单可见时仍能找到两个 SHA | 15/15 | 0/15 | 0/15 |
| 摘要包含六个所选记录的精确 label | 11/15 | 9/15 | 8/15 |
| 工单后自然重读的样本 | 0/15 | 15/15 | 15/15 |
| 自然重读次数 | 0 | 30 | 36 |
| retrieve_evidence 调用 | 0 | 0 | 0 |

“包含六个 label”只是字符串覆盖，不代表数值规则完整、正确或足以完成任务。不能据此声称 8 个 A2 样本只缺 SHA；但可确定它们即使保留了这些事实标记，仍缺少来源 SHA。

每个 A1/A2 初始证据组只活跃于一个模型边界，然后归档；重读形成的证据组同样只活跃一个边界。当前 `read_document` 无论何时读取均返回 `stage=research`；研究已经关闭后，新的读取只靠“最新工具组”暂时保留，后续非证据工具出现即可再次归档。这是代码及轨迹共同确认的生命周期行为，是否需要改变要另作独立候选。

例如 `confirm1013-A2-r1`：第 3 轮在工单到达前重读两份源文件，第 4 轮再次关闭研究，第 5 轮获取工单，第 6 轮又重读两份源文件，第 7 轮写产物。该样本共九次请求。另两个 A2 样本在工单前重读，随后再次重读；合计多出六次早期重读、四次模型请求。该现象不能证明恢复 TTL 有问题，因为自然恢复从未发生。

恢复工具描述包含“Availability varies”，普通读取描述明确允许重读；提示同时允许摘要、重读和恢复。可以提出“入口不确定性影响选择”的假设，但所有正式样本的工具描述相同，没有对应干预，不能认定它就是恢复调用为零的原因。

## 下一候选与限制

优先设计“持久保留可信来源回执元数据”，保留 entity、path、version，而非完整记录或标准答案；三臂接受同一规则。先修复已经确认的来源信息缺口，再看模型是否减少重读。暂不同时改变阶段语义、TTL、工具描述或恢复触发方式。候选设计见 `superpowers/specs/2026-10-15-agents-v6-receipt-manifest-design.md`。

本诊断不新增质量非劣、成本节省或恢复贡献证据。V5 正式结论保持不变，原数据今后只能作为已见诊断数据。任何离线改造只能证明可见性和工程约束，不能把旧轨迹接上新输入后当成真实 V6 质量/费用。
