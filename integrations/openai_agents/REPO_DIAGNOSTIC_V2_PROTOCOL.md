# OpenAI Agents v2：公开源码输入证据开发批

目的：前瞻性复验 v1 的三项公开源码诊断，保存每次过滤前、过滤后和真实模型边界的**哈希与约束命中布尔值**，判断 Django 引用条件及 pylint 正则边界是否在插件压缩后仍送到模型。v1 原始结果、质量合同和评分保留不动。v2 不修改公开源码，不读取或发送参考修复与宿主目标测试补丁。

矩阵、公开输入、固定源码范围、三臂顺序、DeepSeek `deepseek-v4-flash`、温度 0、隐藏 thinking 关闭、provider soft/target/hard 2000/1500/6000、每次输出上限 1024、全批请求尝试上限 300，均沿用 v1。3 任务×3 重复×3 臂为 27 样本。三臂每次模型调用均留证；基线不调用过滤器，插件与原生摘要记录每次过滤前后。证据文件不得写入原消息、工具输出、系统指令、请求头或密钥，只写可独立核对的哈希、长度、约束布尔值与受保护组哈希。所有失败样本计入质量和总 token。

v2 runner 使用新的入口包裹 v1 共享 SDK 运行器；v1 冻结文件不修改。独立审计先执行 v1 的源码/问题输入哈希、矩阵、用量、质量和配对核对，再验证 27 份证据的模型调用数、过滤前后成对、受保护组不变、过滤后输入哈希出现在模型边界，以及证据文件栅格。证据哈希无法证明模型理解或因果；即使某字面约束缺失，也须结合模型轨迹解释。

付费前门控：真实 SDK 假模型的 27 样本三臂零 API 测试通过；真实模型工厂路径单独用假模型通过；独立证据审计自测能检出调用数篡改；本协议、runner、审计和公开输入哈希冻结；确认 endpoint 可达、密钥环境变量存在且批次目录不存在。随后运行 `--plan`，再运行付费批次。结果只作为机制诊断开发批，不能将同任务再次观察作为未参与调参的确认实验。
