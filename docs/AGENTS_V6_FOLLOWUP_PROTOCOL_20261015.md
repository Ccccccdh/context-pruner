# V6 独立后续开发队列协议

用户在旧队列HTTP503停止后明确要求：按顺序完成新开发队列、评估V6、必要时设计统一读取入口。此协议在新队列任何真实请求前保存。

候选行为保持V6来源回执投影不变。两个新开发实例种子227/229，每任务A0/A1/A2各一次，6样本，沿用固定轮换顺序及旧模型/工具/提示/TTL/评分规则。不得只替换旧失败A0。旧队列的5个完成样本、503、未知usage和35请求单独保留，旧操作claim不复用。

本队列上限每样本16HTTP、总96HTTP、24000 wire bytes、USD1保守预留，任一限额触发即停。独立固定操作claim禁止换freeze重置额度。不重试、不替换、不按有利结果扩样；若服务再次失败，保留完整分母和未知计费，仍继续完成可做的分析与设计，不伪造完整队列。

新队列绑定旧completion_manifest、summary、freeze及已消耗的claim，运行前验证旧证据哈希。新wrapper和本协议纳入新source manifest，不改写旧冻结源码/协议/结果。SDK MockTransport6/6及实际请求审计、独立代码审查后才准入付费。

评估：首先要求6样本完整且usage有效，再逐任务比较独立评分、完整估价（命中/未命中/输出）、输入/输出、HTTP轮次、重读、来源清单与恢复。基础设施失败质量未知，不能当普通失败或删去。只有两个独立任务，每臂一次，所有成本方向和通过率均为开发描述；不据此宣称统计非劣或稳定节省，不直接与旧V5/V6不同实例作因果比较。分臂顺序及供应商缓存会影响费用。

保留V6的工程标准是来源标识正确可见、无完整性/预算退化。是否值得作为成本优化候选，须结合每任务费用而非仅总输入。重读仍发生时，第三项交付为统一读取入口的独立设计，明确宿主查档与模型自主恢复分开计数；本次不实现新读取机制、不启动正式实验。

仅向 https://api.deepseek.com/chat/completions 发送生成的registry数据和通用工具描述。沿用已核验的DeepSeek flash低/高时段单价，usage估价不等于账单。保留旧503的费用未知状态；不把新队列费用合计当作此前全操作费用。
