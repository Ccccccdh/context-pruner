## 1. 两种选择的后果：直接可用的结论措辞

### 选项 1（维持现状：严格轨不变，`≤160` 仍是验收条件）

> **结论**：在四判据下没有任何宿主结项。OpenAI Agents 宿主在 **3 个未参与 v1–v12 调参的留出任务**上，
> 插件臂相对无压缩臂的**配对完整总 token 为正且稳定**（池化 +12.65 %，9/9 配对为正，逐任务 8.09 % /
> 12.98 % / 16.87 %，任务间极差 8.77 个百分点），且**事实侧可机械核验地保全**（13/13 插件样本的答案词元在
> 压缩前后可见文本中齐备、注册字面 presence 零丢失、被替换项的指针逐字节可复算）；但**严格轨不通过**——
> 在 `xarray_copy_dtype` 上插件 1/3 对基线 3/3，失败原因为答复长度超出冻结的 **160 字符**条件（179 字符）。
> 因此该机制在留出任务上的**严格验收结论为"未确认"**：多任务确认未达成，且严格失败按原判保留、不重判。

### 选项 2（在全新实例上新预注册：事实轨为验收主轨，长度轨只报告）

> **结论**：在新实例、新 ID 与前瞻冻结下，验收主轨改为**事实轨**（必需字面齐备、`cause=`/`fix=` 结构在位、
> 禁字面未出现、单行、前缀、冻结正则整串匹配全部满足），**长度轨只报告、不参与判定**——冻结的 `≤160`
> 字符条件在该新协议下**不再是验收条件**。**该判据只适用于它自己的批次**：v12、v13、v14 一律按**当时的严格轨**
> 结论保留，**不得重判、不得追认**。**长度方差上升是本机制的已知副作用，已单列**：插件臂答复长度 sd **22.4**
> 对基线臂 **10.3**（约 2.2 倍），3 条超长样本（208、179、179 字符）**全部来自插件臂**，同一任务另一次重复
> 仍可通过，故该副作用表现为"离散度与长尾增大"而非"必然变长"（配对差中位数 0、符号 6 正 6 负）。

### 选项 1 是否还有能改变结论的后续工作？

**在判据不变的前提下：没有正当路径能改变结论。** 具体地：

- **再跑更多任务**只会重复已知形态：严格失败的全部 3 条样本都**只**违反长度条件（见 §4），而插件臂长度
  分布比基线更宽更靠上（sd 22.4 vs 10.3），因此新任务只会以"某个任务的答案恰好越过 160"这一形态再次失败，
  或在答案本就短的任务上通过——**后者等于按结果挑任务**，那本身就是改判据。
- **再跑更多重复**在原则上有机会把 `xarray_copy_dtype` 的 1/3 抬到 3/3（该失败**非确定性**：同任务第 3 次
  重复 143 字符通过），但这是**对已知随机变量反复重掷**，直到某次通过为止；预注册验收线要求"逐任务 ≥ 基线"，
  按观测结果加跑重复属于**按结果调参**，与既有纪律冲突，且不改变"长度长尾存在"这一事实。
- **换更短答案的任务族**：需要新的准入判据（例如"基线答案长度远离 160"），**这是判据变更**，应走选项 2 的
  同一条路径（新实例、新 ID、前瞻冻结），不能在旧判据下悄悄生效。
- **改机制**（缩短指针、改变指针位置等）属机制变更，不在本裁决包范围内；且机制变更后的结果是**新证据**，
  同样不能救回 v12–v14 的结论。

## 3. 选项 2 的预注册协议草案（**只写，未冻结、未运行、未批准**）

> 状态：**DRAFT / NOT FROZEN / MAY NOT BE RUN**。本草案不得被当作已批准判据，也不得据此发起任何请求。
> 若用户批准，须另建新 ID 的冻结文件（写一次），并把本草案中每一项写实。

1. **新任务与状态**：`v15_<task>` 系列，实例为**新**留出实例（≥3，建议 4），**不得复用** v13 的
   `psf__requests-1766` 或 v14 的四个实例（均已用掉）；不得把 v12–v14 的结果作为本判据的依据或先验
   （用旧结果设计新判据＝用旧结果调判据）。
2. **验收主轨＝事实轨（唯一验收轨）**，判据写死、逐样本计算：
   - 前缀完全匹配（`RESULT issue=<short-id> cause=`）；
   - 单行（无换行）；
   - `cause=` 与 `fix=` **两个字段都在且非空**；
   - **必需字面齐备**（大小写不敏感的整词/标识符匹配，字面在冻结时从**基线视图**中选定并逐条登记）；
   - **禁字面未出现**（冻结列表，例如宣称"无问题/无需修改"的措辞）；
   - **冻结正则整串匹配**（`re.fullmatch`，含顺序与边界约束）。
3. **长度轨＝只报告，不参与判定**，并显式写明：**`≤160` 字符不再是验收条件**；长度轨报告内容固定为：
   各臂答复长度均值/中位数/sd/极值、配对差的中位数与符号分布、超长（>160）样本计数与逐条清单；
   报告须声明"**长度方差上升是本机制的已知副作用**"（v12–v14 观测：插件臂 sd 22.4 vs 基线 10.3）。
4. **replay 门（付费 Stage C 的硬前置，四项缺一不可）**：①逐边界复现记录的载荷（结构、连续性、
   每个输出 SHA256/字符数）；②插件项逐项可复算（指针文本恰好等于冻结形式、目标全文仍在同一 payload）；
   ③presence **fail-closed** + **负控制**（把唯一证据项换成指针必须被报出）；④不变量五列
   （任务约束、当前证据、去 id 工具组哈希、恢复/整份回退记账、源定位）。另报**逐调用口径投影**；
   **投影 <3% 或守卫后安全集合为空 → 不进入付费批**。
5. **预算与上限（4 实例）**：模型 `deepseek-v4-flash`、thinking disabled、`max_output_tokens 1024`、
   `max_turns 10`；provider 预算 软 2000 / 目标 1500 / 硬 6000 token；过滤硬上限 65,216 B；
   **每样本摘要调用上限预注册（建议 3）**；请求上限 **≥ tasks×3×24**（4 实例＝288，建议 300），
   最坏情况必须落在上限内，**不得事后截断**；`data_class = public_source_diagnostic`。
6. **失败线（任一触发即停并如实报告）**：事实轨未达基线（逐任务与合计）；配对完整总节省 <3 %；
   实际替换数为 0；必需字面 presence 归零；禁字面出现；配对/项数/顺序破坏；独立审计 `complete=false`；
   请求或摘要上限被突破；合格任务不足 3 个（如实报"合格任务不足"，不降门槛）。
7. **不追溯条款（写进冻结）**：本判据**只适用于其自身批次**；**v12、v13、v14 的严格轨结论原样保留、
   不得重判、不得追认**；本协议的通过结论**不得**被表述为"四判据达成"，也不得与 v13/v14 的百分比合并。
8. **纪律**：一旦进入付费批，其实例即为**已用**；不得在其上调参重试，重试须换机制并另选新实例。
