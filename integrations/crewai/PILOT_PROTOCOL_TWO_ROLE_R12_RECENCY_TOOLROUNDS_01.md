# CrewAI r12 结构保护批：最近 K 个工具轮逐字保留（不加任何 host 指令）

本协议冻结在付费运行**之前**。冻结文件 `integrations/crewai/PRE_RUN_FREEZE_TWO_ROLE_R12_RECENCY_TOOLROUNDS_01.json`（付费）与 `..._MOCK_01.json`（零 API 栅格）。

## 1. 为什么这一轮改"结构"而不是"给模型下指令"

r11 用「追加 host 指令」修 r10 的工具序列缺陷，已被证伪：指令的触发条件（"冻结工具表里还有未调用的工具"）自我维持，第一角色在同一工具上打转（12/16 样本观测 JSON 逐字重复 6 次），`tool_sequence_consistent` 从 10/16 掉到 **0/16**，配对完整总 token **−68.28%**。因此 r12 **不添加任何指令消息**，只改结构：保证第一角色当前所需的工具轮不被压缩掉。

## 2. 机制：v9 三层 + 一条确定性结构规则（`crewai_recency_tool_rounds_v12.py`）

CrewAI 适配器把每个工具调用/观测对替换为带 `_context_pruner_crewai_group` 的占位消息，并在中间件返回后按组**逐字节恢复**真实消息。因此「占位消息活下来」就等于「该工具轮逐字保留」。v12 中间件在 v9 三层**之上**：

1. 从**压缩前**的准备列表里按顺序取出受保护工具轮占位消息，取其中**最新 K 个**（按 group id 去重；`K` 在本协议冻结为 **1**）；
2. 照常运行冻结的 v9 中间件（v9 的逐字证据钉住、任务合同钉住、预算守卫与计数型 tier-3 全前缀回退**全部保留**）；
3. 只把「压缩视图丢掉的最新 K 个占位消息」**原样追加回去**——追加的是适配器自己构造的占位 dict，不是新写的文字，因此适配器会把**真实工具消息**逐字恢复；中间件不生成任何新内容；
4. 更早的轮次仍可被压缩（这才是收益来源），**每个被省略的轮次都逐调用、逐样本计数**（`recency_omitted_tool_rounds_total`）。

省略仍受既有守卫约束：v9 的 tier-1 钉住保证每个 `handle_facts` 字面量及其工具证据仍在视图里；若钉住后仍缺字面量，则触发**已计数的 tier-3 全前缀回退**。规则只读取冻结任务记录与压缩前消息列表，**不读模型行为**，因此不可能像指令那样自我维持。

**K=1 的含义**：只保证"角色当前正在处理的那一轮"不改写；已经完成、不再是最新的工具轮仍可折叠（其事实由 tier-1 钉住负责）。若 K=1 仍不足以保住工具序列，按预注册节奏允许**一次**版本升级（v13，同样只动结构、同样一个付费批次），开始前先报告。

**验收线（预注册，两个都要报）**：

1. 插件在 `tool_sequence_consistent`、严格质量、语义质量三项上**都不劣于**无压缩臂，且完整总 token 配对均值为正 → `valid_equivalent_saving`；
2. **是否还剩可压缩内容**：审计输出 `still_compressible` 与 `boundary`。若正确性全部保住而插件臂**没有任何**被省略的工具轮（`recency_omitted_tool_rounds_total = 0` 且 `compression_events = 0`），则写成边界结论 **"在该宿主上，保住质量后已无可压缩"**——这是合格交付，**不硬凑正收益**。审计在 `errors` 非空时必须明文写出"本批数字不得当作有效节省"。

## 4. 同任务集对照与矩阵

**任务集不变**：`tasks/stage5_autogen/natural_tasks_r10.json`（哈希 `873a306b…`），因此 r10 / r11 / r12 的差值只在**机制**这一维度上。矩阵 **4 任务 × 4 重复 × 3 臂 = 48 样本**；臂顺序按 r4 `balanced_plan` 轮换；重复间载荷完全一致；`deepseek-v4-flash`、温度 0、禁用 thinking；provider soft/target/hard = 1200/900/3000；`fixed_reserved_tokens=300`；输出 ≤512；摘要 ≤1024 token/角色 ≤4 次。

**全局请求上限 440**，算术：最少 agent 请求 = 2 × 48 = **96**；`native_summary` 臂病态最坏摘要请求 = 2 角色 × 4 次 × 48 = **384**；440 = 96 + 344（最坏值的约 90%），比 r10 同栅格实测 **319** 高约 34%、比 r11 实测 **362** 高约 22%。v12 不添加指令，插件臂应回到基线的 6 次调用/样本（16 样本 × 6 = 96），预期总量约 **320–330**。触顶则停止、保留部分目录、按新 id + `--resume` 续跑，不把部分栅格当完整栅格。
