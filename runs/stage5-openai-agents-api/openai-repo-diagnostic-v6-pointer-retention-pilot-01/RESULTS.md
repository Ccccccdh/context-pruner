# OpenAI Agents v6 指针式行范围保留小试

2026-10-04 完成。独立审计 `audit.json`：`complete: true`、`issues: []`、`evidence_checked: 9`、9/9 样本、**33 次 API 请求尝试**（全局上限 100）。协议 `integrations/openai_agents/REPO_DIAGNOSTIC_V6_POINTER_RETENTION_PROTOCOL.md`；冻结 `integrations/openai_agents/REPO_DIAGNOSTIC_V6_POINTER_RETENTION_FREEZE.json`（含 28 份源码/测试/协议脚本与 3 份公开输入哈希；冻结集**包含审计器自身源码、v6 零 API 门控脚本与 v5 归因诊断脚本**）。零 API 归因诊断见 `integrations/openai_agents/V5_COST_REGRESSION_DIAGNOSIS.md`。

## 0. 预注册验收线与本批判定

预注册（写入冻结与协议）：**插件严格质量 ≥ 基线 且 完整总 token 配对均值为正**。

- 插件严格质量 **0/3**，基线 **2/3** → 质量门槛**不通过**。
- 完整总 token 配对均值 **−176.36 %**（正收益对 **0/3**）→ 成本门槛**不通过**。

**判定：not-yet-valid。** 插件在两个门槛上都不达标，且方向比 v5 更差；本批判定机制**尚不可行**，样本量保持最小（1 任务 × 3 重复 × 3 臂 = 9 样本），不扩样、不做任何事后改判。

## 1. 这批做了什么（相对 v5 的唯一机制变更）

v5 的零 API 归因诊断把 −79.79 % 分解为（provider input token，残差 ≈ 9e-13）：多走一次模型调用 **+2,335.8**（占回退 99.85 %）、被组基线假阳性挡掉的压缩 **+140.2**、固定文本造成的载荷膨胀 **−136.7**（同一边界比较，即插件的第 2 次调用比基线便宜 137 token）。结论：**主导项是调用轮次，不是重传字节**。

v6 据此只改机制本体，并同时修掉 v5 自己记录的组基线假阳性（**不回写 v5 冻结源码**）：

1. 承载约束的工具输出**不再整份固定**，改为**行范围保留**：只保留携带已注册字面的行（`CONTEXT_LINES = 0`，冻常常数）+ 头部行，其余行区间换成确定性指针；保留行与被省略区间必须**恰好划分**注册范围，且**任何承载注册字面的行都不得被省略**；
2. 指针写明 `repo/path`、被省略的确切行区间、保留行号、省略字符数与重新取回所用工具名；
3. 组基线只从**未被机制改写的观测**中取，并按条目公共前缀比较（v5 的 `_group_hashes` 会在每一次调用含过滤后观测写基线，被自己的注释污染）。

矩阵与 v1–v5 相同：`django_count_annotations` 1 任务 × 3 重复 × `none`/`pruner_v1`/`native_summary` 三臂 = 9 样本；`deepseek-v4-flash`、禁隐藏 thinking、provider soft/target/hard 2000/1500/6000、输出上限 1024、全局请求上限 100、三臂轮换、逐样本落盘；`manifest.json` 的 `data_class` 为诚实的 `public_source_diagnostic`。

**零 API 门控在付费前通过**：`tests.test_openai_agents_evidence_safe_retention_v6` **24 tests 全通过**（23 通过 + 1 父门控子进程跳过项），冻结的 v1–v5 六个测试模块与 v5 组基线诊断测试全通过。门控测量到的投影节省为准正：最后一次调用载荷 **7,921 → 4,481 字节（−43.4 %）**，按 v5 批次自身的换算比例投影，插件完整总 token 从 v5 的 5,325 降到约 **3,873（−27.3 %）**。**这个投影没有成立 —— 见第 3 节。**

## 3. 质量与成本为什么都失败：机制被真实模型"反向利用"

审计逐样本核对（`audit.json` 的 `per_sample_facts`）：

| 重复 | 插件省略的源/行 | 保留的字面行 | 省下字节 | 插件模型调用 | 相对基线的额外调用 |
|---|---:|---:|---:|---:|---:|
| 0 | 30 / 1,203 | 66 | 45,351 | **6** | +4 |
| 1 | 30 / 1,203 | 66 | 45,351 | **6** | +2 |
| 2 | 3 / 130 | 6 | 5,075 | 4 | +2 |

**3/3 插件样本都需要比基线更多的模型调用**（审计字段 `plugin_samples_needing_extra_model_calls_vs_baseline = 3`）。两个样本直接以 `MaxTurnsExceeded` 结束（`max_turns = 6`）。逐调用输入 token：重复 0/1 为 `662 → 1,321 → 2,517 → 2,110 → 3,304 → 2,899`，即模型在每次被省略之后**重新调用工具取回被省略的行**，于是历史不断增长、调用不断增多，最后触顶、没有产出合同要求的单行答案。

也就是说：

- **机制本身按设计工作**：省略、指针、保留字面行、行区间划分、工具组边界、字面生存守卫全部通过审计；`task_anchor_restore_failures`、`budget_fallbacks` 全为 0，`restore_failures_by_model_call` 全零；四个已注册字面在每次模型边界的出现次数**不低于基线**（审计以基线为下界逐字面核对，并通过）；v5 的组基线假阳性在本批**归零**（v5 批为 3，本批为 0）。证据安全的三个目标都达到了。
- **代价方向被模型行为翻转**：零 API 门控的假模型按固定轨迹在固定调用数后作答，它**无法**表现"省略会诱发重新取回"。真实模型看到指针后选择重新调用工具，于是 v6 用"少发字节"换来了"多发整轮"。**这正是 v5 诊断第 3 节留作风险的那条路径，本批把它测成了负结果。**

**结论：把"模型已看过的大段证据"从载荷里移走、只留指针，在本任务上会诱发重新取回，因此"证据安全 + 更便宜"这一版机制不成立。** 离线门控能验证证据安全与载荷缩减，但**不能**验证轮次假设——这必须在付费批次里测量，本批给出的就是该测量。

## 5. 边界

- 本批只有 **1 个任务、3 个重复、9 个样本**，且 Django 任务在 v1–v5 已参与调参；**不是**未参与调参的盲测确认批，禁止外推到多任务、其他宿主或真实软件修复，也禁止与 CrewAI / OpenHands 的百分比合并。
- 基线臂重复 1 为失败样本（严格合同不符），照实报告、未剔除；配对口径保留全部样本与失败，不做成功子集筛选。
- `selective_retention_notes_with_source_pointer` 是 v5 引入的计数器，按 v5 注释形状计数，对 v6 的"头部+标记"形状计为 0；本批的指针证据以逐输出 `note_has_source_pointer`、`pointer_completeness` 与 `evidence_span_elision_records` 为准（全 True、全通过）。该计数器未用于任何判定。
- 证据只有哈希、长度、布尔、计数与行区间边界，不保存原文；审计通过只说明冻结哈希、账本、资格判据、质量口径、字面保留与行区间划分一致，**不等于语义等价，也不构成成本有效的结论**。
- v1–v5 源码、协议、冻结与结果目录保持不变；v6 使用新文件、新协议、新冻结与新批次 ID。本批未做任何事后改判。

## 6. 下一步（不建议继续付费扩样）

1. **不要在同任务上继续加大样本**：质量 0/3 与成本 −176 % 都是机制缺陷，不是样本量问题。
2. 若要继续这一方向，需要先解决"省略会诱发重新取回"这一行为：可能的做法是**只在正确答案不依赖被省略文本时省略**（例如把省略限制在不承载字面、且不是最近工具组的输出，并在合同层要求模型直接用指针作答），并为此设计一个**能表现重新取回行为的离线假模型**（按载荷中是否出现指针决定是否再次调用工具），再在零 API 下证明轮次不增加。
3. 只有出现"质量不劣 + 完整总 token 稳定为正"的离线证据，才考虑换**未参与调参的新公开仓库任务**做 3×3×3 确认；跨宿主百分比一律不合并。
