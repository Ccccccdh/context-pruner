# OpenAI Agents v12：逐字重复输出预筛（零 API，2026-10-05）

## 候选机制

在同一模型输入中，只有较新的工具输出与较旧输出**逐字相同**时，才把旧输出换成含较新 `call_id` 与原文 SHA256 的短指针。较新输出全文、每个工具调用、每个输出项和原有顺序全部保留。这与 v11 调整最近 M 次调用的窗口不同；不按行裁剪源码，也不省略唯一证据。

## 实测载荷 replay

读取 v9 三个无压缩重复的 `input-evidence` 中 `output_manifest`，逐边界将其输出 SHA256 和字符数与公开基线源码重建值比对，全部一致。原批 `audit.json` 已签署完整。结构指纹也与实测输入一致；因此此处的六次工具调用与三段源码各重复一次，来自**实际记录**，不是虚构桩。

三个重复各自在七个模型边界中，最后三处分别可替换 1、2、3 份旧逐字重复输出。逐重复 replay 均保持工具调用与输出配对、每种独特源码至少一份全文、最新副本全文、输出项顺序和数量。六个含工具调用边界的序列化输入字节为 63,026 → 50,391，投影节省 **20.05%**。这是**字节投影**，不是供应商计费 token，也不是质量结果；三次重复是同一确定性输入，不能当成三个不同任务。

## 门控结论

**同一 Django 任务的有界开发小试门已通过，未参与调参任务的确认门仍未通过。** 现有六读真实载荷仅有参与 v1–v11 调参的 Django 任务。`pytest_mro` 与 `pylint_regex_csv` 有公开源码与既有短任务记录，但没有六读版本的**真实模型输入**，不能凭合成后半程宣称新任务 replay 通过。因此开发小试可在新 ID、冻结上限和独立审计下运行；结果不能当作未参与调参任务的确认。

若以后取得未参与调参任务的真实六读输入记录，应先按相同 SHA256、配对和唯一证据检查运行此门，再在**新 ID** 中冻结模型、任务、重复数、三臂矩阵、请求和 token 上限、失败线、公开源码发送类别及独立审计。所有失败样本计入配对。通过后再运行盲测确认。
