# OpenAI Agents v3：Django 任务约束保留机制小试

v2 独立证据表明：Django 插件臂三个重复在第二次模型调用前，把公开问题陈述中的 `other annotations` 字面约束从最终模型输入移除，并且 0/3 过冻结质量；无压缩与原生摘要各 3/3。v3 只改变插件臂的输入过滤机制：在共享触发门**内部**用短 system 占位符保护最初两条 user 消息，完成原有压缩后逐字恢复；如果占位符缺失或重复，则退回原输入。三臂任务、公开源码、模型、提示、答案合同与 token 阈值沿用 v2。该版本仍是调参开发，不能作为独立确认。

冻结矩阵：仅 `django_count_annotations` 1 任务×3 重复×`none/pruner_v1/native_summary` 3 臂，共 9 样本；DeepSeek `deepseek-v4-flash`、禁隐藏 thinking；provider soft/target/hard 2000/1500/6000，输出上限 1024；全批 Agent、摘要、重试请求尝试上限 100。完整总 token 包括摘要辅助调用，失败样本照计。只发送公开问题陈述、固定公开基线源码、Agent 工具结果与压缩摘要；不发送参考修复、宿主测试补丁、密钥或本地私有文件。

前置零 API 门控：`tests.test_openai_agents_task_anchor_v3` 的 9 样本真实 SDK 假模型三臂测试、单例逐字恢复和丢失占位符回退均通过；独立 v2 证据审计检查模型调用、过滤对、保护组哈希与最终边界；v1 审计沿用冻结质量与 token 统计。新冻结文件哈希包含 v1/v2 基础运行器、v3 机制与入口、审计、测试、协议及 10 份公开输入。运行前核对输出目录不存在、endpoint、密钥环境变量、`--plan`。

判定：主质量仍为冻结严格答案合同；同时报告第二次真实模型输入是否保留 `other annotations`、`filter`、`ordering`，完整总 token 的 3 对配对节省、保护恢复失败数。只有质量不低于基线且插件实际触发，才可称这 3 对小试为有效节省；单任务小试不外推多任务，更不外推真实软件修复。
