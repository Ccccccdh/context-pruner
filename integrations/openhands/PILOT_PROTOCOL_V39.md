# v39 Django 反馈预算小试协议（开发性）

v38 的三组代码均未通过宿主目标测试。无压缩组、原生摘要组、插件组
分别使用了 33、36、36 次 Agent 请求；后两组在宿主反馈到达后无
未预留的编辑请求。v39 使用同一个 `django__django-16263` 固定任务、
同一公开工作区和宿主补丁、同一模型与三组设置。任务已在 v38 使用，
本轮是受先前结果启发的**开发性复试**，不得称为独立盲测或新任务泛化。

唯一有意改变的共享机制是请求分段：总上限仍为每样本 36 次 Agent
请求、16 次摘要请求。首次实现最多 24 次工作请求，接着最多两次
用于公开测试和 Finish；宿主检查后若目标失败，至多保留 10 次用于
修正，包含末尾公开测试与 Finish。两阶段共用同一总 token 上限。
首次阶段还预留 10×80,000 的估计输入容量给后续修正；这些是上限，
不是预期消耗，也不改变供应商计费方式。三组执行相同策略。

主要指标仍为相对于无压缩组、包含摘要开销的供应商总输入 token
减少率，所有失败与未压缩样本纳入；同时单列目标测试通过、正常
完成、API 错误、压缩次数及实际修正请求数。比较 v38 与 v39 只能
描述协议改变后的探索性差异，不能把质量改变归因于插件。

先通过策略单元测试和零 API 正负门控，冻结源码哈希。只有在另外
明确授权本轮公开 Django 上下文和付费请求后才可运行 1×1×3。
如质量未通过或未压缩，停止扩大付费实验并保留全部样本。
