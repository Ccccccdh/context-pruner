# CrewAI r15 载荷获取运行协议（无压缩臂，仅产出真实宿主载荷）

本协议与冻结文件 `integrations/crewai/PRE_RUN_FREEZE_R15_PAYLOAD_ACQUISITION_01.json` 在**付费请求之前**写定。**冻结一经写定不得再改**；如需修订，另建 `*_FREEZE_AMENDMENT_<日期>.json`（记录改了什么、原因、新旧 SHA256），并在批次 manifest 中记录**冻结文件自身**的 SHA256。

本批**不是**节省证据、**不是**质量等价检验：它只有一个目的——为四个新任务产出**真实的 CrewAI 宿主载荷**，供 `experiments.commands.crewai_candidate_gate_r15_real_payload` 复算第 1–3 门。r15 候选门此前停止在第 1 门（新任务无宿主记录）；本批是该门前置条件的补齐，属于**工具性获取**，不用于任何收益主张。

## 1. 任务集（新 ID，同形质量合同）

`tasks/stage5_autogen/natural_tasks_r15.json`（4 项，SHA256 见 manifest）：`service_release_gate`、`schema_migration_gate`、`flag_promotion_gate`、`cache_promotion_gate`。

同形合同（四项一致）：

1. **第一角色**按**固定顺序**读取 **4 份相互独立的当前证据**：配置 → 运行指标 → 变更记录 → 校验结果，每份一个工具、各调用一次；
2. **第二角色**按冻结规则作出**一个可核验的发布或回滚决定**：`RELEASE` / `REVERT` / `PROMOTE` / `DISABLE`，决策词与必需字面量由判据逐字校验；
3. 每任务有**独立验收规则**（`answer_facts`）、**固定事实**（`handle_facts`）、**工具顺序**（冻结工具表）与**失败标签**（`forbidden_facts`，把答案误判成历史值即失败）；
4. 历史由**自然产生的过期讨论**构成（`history_topic` 与 archive 片段），**不重复铺设合成"第 N 次历史交接"**；
5. 四项任务均未参与 r9–r13 任何批次的调参（零 API 探测断言：任务 id、工具名、事实字面量、区域、版本、决策词均不与 r3–r13 复用）。

## 2. 采样矩阵与臂

| 项目 | 值 |
|---|---|
| 臂 | **仅 `none`（无压缩）**，`--methods none`；runner 对其它臂直接拒绝 |
| 任务 × 重复 | 4 × 3 = **12 样本**（`--repeats 3`） |
| 模型 / 温度 / thinking | `deepseek-v4-flash` / 0 / 禁用 |
| provider soft/hard/target | 1200 / 3000 / 900（估计等价 3085/7712/2314） |
| `fixed_reserved_tokens` / 输出上限 | 300 / 512 |
| 摘要 | **该臂不产生摘要请求**（`native_summary` 不在矩阵内） |
| 全局请求上限 | **120** |
| 发送数据类别 | 合成运维数据（`--confirm-send-synthetic-data`） |
| 历史垫料 | 14 组 archive 片段（`filler_history_pairs=14`，写入 manifest） |

**请求上限算术**：最少 agent 请求 = 每样本 2 个角色 ≥ 2 次调用，但本任务形状实测为第一角色 5 次（4 工具轮 + 1 交接）、第二角色 2 次 → 每样本约 7 次，12 样本约 **84** 次；120 = 84 + 36（约 43% 余量，覆盖重试与偶发空响应）。触顶即停止并保留部分目录，不把部分栅格当完整栅格。

**停止线**（写入 manifest）：全局请求上限到达、空模型响应、连接类错误（`APIConnectionError`/`APITimeoutError`/`connection error`/余额/限流/认证）。失败与触顶样本**全额保留并计数**，不重试掩盖。

## 3. 逐样本记录的载荷（第 2 步命令的输入）

每个样本记录两角色的**逐调用真实载荷**：消息角色序列、每条消息的 SHA256 与字符数、每个角色**首次调用**的逐字消息文本（即需要被压缩的那一帧）、逐调用新增帧字节与 provider 上报的输入/输出 token、工具轨、交接行、最终答案与判据结论，以及 `payload_sha256`。第 2 步命令据此计算：

- **第 1 门（真实载荷）**：目录、manifest 目的字段（`purpose=payload_acquisition_only`、`citable_as_saving=false`）、每行载荷块与指纹、源文件 SHA256 全部匹配；**mock 批次在非 `--force-mock` 下直接拒绝**；
- **第 2 门（质量安全候选）**：第一角色工具序列 = 冻结工具表（4 个证据源全部调用且顺序一致）、首轮交接含全部 `handle_facts`、补救 0、无错误；
- **第 3 门（≥3% 上界且 ≥3 任务非零）**：`upper_bound(t) = 第一角色首次调用的 provider 输入 token − 保护成本`，其中保护成本 = 钉住字符 / 实测每 token 字符数 + 整份回退 token + 辅助摘要 token。本批为无压缩臂，这三项实测为 0；命令仍把它们实现为可非零项，接入插件臂后立即生效。**同工作量**由第 2 门保证（不得把少调工具/少调用模型算作收益）。

## 4. 零 API 先行

1. `.tooling/probe_crewai_r15_tasks.py`：四项任务的新意与自洽（判据对构造样本通过；截断交接、尖括号回抄、错误决策、禁用事实一律拒绝）。
2. `--mode mock --repeats 3`：12 样本全绿（严格/语义/首轮/工具序列 12/12），载荷块结构完整且**不含任何真实请求**。
3. 接口检查：`crewai_candidate_gate_r15_real_payload --force-mock` 只验证门命令可运行并能算出逐任务上界；其结果**不得**作为门控判定。
4. `--plan` 经密钥启动器核对任务×重复×臂、模型、预算、上限与目的。

## 5. 边界

- 本批**只有无压缩臂**，因此：不产生配对、不产生节省、不构成质量等价证据；引用它时必须同时引用"仅载荷获取"这一性质。
- 4 任务 × 3 重复只有 4 个任务层观测点，不能给出置信区间；温度 0 仍有独立轨迹差异。
- 不覆盖、不重跑、不重打分 r9–r14 的任何目录、冻结、答案或评分；三宿主数据不得合并。
