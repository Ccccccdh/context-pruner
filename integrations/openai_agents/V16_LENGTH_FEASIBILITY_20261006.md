# v16 长度可行性回放：所有臂共用输出约束/校验器（零 API，2026-10-06）

**这是新主机配置的回放投影，不回写 v12–v14 任何冻结、评分或答案**；未发任何请求。
机器输出 `V16_LENGTH_FEASIBILITY_20261006.json`（生成器
`experiments/runners/openai_agents_v16_length_feasibility.py`），只用已记录数据。

## 1. 回放结果：四种条件能否同时满足

| 批次 | 已记录样本 | 超长样本 | 超长且**仅**长度不合格 |
|---|---:|---:|---:|
| v12 django_long_investigation | 3 | 1 | 1 |
| v13 requests_digest_qop | 9 | 0 | 0 |
| v14 三任务 | 27 | 2 | 2 |
| **合计** | **39** | **3** | **3** |

对每个样本把答案重新拆成 `issue` / `cause=` / `fix=`，逐条机械检查"字段在位 / 必需事实 / 冻结正则整串 / ≤160"。
超长的 3 条**全部只违反长度**，与既有清单一致。

**删除式最小答案（只用原答中的子串，不新增词、不重排）**：对每个冻结合同算出同时满足"必需事实 + 冻结正则
顺序与边界 + ≤160"的最短答案，长度为 **54 / 65 / 66 / 76 字符**（远小于 160）。
→ **结论：四种条件在"答案空间"里可同时满足（可行性存在）**；但这**只证明存在**，
**不能证明活模型会给出这样的答案**（零 API 回放不具备该能力）。

**由此得出的两条限定（必须一起读）**：
1. 删除式最小答案只保留必需令牌、丢掉其余内容——**机械合格但语义退化**，不宜作为"所有臂共用的校验器"去**改写**模型答复；
   回放支持的是"约束+校验（不合格就重试）"，不是"宿主替模型改写"。
2. **已有一次真实修复尝试的反例**：v15 付费批里 `django_textchoices_string_value` 首答 166 字符，
   全臂共用包装层**已付费重试一次**（input 2,186 / output 39），模型返回**逐字相同**的 166 字符答复
   （两次答复 SHA256 相同），重试未通过格式门。这是本仓库目前唯一一条真实"格式修复"记录。

## 2. 重试最坏成本，以及它对成本门的影响（判据：完整总 token，**含格式修复调用**）

重试定价方式：每条超长答案 **+1 次请求**，输入取该样本**自身**最后一次调用的输入 token（重发最终载荷），
输出取该样本自身的答复输出 token——即**全额计入产出该答案的那个臂**。

| 批次 | 实际发生修复 | 实际额外 token | 最坏情况（每样本都修复） | 最坏占该批 token | 配对节省（记录值 → 计入修复后） |
|---|---:|---:|---:|---:|---|
| v12（1 任务 × 1 重复） | 1 | 2,793 | 10,859 | 21.4 % | **+14.63 % → −1.62 %** |
| v13（1 任务 × 3 重复） | 0 | 0 | 37,785 | 20.6 % | +17.50 % → +17.50 %（无超长） |
| v14（3 任务 × 3 重复） | 2 | 8,811 | 103,950 | 20.8 % | **+12.65 % → +9.28 %** |

- **单对批次上，一次修复就能吃掉全部节省**：v12 只有一条配对，重试重发的是最贵的最终载荷，节省从
  **+14.63 % 翻成 −1.62 %**（成本门失守）。
- **多对批次上仍高于 3 %**：v14 由 **+12.65 % 降到 +9.28 %**，仍过门；但幅度掉约 3.4 个百分点。
- "最坏情况每样本都修复"一栏的数字**不是更好的结果**：两臂都付同样的重发成本，百分比可能升也可能降，
  该列只用于说明"最坏请求数 = 样本数、最坏 token ≈ 批 token 的 21 %"。
- 成本影响与质量无关：即使修复成功，严格轨也只回到与基线相同的格式合格率；这一点不得分开表述。

- 若走事实轨，则按 §4 的预注册要求另建新 ID 冻结。

## 4. 预注册要求（若走到那一步；本文件不是冻结）

1. **任务身份**：新任务不得参与过 v12–v14 调参，且**不得因为答案短而被事后挑选**（选择只看公开元数据与
   基线源码，不看模型答复长度）。
2. **登记齐全**：基线提交、三段读取协议（各读两次）、答案判据（事实清单 + `cause=`/`fix=` 结构 + 冻结正则
   + 长度轨口径），以及源码视图的**全部 SHA256**（文件级与视图级）与 `problem_statement` 哈希；
   参考补丁与评测补丁**只登记哈希、不读取**。
3. **获取批**：只用于取得真实载荷，`citable_as_saving=false`、`citable_as_quality_equivalence=false`，
   全部失败与触顶计入。
4. **replay 门（付费前置）**：逐边界证明工具配对、每个唯一源码仍有全文、必需字面 presence 不归零、
   指针可逐字节复算、**守卫后安全可省空间非零**；负控制必须报出"唯一证据被替换"。
5. **成本门**：完整总 token，**明确包含格式修复调用**；修复合法的重试必须记入对应臂。
6. **质量门**：**逐任务**按严格轨（Track A ≥ 基线）判定；Track B 只作诊断，不得写成"质量不降"。
7. **失败与触顶全计**；成本正数必须与严格质量缺口同时报告；不得与其它宿主百分比合并。
