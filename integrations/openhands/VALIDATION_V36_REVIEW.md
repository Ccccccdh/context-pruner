## 付费小试结果

首次付费启动被自动审批拒绝，原因是此前授权不包含新的 pytest 外发上下文。用户明确授权本轮具体上下文及最多 3 个样本后，才用现有环境密钥运行。计划和实际均为 1 任务 × 1 次 × 3 组，原始数据、独立审计和报告保存在 `runs/stage5-openhands/pytest-mark-mro-v36-pilot/`，模型请求已全部停止。

插件相对无压缩的逐对输入节省率是 **-8.71%（n=1）**；原生摘要为 +31.46%（n=1），但该组也未触发摘要。三组均是 `1 failed, 88 passed, 1 xfailed`，失败项均为新增的 `testing/test_mark.py::test_mark_mro`。插件和无压缩组最终结果在第一个位置返回 `xfail("a")` 而非预期的 `xfail("c")`，并多出一个标记；原生摘要组也从 `xfail("a")` 开始且少一个标记。三组模型轨迹不同，不能把这些差异归因于压缩或摘要。

插件的 20k 触发阈值未达到：记录的估计单次输入峰值为 16,210。无压缩组与原生组也没有摘要事件。因此本轮**没有实际检验 v36 的压缩效果**，输入差异仅是不同 Agent 轨迹的描述。没有双方成功的配对可用于质量保持条件下的收益统计；v30 的 37.35% 不能迁移到此任务。

后续由 DeepSeek 辅助离线分析三组功能失败，主 Agent 在新副本独立复核：写入子类标记时读取继承来的 `pytestmark`，导致父类标记先被复制进子类；读取时再按 MRO 收集会重复，而按名称去重会丢失同名不同参数标记。候选修复在选定公开回归与目标测试中分别得到 88 passed、1 xfailed 和 89 passed、1 xfailed。该事后开发复核不改变三组冻结结果，详见 [辅助诊断复核](DEEPSEEK_V36_DIAG_REVIEW.md)。

独立审计复核了 3/3 样本：源码哈希匹配、文件边界与引用有效、凭据命中 0、供应商失败请求 0、`AgentErrorEvent` 0；结束状态与预算交叉检查均为 3/3 一致，预留与提示检查通过。实际美元费用未知，以供应商账单为准。

## 决定与下一步

按冻结协议，只要插件未触发压缩，或出现质量失败，就停止扩大此任务；本轮两项条件均满足。保留三个失败结果，不调整主统计、不覆盖运行目录、不把后续重复称为独立验证。

下一轮先离线选定另一个未用于调参的公开真实问题，预先写下选择标准：可在本机重现正负门控，基线/参考测试稳定，允许的源码与评价边界明确，预计能产生超过 20k 的上下文而无需人为灌入无关文本。选定后先冻结任务、代码哈希、停止规则和样本数；原先已看过的 pytest 问题只能作开发集。真实新任务即使触发压缩，也要同时满足质量和输入指标，才有继续扩大样本的依据。

另外，冻结的 v36 运行器在计算最终变更文件时，对约 580 个文件反复全树计算哈希，形成不必要的平方级开销；三个样本各耗时约 310 秒。后续版本应先计算一次 `final_hashes = hashes(workspace)`，再用该结果比较。不要改动 v36 冻结源码或重跑当前付费样本；新版本需重新冻结哈希并通过零 API 预检。此运行开销会影响墙钟时间，不解释供应商输入 token 差异。
