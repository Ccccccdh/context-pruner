# v37 外部任务离线筛选规则（查阅候选详情前记录）

## 目标与定位

v36 的 pytest MRO 任务三组目标测试均失败且插件未压缩，不能评估长上下文收益。v37 先选公开真实问题做**开发性可行性门控**；本轮筛选规则依据 v36 的机制缺口制定，因此后续任务不称严格独立盲测。选择、失败和排除原因全部保存，不用实际模型跑分倒推挑选任务。

## 候选资格与排序

只用本机已下载的 SWE-bench Verified 数据集元数据，不查看参考修复正文。先排除已用于本项目模型试验的实例；优先 Python 项目，便于在本机建立可复现环境。候选须有明确问题陈述、至少 1 个 FAIL_TO_PASS 测试、可识别的源码/测试路径，且基线提交可获取。

在合格候选中，优先级依次为：

1. 原修复涉及 2～4 个源码文件，且测试跨至少 1 个模块；若无可行候选，再考虑单个较大的源码文件。
2. 元数据难度为 1–4 小时或更长；短于 15 分钟的任务最后考虑。
3. 相关源码合计规模较大、问题需要跨函数或跨模块理解。文件大小只作自然上下文需求的弱代理，不能保证 Agent 实际超过 20k 触发阈值；不得塞入无关文本强行触发。
4. 优先近年基线以降低 Python 3.13 依赖兼容成本；保留其它候选及排除原因。

按元数据形成短名单后，逐个进行零 API 门控：可取得指定基线、隔离依赖可安装、原始目标测试失败而选定公开回归通过、参考修复在同样测试上通过、文件编辑/宿主评分边界明确。首个通过这些门控的候选才进入冻结协议；若门控失败，记录日志后按同一排序检查下一个，不因预想模型表现跳选。完整上游测试或官方 Docker harness 若未运行，报告必须注明。

## 运行与费用门槛

先修复下一版运行器重复全树哈希的耗时，在零 API 预检中验证源文件、工具和宿主测试不会改动工作区。然后冻结任务、候选插件、三组共用工具、质量口径、调用上限、预留/停止规则和源码哈希。首轮最多 1 任务 × 1 次 × 3 组；只有质量、工具审计与压缩触发条件允许，才考虑扩大。新的任务上下文和付费调用不在 v36 三样本授权内，启动前需单独确定范围。

DeepSeek Agent 可以协助读取**脱敏后的问题陈述与公开源码路径**，提出需要核查的跨模块关系和测试场景；它不选择最终任务、不看参考修复正文、不修改冻结协议，也不单独宣布插件达标。主 Agent 负责门控、代码和统计复核。
