# Agents 正式实验后的推进顺序

依据：`AGENTS_FORMAL_QUALITY_COST_V5_RESULT_20261014.md` 和正式 `final-audit.json`。目标是在保持质量的前提下，找出真实计费下降的条件，并明确恢复机制的适用范围。当前 V5 不再扩跑；本安排没有启动新的付费队列。

1. **结项与封存（已完成）**：补齐结果报告、结项状态和文件哈希清单。保留普通失败、旧开发失败与原恢复门 FAIL。以后调参不得再把这三个正式实例作为未见测试集。
2. **零 API 诊断（下一项）**：从 `paid/` 的请求日志按阶段拆分缓存命中/未命中输入、输出、重读、额外轮次和成本；比较相同任务/重复的 A0/A1/A2。核对每次证据依赖时模型实际可见的工具说明、来源摘要和选择。产出逐请求成本表、阶段图及可证伪假设。工具的可用性描述可能影响选择，这是待验证假设，不是已经确定的原因。不得靠重新调用模型补齐旧轨迹。
3. **依据诊断设计 V6 单一改动**：优先评估保留稳定缓存前缀、决策摘要与来源标识的保守归档策略；若主要问题是证据入口，再评估清晰的归档可用性索引或统一读取入口。一次只改变一个因素。统一入口的宿主自动查档必须单列为宿主恢复，不能标成模型自主恢复。新版本新文件，保留 V5 冻结代码；设计确定后再写精确实现计划。
4. **本地验证后做小型开发试验**：先验证旧版本拒绝、来源绑定、缺失/无须恢复、TTL、工具配对和计费边界。再为新候选冻结 2—3 个开发实例 × 三臂 × 一次的小队列，单独设置预算与操作 claim。通过率、完整成本、重读和恢复机制同时记录。保留正常读取替代路径，不通过强制调用恢复或禁止重读制造贡献。此处是后续安排，本轮未启动付费试验。
5. **明确推进门或停止门**：若完整成本仍升高或恢复仍无自然使用，停止扩跑同一任务家族，调整任务适配性或收窄论文主张。只有开发证据支持候选质量与成本后，才创建全新的正式未见队列，增加独立实例及任务家族，按方差和目标差异确定样本量；事先明确质量端点与聚类统计方式。
6. **第二宿主与论文材料**：Agents 候选机制清晰后再迁移到 CrewAI，分别核验宿主生命周期、缓存和恢复语义，分别报告结果。当前即可整理工程正确性、输入节省与负成本结果，形成有边界的论文证据；暂不同时推进两个宿主的大规模付费队列。

最近一轮工作以第 2 项的诊断报告和第 3 项的候选设计为交付物。建议先完成这两项，再决定具体 V6 改动；当前证据不足以提前承诺恢复收益或美元节省。
