# OpenAI Agents v16：结构化终答零 API 设计（2026-10-06）

本轮只设计和运行离线测试，**API 请求 0**。v12–v15 的冻结合同、失败判定与账本不变；`≤160` 字符仍是将来 v16 严格主轨。v15 已付费的 11964 答复没有用于选择规则、字段或测试样本。

## 全臂共用的终答路径

模型提出 JSON：`{"issue":"...","cause":"...","fix":"...","facts":["..."]}`。宿主对 `none`、`pruner_v1`、`native_summary` 安装同一版本的 [确定性 renderer](../../experiments/runners/openai_agents_structured_final_v16.py)，按原字段逐字生成 `RESULT issue=... cause=... fix=...`。`issue` 必须等于本任务公开的固定 ID；字段必须齐全、无重复键或额外键，`cause`/`fix` 非空且单行；模型自报的每个 `facts` 字符串必须逐字存在于渲染结果。宿主不裁剪、不概括、不补写因果内容。

若渲染结果超过 160 字符，或 JSON/结构不合格，最多发起**一次**格式重试。重试必须走与原调用相同的计费模型和全局请求预算；首答和重试的每次尝试、输入/输出 token、成功与失败均落账。第二次仍不合格就标记严格失败；传输异常而无法证明尝试次数时，标记账本不完整并拒绝验收。独立审计还须核对冻结任务的必需事实、完整正则、工具工作量、源码与指针，不能把模型自报的 `facts` 当成真实答案。

这一实现**目前只是离线参考模块**，尚未接入 SDK Runner，也未证明模型在新 JSON 输出合同下能可靠生成短而正确的 `cause`/`fix`。JSON 字段可能增加输出 token；一次修复可能抵消压缩收益。即使 renderer 对所有臂相同，也不能仅凭离线测试推断质量等价或成本为正。将来接入后，必须重新冻结新 ID、源哈希、全臂请求/摘要上限与独立审计器，再先做小试。

## 合成反例验证

`tests/test_openai_agents_structured_final_v16.py` 的 **8 项标准库 unittest 全通过**：160 字符边界、161 字符拒绝且不截断、缺/多/重复字段、隐藏字段分隔符、错任务 ID、丢失自报事实、换行、一次重试的请求与 token 合计、失败重试仍计费，以及无法计数的异常拒绝验收。测试只用虚构 `sample-42` 和 `OldType`，不包含任何 v15 付费答复。

## 新任务选择协议

[预选脚本](../../experiments/runners/openai_agents_v16_preselect.py)仅从本地 SWE-bench Verified 的实例 ID、仓库、难度、基线提交、题面 SHA256 取数。选择规则固定为：`django/django`、`<15 min fix`；排除已引用或已抽取的实例，以及 v15 四个预选实例（**包括未花费的 13512**）；按 `SHA256("v16-structured-final-2026-10-06" + NUL + instance_id)` 排序，前三个为开发候选、后三个为封存确认候选。结果在 [v16 候选清单](V16_PRESELECT_20261006.json)：开发候选 13821、13410、14089，确认候选 11820、12193、13089。没有用模型答复、答复长度、补丁、测试补丁或成本筛选。

这些只是元数据候选，**尚未取得精确源码 blob、三段视图、题面/源码 SHA256 注册、冻结答案正则，也没有真实载荷**。任何候选若严格基线失败或达上限，均保留失败；不能从列表中递补以宣称原确认门通过。新任务需在请求前完成公开基线源码注册与正反控制，并把开发/确认身份写进冻结。受控六读重复源码工作量只能支持该形状下的结论，不代表自然 Agent 使用或普遍插件效果。
