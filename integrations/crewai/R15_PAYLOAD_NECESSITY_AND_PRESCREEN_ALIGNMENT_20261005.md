# CrewAI R15 载荷获取的必要性判定、预筛对齐与三轮判定（2026-10-05）

本文件回答三个问题，全部为零 API 复算或对已记录数据的重述；不修订 r9–r14 任何冻结、答案或评分，也不改写本批 `RESULTS.md` 的原始记录。

## 1. 载荷获取运行是否**必须**付费？—— 是，且已按新 ID + 预注册冻结执行

**判定：必须，且只做无压缩臂。** 理由分三层，缺一层就不该付费：

1. **门规层面**：R15 候选门第 1 条要求"真实载荷"，其定义是**来自实际 CrewAI 宿主运行记录的真实模型输入**（`REAL_PAYLOAD_PRESCREEN_20261005.md` §2 第 1 条）。四项新任务此前没有任何宿主运行，因此第 2、3 门（安全候选、收益上界）在定义上不可计算——不是"懒得算"，是**没有输入**。
2. **预筛层面的反例**：`REAL_PAYLOAD_PRESCREEN_20261005.md` 明确记录"既有 v9 假模型曾虚构 6 个工具轮并投影 +34.15%，真实载荷实际只有 1 个连续轮"。**假模型桩的系统性偏差是已被证实的**，因此 mock 只能验证接口，**不得**用于收益上界。这条反例是本轮必须付费的直接依据。
3. **纪律层面**：获取运行被限制为**只有无压缩臂**、预注册冻结（协议 + 源 SHA256 + 矩阵 + 预算 + 请求上限 + 停止线 + 发送数据类别）、新 ID、失败与触顶全额计入，并在 manifest 内写死 `purpose=payload_acquisition_only`、`citable_as_saving=false`、`citable_as_quality_equivalence=false`。**它不产生配对、不产生节省、不构成质量等价证据**；它买到的是"第 2/3 门可以被计算"这一前置条件。

**若判定不该付费，替代方案只能是**：把第 2/3 门降级为机制检查、放弃本轮候选门——但那样就无法回答用户指定的"新任务是否有 ≥3% 安全空间"。因此本轮选择付费获取，代价被限制为 84 次请求（上限 120）。

**执行记录**：`runs/stage5-crewai/crewai-r15-payload-none-01`（4 任务 × 3 重复 = 12 样本、84 请求、0 失败/0 触顶/0 错误、完整总 token 156,502）；冻结 `PRE_RUN_FREEZE_R15_PAYLOAD_ACQUISITION_01.json` SHA256 `40b5c385…`。**冻结后为对齐预筛新口径改动了"门命令"**（非 runner、非任务、非协议），按 r15 纪律另建修订件 `R15_PAYLOAD_ACQUISITION_01_GATE_SCOPE_FREEZE_AMENDMENT_20261005.json`（记录改了什么／原因／新旧 SHA256）；已记录的载荷**未重跑、未重打分**。

## 2. 四项分面（预筛 §1 要求：不得只用总长度）

`experiments.commands.crewai_candidate_gate_r15_real_payload` 现在**逐任务分开报四类**，并把"潜在旧单位上界"与"守卫后安全候选"分开：

| 任务 | ①历史可删量（assistant / user 字符，占帧比） | ②当前证据与工具轮（工具数 / 首角色轮数 / 证据标记字节） | ③角色决策行为（首角色调用 / 决策者调用 / 首轮齐全 / 补救） | 可实现上界 |
|---|---|---|---:|---:|
| `service_release_gate` | 755 / 1,730（54.8%） | 4 / 5 / 246 | 5 / 2 / true / 0 | +10.35% |
| `schema_migration_gate` | 747 / 1,765（54.9%） | 4 / 5 / 240 | 5 / 2 / true / 0 | +10.35% |
| `flag_promotion_gate` | 749 / 1,771（55.0%） | 4 / 5 / 230 | 5 / 2 / true / 0 | +10.38% |
| `cache_promotion_gate` | 752 / 1,845（55.7%） | 4 / 5 / 254 | 5 / 2 / true / 0 | +9.90% |
| ④**任务间离散度** | 上界 max−min = **0.48 pp**，sd 0.20 | — | — | 全批 **+10.25%** |

- **①历史可删量**：assistant 历史 747–755 字符、user 历史 1,730–1,845 字符，占首帧约 55%。与预筛里 r4/r9 的 assistant 历史（572–646 字符）同量级、略高；**但预筛已证这一项不能单独预言收益**（r4/r9 从 −0.26% 跨到 +22.25%），因此本列只作结构描述，**不进入上界公式**。
- **②当前证据与工具轮**：4 个冻结工具、首角色 5 轮调用、证据标记字节 230–254；这些由冻结规则**逐字保护**（tier-1 钉住 + K=3 轮保护），**永不计作可删**。
- **③角色决策行为**：四任务 12/12 单元首轮齐全、补救 0、严格/语义全通过 → 基线干净，可作安全候选。
- **④任务间离散度**：上界 0.48 pp 的离散度远小于 r9 的 22.50 pp，说明这四项任务**不靠单项拉动**；但仍只有 4 个任务层观测点，不能给置信区间。
- **潜在 vs 守卫后**：`potential_old_units_upper_bound = 4`（冻结工具数，即策略**最多**能碰到的旧单位），`guard_preserved_safe_candidates = 3`（扣除字面守卫后**可计入**的单元数）；命令把两者分开输出，未合并。守卫保留的最短证据片段字节数逐字面量列在 `guard_survivors`（如 `rel-2207`→80 字节、`us-east-2`→126 字节）。

## 3. 第 3 门按预筛 §2 口径执行

预筛 §2 第 3 条要求：集合为空（OpenAI v9 型）或**保住质量后的离线上界低于预注册成本门**（CrewAI r14 型 0.86% < 3%）→ **停止付费**。

- 本批判定口径 = **可实现上界**（`一次性文本 = 首帧字符 − 后续调用帧增长` → ÷ 实测每 token 字符数 → 减保护成本），全批 **+10.25%**，逐任务 +9.90%~+10.38%，**≥3% 且 4 个任务非零（≥3 达标）** → 第 3 门通过；
- 另报更松的 **ceiling +15.18%**，明确标注**不是**判定口径（它假设压缩后的替代文本免费）；
- 保护成本三项（钉住字符/整份回退/辅助摘要）本批实测为 0，命令已实现为可非零项；**K=3 重新追加的受保护工具轮必须从这个余量里付钱**，这一点写入三臂草案的对照义务。

## 4. 本批不构成节省证据（重复声明）

单臂、12 样本、只有无压缩臂：**无配对、无节省、无质量等价结论**。第 2/3 门的数字是**机制天花板**，不是实测收益；真实插件臂还要承担钉住、受保护轮、回退与摘要的成本，并可能因行为差异损失质量。
