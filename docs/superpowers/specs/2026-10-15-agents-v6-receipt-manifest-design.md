# Agents V6 候选设计：保留可信来源回执

日期：2026-10-15。状态：候选设计已形成；本轮范围为离线诊断与设计，没有实现 V6，也没有启动新付费实验。

## 目标、依据和成功定义

用户要求按顺序完成零 API 成本诊断与 V6 设计。目标仍为保持任务质量、降低完整计费成本；恢复是次要指标。依据 `../../AGENTS_V5_OFFLINE_DIAGNOSIS_20261015.md`：A1/A2 首次工单后均丢失两个必需来源 SHA，模型自然摘要均未保留 SHA，实际恢复调用零，重读普遍发生。

设计只干预“来源回执元数据是否在归档后可见”。工程成功是来源标识持续可见、来源正确、原始历史及工具配对不变、预算覆盖新增元数据；行为收益需在后续真实开发试验中单独观察，不预设一定降低重读或成本。不能把元数据保留算成恢复完整证据。

## 三种路径的取舍

| 路径 | 直接解决什么 | 局限 | 顺序 |
|---|---|---|---|
| 保留可信来源回执 | 已确认的来源 SHA 丢失 | 不能补齐被摘要省略的记录事实 | 首个 V6 候选 |
| 重读证据按实现阶段保留或给予租约 | 研究关闭后重读又快速归档 | 可能增加上下文和计费；需单独定义依赖结束点 | 元数据候选之后再决定 |
| 统一读取入口、宿主先查档 | 降低模型对两条入口作选择的负担 | 改变机制及因果问题；宿主查档不能算模型自主恢复 | 暂缓 |

前缀缓存策略也暂缓：现有 usage 不足以分离提示变化、裁剪与供应商缓存状态。一次同时修改缓存策略、阶段语义和恢复入口，将无法判断哪项产生收益。

## 唯一行为改动

研究关闭后，在每次发给模型的可见输入投影中保留一条独立的宿主来源回执数据项。它只来自本任务已经实际观察、验证过的当前源回执，不来自任务参考答案、独立评分器、模型自行编写的摘要或未读取的文件。

概念格式：

```json
{
  "kind": "host_source_receipts",
  "schema": "agents_receipts_v6",
  "sources": [
    {"entity": "north", "source_path": "docs/north.json", "source_version": "<observed-current-64-hex-SHA>"},
    {"entity": "south", "source_path": "docs/south.json", "source_version": "<observed-current-64-hex-SHA>"}
  ]
}
```

占位值仅用于说明格式，实现不得输出占位 SHA。列表按 entity/path 排序，序列化固定。当前候选限定现有 north/south registry 家族，不泛化为任意文件记忆系统。

新增项没有 multiplier、bias、label、查询选择、期望值或历史正文，也不提供恢复可用性建议、不要求调用任何工具。它记录来源身份，不代替原始记录证据。

## 数据流与边界

1. SDK 工具返回后，使用既有可信工具观察与版本校验路径接收来源回执。只有当前 namespace 中成功的 current 读取可进入清单；历史回执、未读来源、其他任务回执及与当前版本不匹配的回执不能进入。
2. 首次可信研究关闭后生成回执投影；关闭前不新增信息。当前源文件不可变，按任务持有清单；若检测版本变化，旧条目立即失效，不能静默替换为尚未读取的新 SHA。
3. 既有生命周期适配器先完成归档、恢复和预算处理的输入投影，新适配层再加入独立数据项，并对最终模型输入重新计入预算。不得向已经封存的 SDK 权威历史插入或改写项。
4. 以普通输入数据消息承载 JSON，不给予模型输出新的系统权限。清单是宿主生成的数据，任何可信判断仍由宿主自己的回执账本完成；模型伪造同名 JSON 不能修改宿主账本。
5. 按研究关闭位置确定稳定插入点，并在后续可见视图中保持相同顺序。每次投影恰好一项，不能随模型轮次重复追加。若原始关闭结果与证据处于同一被归档原子组，独立清单仍须可见，不依赖该工具输出留存。
6. 最终投影进入边界日志、输入哈希、HTTP 请求体与计费审计。日志须区分 SDK 原始输入、生命周期处理后输入与清单注入后的最终输入，禁止用注入前哈希冒充最终发送内容。

输入投影中的新增清单为普通数据项，不构造虚假的 function_call/function_call_output；原工具组继续满足完整配对。实现时须核验实际 SDK 转换后的消息角色及顺序，不仅检查内存对象。

## 跨臂一致性与控制变量

A0、A1、A2 均增加同一可信回执规则；不得只给 A2 注入 SHA。A0 保留原文，A1 仍不恢复，A2 仍可选恢复。模型、提示文字、工具 schema、工单、评分器、恢复 TTL=2、归档条件和允许重读规则均沿用稳定 V5。本候选不会使 A1 失去普通读取路径。

新增元数据全部计入最终 wire bytes、模型输入预算及实际 usage。清单序列化上限为 2048 UTF-8 字节，最多两个当前源条目，不截断 SHA。超过上限或版本验证失败应在发送前明确拒绝，不能输出伪造、裁断或过期标识。原有 24000 wire-byte 和每样本 16 请求上限继续适用；新增开销也必须占用冻结预算。

## 必须验证的条件

| 条件 | 预期 |
|---|---|
| 未读源或只读 historical | 清单不能凭宿主已知当前版本直接补出 SHA |
| 已读 current 后关闭，原文被归档 | 对应 entity/path/version 可见，正文不因此被恢复 |
| 关闭回执与证据混在同一原子组 | 清单独立保留，原组保持完整配对 |
| 模型伪造回执、跨 namespace、过期 SHA | 不进入可信清单；旧版本不得通过当前版本检查 |
| 重复关闭、连续模型轮次 | 每个最终投影只含一条稳定清单 |
| A0/A1/A2 同样的可信观察 | 清单数据相同；差异仅为既有归档与恢复行为 |
| 清单超过 2048 字节或总请求超过 24000 字节 | 发送前拒绝，provider 请求计数不增加 |
| 重新启动/恢复 checkpoint | 同样的可信观察产生同样清单；无法重建时明确失败，不借新 claim 续跑旧正式队列 |
| 恢复工具没被调用 | 恢复计数仍为零；元数据保留单独计数 |

先 RED→GREEN 验证这些工程条件，再做完整 SDK mock。离线重放只验证可见性和边界完整性，不将旧模型响应作为新策略的质量/成本结果。

## 后续开发试验与停止条件

本轮不执行。实现并完成本地验证后，另行冻结新开发实例、操作 claim、价格依据和有限预算。可以从两个开发实例 × 三臂 × 一次开始观察机制，不能据此宣称统计非劣或稳定节省。三个 V5 正式实例均已用于诊断，不再充当下一版未见确认集。

同时记录：独立产物质量、总成本及三项分解、SHA 可见性、事实 label 覆盖、重读次数及阶段、额外模型轮次、真实恢复信号/投递/使用。判断候选时看逐任务表现和全部失败，不只看总输入 token。

若清单正确可见但重读/完整成本仍无改善，应报告该假设未获收益支持，再单独考察事实缺失或阶段租约；不得追加提示强迫恢复、禁止重读或替换失败样本。若改善主要来自减少 SHA 重读，项目结论是“保留来源元数据有价值”，不能扩大为“恢复完整证据有效”。
