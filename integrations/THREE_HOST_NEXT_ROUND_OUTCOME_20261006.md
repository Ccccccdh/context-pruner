## OpenHands v66 必须同时报告的事实

批次 `runs/stage5-openhands/django-finish-v66-01` 的 `comparison.json` 记载：首次前缀尝试即选中（视图 29,487 ≥ 28,000），共享前缀 322,804 token。各臂完整全程 token 为 none **1,156,393**、native **1,191,887**、插件 **1,039,941**。本轮按预注册停止线没有扩样。

runner 的 `quality_verdict_obtained=true` 只说明取得三条布尔 `failed` 判定且插件压缩，**不说明质量等价**。最终宿主日志显示：none 运行 113 项、errors=4；native 运行 113 项、failures=9；插件在导入 `related_descriptors.py` 时因 `from django.db.models.window import Window` 抛 `ModuleNotFoundError`，**0 项测试启动**。因此“等失败”只能描述布尔标签，不能描述同质质量；插件最终交付物比可运行但测试失败的基线有更严重的故障形态。

冻结 `audit_validation_v66.py` 在读取 `windows-compatibility.json` 后即拒绝：该记录把 `source_path` 写为 v62 wrapper，`source_sha256` 却是 v66 wrapper 自身。v66 manifest 登记的 **107/107** 源哈希仍与当前文件一致；这不能抵消记录内部矛盾。未生成 `audit.json`，也没有冻结审计器的逐分叉重建与宿主重测。新增负控制 `tests/test_openhands_posthoc_shim_mapping.py` 已通过，它只证明错误映射被拒绝、在内存中改为 v66 路径时哈希匹配，**不是对 v66 的追认**。`runs/stage5-openhands/django-finish-v66-01/RESULTS.md` 保留原始数字与质量/审计边界。

## 具体下一步与停止线

1. **OpenHands**：先在新代码版本中让实际 Windows wrapper 产生的 shim 路径与冻结哈希一致；付费前拿该 wrapper 的真实输出做完整三分支审计正例及路径/哈希错配负控制。再加宿主测试“实际启动并运行目标用例数”的质量门，避免导入崩溃被一个 `failed` 布尔掩盖。v66 同任务已是开发任务，不再在其上连续付费寻找正数；新实验须新 ID、新任务或明确的新机制问题，成功路径和冻结独立审计均为硬前置。
2. **OpenAI Agents**：恢复四个候选固定提交的精确公开源码 blob，逐文件核对 SHA256 后才登记三段只读范围和冻结答复合同。先做单臂有界载荷取得（不作收益证据），再在真实载荷上验证全臂格式重试的事实完整性、请求与摘要账本和最坏成本；未过门不付费。
3. **CrewAI**：把“有 Action 但错序”纳入新宿主守卫的零 API 负控制，并用真实续写而非静态旧轨迹证明工具序列和严格质量能恢复；把额外重发完整成本纳入上界。若三项新任务没有安全空间或批级成本下界仍非正，继续停付费。

**总判断**：OpenAI Agents 保持最清晰的跨任务成本正向线索，但严格质量未过；OpenHands 的新策略缺陷修复是工程进展，v66 没有产生成功质量且冻结审计失败；CrewAI 的开发收益仍未在确认任务复现。三宿主仍无一条同时满足多任务、多重复、质量不下降、稳定正节省四项结项条件。
