# CrewAI r14 离线上限估算与最终收口：第一角色"永不压缩"臂的节省上限不足 3%

对象：r13 收口对照（`integrations/crewai/R13_TOOL_LOOP_TERMINATION_CONTROL.md`）留下的那条残留不确定性——**"视图更短这一事实本身是否影响模型倾向"**。要回答它需要一条"第一角色永不压缩、只压决策者"的臂。本文件**先离线估出该臂的节省上限**，据此决定是否付费；结论是**不付费**，并给出该宿主的最终收口结论。

全部为本轮零 API 计算，不重跑、不重打分、不修改任何既有冻结或评分。

## 1. 方法与算法（按角色拆分 token）

`results.jsonl` 逐样本记录每次模型调用的 `input_tokens` / `output_tokens`，而调用顺序是冻结的：前 3 次属于第一角色，其后属于决策者（各臂一致）。于是

- `first_role_tokens = Σ(input+output)` over 前 3 次调用；`decider_tokens` = 余下；
- "第一角色永不压缩"臂的估计成本 = **无压缩臂的 first_role_tokens + 插件臂的 decider_tokens**（第一角色付未压缩的钱，决策者保留冻结机制的钱）；
- 配对节省 = `(none_total − estimate) / none_total`。

三个批次各 4 任务 × 4 重复 = 16 对。脚本：`.tooling/estimate_crewai_r14_upper_bound.py`（第一批估计）与 `.tooling/estimate_crewai_r14_call_effect.py`（剔除"少调工具"混杂后的受限估计）。

## 2. 第一步（乐观上限）：全批 +5.48%，但被"少调工具"污染

| 批次 | 全批配对均值 | 任务间离散度 | 正收益对 |
|---|---:|---:|---:|
| **r13**（与付费验收线同机制） | **+5.48%** | 12.54 pp | 12/16 |
| r12 | +4.79% | 15.34 pp | 12/16 |
| r10 | +8.45% | 29.63 pp | 15/16 |

r13 逐任务（全重复）：`batch_replay` +1.63%、`credential_rotation` +6.19%、`shard_split` +0.77%、`window_gate` **+13.32%**。第一角色占无压缩总 token 的 **57–61%**。

**但这个 +5.48% 不是压缩收益**：r13 插件臂在 4 个样本上**少调了工具**（`window_gate` 重复 1/2、`credential_rotation` 重复 1/3），少一次工具调用同时省掉第一角色与决策者的工作。而"第一角色永不压缩"的臂**不可能靠跳过工作省钱——它恰恰是为了让模型不跳过工作而付出的代价**。因此必须把这一半拆掉再估。

## 3. 第二步（受限上限，也就是真正的上限）：全批 +0.86%

把估计**限制在插件臂工具序列与基线完全一致的 12 个样本**（即两臂调用了同样 3 个工具、同样次数）：

| 任务 | 全部重复 | **受限（同序列）** | 受限样本数 |
|---|---:|---:|---:|
| `batch_replay` | +1.63% | **+1.63%** | 4/4 |
| `credential_rotation` | +6.19% | **+0.01%** | 2/4 |
| `shard_split` | +0.77% | **+0.77%** | 4/4 |
| `window_gate` | +13.32% | **+0.35%** | 2/4 |
| **全批** | +5.48% | **+0.86%** | 12/16（8 对为正） |

辅助证据（同一次计算的直接读数）：

- **调用次数不一致的样本数：0**（在受限子集内两臂调用序列完全一致，故不存在"少调工具"混杂）；
- **同调用次数下第一角色输入缩减：每调用仅 ~0.57%**——这才是冻结机制对第一角色视图的真实压缩效果，折合到完整总 token 只有 **+0.35 pp**（见 §3 的精确分解）；
- 决策者一侧的节省同样很小且与行为无关：决策者占无压缩总 token 约 **39.58%**。

**上限的算术（精确分解）**：受限 12 对的逐对分解给出——第一角色视图的压缩效果只贡献 **+0.35 个百分点**（`first_role_tokens` 相对差 × 第一角色占比 ≈0.57% × 约 59%），剩下的约 **+0.51 pp** 来自决策者侧压缩与逐对轨迹涨落（逐对估计值从 −0.62% 到 +2.62% 波动）。也就是说：

- **只有"第一角色视图"这一侧才可能通过"不压缩"改变模型行为**，而它的可压缩幅度上限只有约 **+0.35 pp**（≈0.35%）；
- 整体混合臂的受限上限是 **+0.86%**，其中大部分不是第一角色侧的贡献，而决策者侧与行为无关；
- 即便把"第一角色把 5% 视图全部省掉"这种不可能的情形代入，上限也只有约 `59% × 5% ≈ 3%`，而实测第一角色视图的可压缩幅度（0.57%/调用）远低于此。

## 4. 决策：不付费（估值 <3%）

预注册规则：估值 ≥3% 才付费。**受限上限 +0.86%（乐观上限 +5.48% 已被证明是"少调工具"混杂，不能作为依据）→ 不付费。**

因此：

> **该宿主在"保住第一角色视图完整"的前提下，节省上限不足 3%（实测上限 +0.86%，且其中 8/12 对为正但幅度极小），不值得再付费。**

不新建 r14 批次、不写冻结、不写 runner/审计；不触碰 r13 及更早的评分与冻结。**因此本轮也不需要 `*_FREEZE_AMENDMENT_*.json`**（没有既有冻结被修订；该流程改进自本轮起对后续冻结生效：冻结写定即不可改，修订必须另建 amendment 并记录新旧 SHA256，批次 manifest 记录冻结文件自身的 SHA256）。

## 6. 该宿主的最终收口结论

**该宿主目前没有可引用的正收益；并且已证明"保住第一角色视图完整"这一收缩方向的上限不足 3%（+0.86%），因此该方向不值得再投入付费实验。**

支撑链条（每一环都有冻结批次与独立审计）：

1. **r9→r13 机制链**：v9 钉住（r9）→ 同机制换新任务（r10）→ host 指令（r11，被证伪）→ 最近 K=1 轮保护（r12）→ K=3 全轮保护 + 预注册合同措辞（r13）；
2. **质量链**：插件严格/语义 6/9·9/9 → 6/16·6/16 → 0/16·0/16 → 7/16·7/16 → **12/16·12/16**；首轮事实齐全自 r9 起 9/9→16/16→4/16→16/16→16/16；配对均值 +8.01%（无效）→ +11.81%（无效）→ −68.28% → +6.36%（无效）→ +6.25%（仍无效）；
3. **根因归属**（每条都由机械判据判定）：首轮事实丢失 = **v9 已修**（16/16、补救 0）；合同占位符回抄 = **模型行为 × 合同措辞**（r13 预注册措辞消除 6→0）；少调工具 = **模型行为**（r13 逐边界对照证明内容不缺）；host 指令 = **已证伪杠杆**；压缩收益空间 = **被质量门与"跳过工作"涨落吃掉**（本轮受限上限 +0.86%）；
4. **可引用性**：r9–r13 五批的插件配对正收益**全部伴随质量下降**，且 r13 审计 `errors` 非空 → 均不得作为有效节省引用。

## 7. 方法与不确定性（必须随数字一起引用）

- 估算是**代理指标**：它假设决策者侧保留冻结机制的效果且无行为回归、假设"第一角色不压缩"不带来其它成本变化（不增加调用、不增加辅助请求）。这些假设**有利于**该臂，因此 +0.86% 是**偏乐观**的上限而非保守值；
- 全批 +5.48% 与受限 +0.86% 的差额（4.6 pp）**全部**来自 4 个"插件少调工具"的样本，这是 r13 已归因的模型行为，不是压缩收益；
- 4 任务 × 4 重复只有 4 个任务层观测点，无置信区间；温度 0 仍有独立轨迹差异；
- 三宿主数据不得合并；本文件不修改任何既有批次的评分、冻结或 `audit.json`。
