## Django 的模型边界证据

三个重复的首个模型输入，三臂 SHA256 各自相同。插件第二次调用前的 `filter_before` 均含 `other annotations`、`filter`、`ordering` 字面约束；压缩后的 `filter_after` 与实际 `model_input` SHA256 一致，且三次均从普通消息移除了这三条字面命中。受保护的源码工具组前后哈希相同：`filter`、`ordering` 仍可在保护组中命中，但 `other annotations` 在压缩后完整输入中也不再命中。基线与原生摘要第二次模型输入均保留这条约束，且各 3/3 给出过滤、其它注解、排序的引用判定。插件三次均改为只谈 `annotation_select_mask`，冻结评分 0/3。

这证明**插件送到模型的输入丢失了问题陈述中的一条可检索约束**，并与稳定错误答案同现；不能仅凭字面布尔值证明模型必然因此失败，也不能认为保护组里的 `filter`/`ordering` 足以传达完整任务。下一机制候选应逐字保留当前任务的问题陈述与短合同，再以前瞻性新批验证质量和成本；不得回写 v1/v2 结果。

限制：公开源码诊断，非真实修复；三个仓库任务已有调参与复验，非盲测；证据只有哈希、长度与字面命中，不存原文，也不能评价语义等价。`manifest.json` 沿用共享 runner 的旧 `data_class: synthetic_only` 字段，但 disclosure、任务输入与本协议均明确为公开源码；报告按公开源码解释。
