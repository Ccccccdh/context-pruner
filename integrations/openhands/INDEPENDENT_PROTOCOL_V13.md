## 改动

v6 将已观察到的 TASK.md 完整正文置于受保护的任务合同；用文件版本治理消除重复/旧证据；从已观察代码选择任务相关函数和模块片段。省略部分通过文件路径、版本与范围指向 SDK 原事件，可用原编辑器重新读取。完整函数过大时不截断为伪完整函数，而留在归档并提供读取范围。

v6 使用适配器内的有界证据选择替代 v5 的中间件摘要路径；没有新增摘要模型调用。保存 SDK 原事件与选择记录，不声称实现跨进程归档恢复或全部生命周期接口。未知摘要恢复时保留原视图。

压缩后以 SDK 的实际计数校核目标 10,000 和硬界 16,000。受保护用户内容/任务合同/最新完整工具批次单独超过硬界时保留原视图并明确记录无法安全压缩；不宣称能压缩不可删内容，也不把跳过记作成功。

三组初始用户消息均给出完整功能合同。各组均得到相同 scoped_tests 工具，只运行固定公开回归，最多三次代码改变后的测试，未改变代码用缓存。不接受任意命令或路径；测试进程凭据隔离。特定功能验收仍由外部主机执行。

SDK 每阶段最多 200 步，独立的模型请求总预算仍为 Agent 36 次，摘要 16 次，最大输出 3,072，单次估计输入 80,000，总输入估计 2,000,000。统一调整所有组，避免压缩步骤提前占尽旧 36 步上限。明确要求实现完成且公开测试通过后立即 finish。

仍为 none、native_summary、pruner_v6 三组，同模型、温度 0、关闭 thinking，无 API 自动重试，独立等长不透明工作目录、组顺序轮换。2 个任务 × 3 次 × 3 组 = 18 个样本。运行前必须通过原版负对照、选定回归、参考可解性以及本地 v6 回放与预算测试。

首次请求前冻结任务、运行器、测试工具、v6/依赖源码、协议和环境版本。所有已经请求过的失败保留，不替换或改写。全部样本结束后停止请求并独立审计。
