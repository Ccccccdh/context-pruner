# V7 统一读取入口离线验证与扩大开发协议

用户明确要求：先离线实现与验证，没问题后扩大付费实验。此要求覆盖早期设计仅到设计/不付费的阶段限制；旧V6和所有历史协议、claim及结果保持冻结。

唯一新机制：原read_document在研究关闭后的current读取，A2由宿主先查当前任务可信归档，未命中回退；A0/A1正常读。工具schema、提示、完整payload、V6来源清单、原生命周期TTL2和评分保持不变。宿主命中不能记作模型自主恢复，命中也仍计作研究后读取请求。

先做纯resolver测试和真实SDK MockTransport验证；用相同固定脚本检查A1/A2最终HTTP body等值、归档proof、普通回退、实际call_id、错误停止和未发送计数。等值意味着仅更换后端并不自动减少模型token。本次用户仍授权扩大自然流程开发验证，以观察宿主实际复用；不把扩大实验当成省钱证明。

通过独立审查及完整离线门后，冻结四个新开发实例种子307/311/313/317，三臂各一次，共12样本，沿用轮换顺序。上限每样本16HTTP、192总HTTP、24000wirebytes、USD2保守最高价全未命中预留，任一触发即停。固定操作claim防止换freeze重复预算；不重试、替换或按有利结果扩样。基础设施/完整性错误停止并保留完整分母及未知费用。

12样本是扩大开发，不是正式质量非劣/稳定节省确认。主要机制指标：研究后read请求数、宿主已验证查档命中、后续成功SDK/HTTP边界确实带有该payload的投递数、source payload构造调用、独立来源校验调用。原模型缺失信号及生命周期恢复单列。不得把source读取变成archive就把重读次数清零。

完整费用、命中/未命中/输出token和质量均保留，四实例一重复只作描述性分析。provider/cache/模型轨迹会造成价差；不能把A2与A1价差自动归因于宿主命中。当前源内容主要从任务内存序列化，来源校验I/O仍保留，不虚称省掉昂贵源文件加载。

只发送生成的registry数据到https://api.deepseek.com/chat/completions，不上传源码、真实用户数据或凭据。按冻结并核验的DeepSeek flash单价计算usage低/高估价，非账单核销。旧503和未知usage单独保留。扩大开发结束后停止，不自动进入正式实验或下一候选。
