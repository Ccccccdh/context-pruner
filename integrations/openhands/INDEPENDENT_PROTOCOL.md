# 独立项目功能任务验证 v11（首次请求前冻结）

## 问题与范围

验证冻结的 ContextPruner v5 能否在新的自然开发任务中保持质量并减少真实总输入。使用 Click 8.2.1 和 packaging 25.0，提交号、公开地址、功能合同及验收测试见 independent_tasks.py。这是评估者设计的功能扩展任务，不是上游漏洞复现，也不是随机抽取的工业任务样本。

任务涉及命令注册、装饰器、查找、补全与原子错误处理，以及依赖名称、版本、marker、extras和迭代器筛选。允许 Agent 自行决定相关阅读和编辑；不通过强制重复读取或填充日志制造长上下文。若部分样本没有触发压缩，直接报告，不能把其组间差异归因于压缩。

## 三组和预算

- none：SDK NoOpCondenser。
- native_summary：SDK LLMSummarizingCondenser，阈值 12,000，保留前两事件。
- pruner_v5：冻结 v5，触发 12,000，目标 10,000，软硬界标记 16,000。
- 2 个任务 × 3 次 × 3 组，共 18 个独立样本；按任务及轮次轮换组顺序，等长不透明工作目录。
- 同模型 openai/deepseek-v4-flash、同工具、温度 0、关闭 thinking。模型仍可能非确定。
- 每样本最多 36 次 Agent 调用、8 次摘要调用，每次输出 2,048；估计输入单次 40,000、总计 700,000。估计值仅用于预算，效益使用供应商实际返回计数。
- 三阶段：只读诊断、实现、外部测试反馈后修正或直接结束。最后再次验收。全组均相同。
- 不自动重试 API，不替换失败样本；恢复命令只跳过已有报告。Windows 原子写入兼容重试仅针对本次输出目录，单独记录。

## 运行门槛与停止规则

原版选定回归必须通过；新功能验收必须失败；只在主机隔离目录中的参考实现必须通过同一验收加回归。参考实现不进入 Agent 输入。测试进程不继承 API 密钥。首次模型请求前冻结源文件哈希、安装版本和协议。

完成全部 18 个样本后停止请求并审计。发生无请求本地故障则保留报告并暂停修复基础设施；已经发生请求的任务失败或 API 失败保留为正式结果。不得看完结果再改任务、验收或插件，并在同一轮冒充确认性结果。

## 统计和结论

报告每组正常完成率、最终代码验收通过率、Agent 与摘要实际输入输出、摘要调用、失败调用、峰值估计输入及压缩事件。配对减少率为 1 - 方法总输入 / 无压缩总输入；摘要开销必须计入。供应商未返回 usage 的失败请求其消耗未知，不能解释为节省。

保留全样本结果，并分别展示 API 正常与双方任务通过的敏感性子集。平均减少 30% 是待验证目标，不能通过剔除失败、早停或无压缩样本来达成。仅两个自编任务、每任务三次不能证明广泛质量等价或外推到所有 Agent；若压缩未充分触发或结果不稳定，结论为尚未确认。

只覆盖选定的上游测试模块，不声称通过完整上游测试。供应商价格映射缺失，金额未知，SDK 显示零不能解释为免费。
