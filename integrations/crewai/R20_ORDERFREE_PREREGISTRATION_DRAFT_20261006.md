# CrewAI r20 顺序无关任务族：预注册（草案，冻结前）

状态：**零 API 草案**。本文件在 r20 获取批与三臂批之前写定；冻结后不得修改，只能另开修订文件。

## 0. 不追溯声明

**本预注册只适用于 r20 任务族。** r15、r16、r17 保留其**精确顺序**判据、已记录的失败单元与评分，**一律不追溯、不重算、不改写**。r17 确认批的 20 次守卫拒绝与 3 个 `complete_but_misordered` 单元作为历史证据原样保留。

## 1. 合同（r20 任务族）

- 第一角色：**四份冻结证据源每份至少读一次**；**读取先后不限**；**允许重复读取**。
- 第二角色：按冻结规则作出**一个可核验决定**，并输出精确的 `RESULT` 合同。
- 机制与守卫：**在本预注册写定后冻结**；任务集在机制与守卫冻结后**独立选定**。

## 2. 判据 id（`experiments/audits/criteria_crewai_r20_orderfree.py`）

| 判据 id | 内容 | 性质 |
|---|---|---|
| `CRIT_R20_COVERAGE` | 每份冻结证据源在**宿主记录的工具轨**里**至少出现一次** | **质量侧的一部分**（未读到的证据无法贡献其事实） |
| `CRIT_R20_REPEAT_REPORT` | 逐单元重复次数、调用数、重复的工具名 | **报告项，永不作为门** |
| `CRIT_R20_SAME_WORK_REPORT` | 同工作量判定（调用数相同或工具轨相同）、重发超额调用数 | **报告项，永不作为门** |

全部从 `first_role_trace`（宿主记录）计算，**不读模型叙述**；该模块不导入任何 runner。

## 3. 验收线（三条）

1. **质量门 = 仅冻结 r8 judge**：逐任务**严格与语义成功数不低于基线臂**（且 `CRIT_R20_COVERAGE` 全单元满足）。
2. **成本门 = 完整供应商 token**：配对多数为正且**批均值为正**；**全部重复、补救与守卫请求全额入账**；**缓存只改变美元、不改变 token 计数**。
3. **完整性/账本**：请求账本闭合（逐行计入全部请求，含摘要与异常尝试）；冻结与源钉住无未登记漂移。

**失败线**（任一条触发即止，不换样本找正数）：插件臂 `guard_exhausted > 3/12`；**非插件臂出现守卫触发**；审计 `errors` 非空（此时明文"不得当作有效节省"）。

## 4. 为何"同工作量从门降为报告项"不是放宽质量

- 在这些任务上，**决定依赖证据的集合**：**是否读全**是质量问题（`CRIT_R20_COVERAGE` 仍参与质量侧），而**顺序与次数只是实验控制量**——它们改变成本，不改变正确性。
- 因此原质量判据**从未引用顺序**；把控制量降为报告项**不可能放进一个错误决定**（r8 仍逐任务检查事实与决定）。
- 反之，**把控制量当门**会像 r17 那样**让一个正确回答因为与正确性无关的属性而失败**；设计 D 移除的正是这条人为失败。

## 5. 投影与不确定性（必须随数字引用）

- 设计 D 的三口径（观测 −9.73%、剔除守卫重发 20 次调用 **+11.152%**、剔除全部超额 35 次 **+27.80%**）是**在 r17 轨迹上的算术**，**不是活体无守卫运行**：计数来自记录账本、单价来自记录均值、且守卫改变了对话。
- 因此**不得**表述为"设计 D 在 r20 上已成立"；r20 需要**自身载荷批与三臂批**才能判定。
- 备选②（"只补缺失证据"的补救）**已被缓存数据自我否定**：重发新增消息为 0、全按命中价计费（命中价为未命中的 1/50），故重发在 token 上本就不贵；真问题是**请求次数与补救的有效性**。**该方向不再推进。**

## 6. 归因措辞

任何通过都必须写成"**在装有本轮控制器配置的主机配置下**，插件在等质量前提下省 X%"，**禁用**"压缩单独省了 X%""四判据达成"。r20 任务是在守卫冻结后独立选定的，因此其结果可作为**确认证据**；但若机制在 r20 上未冻结，则仍只能作为开发证据。
