# v40 后续独立任务筛选规则（在查看下一候选元数据前记录）

v38/v39 的 Django 开发性复试均压缩了输入，但三组最终质量均未通过。
下一任务必须与已用的 pytest、pylint、Django 实例不同；同一实例
继续调参只能用于开发，不能充当独立验证。筛选仅读取本地
SWE-bench Verified Parquet 的路径和任务元数据，不读取参考修复正文。

优先选难度 **15 分钟至 1 小时**、参考修复涉及 2～4 个 Python 源码
文件、有至少 1 个目标测试且 PASS_TO_PASS 不超过 150 项的实例；
组内按问题创建时间从新到旧。若此档没有通过功能门控的候选，再按
同样规则考虑 **1～4 小时**难度。公开基线对应文件合计需至少
50 KB，并有真实跨模块调用或状态流；字节数仅作弱代理，不保证
Agent 会达到压缩阈值。若调用链局限短函数或主要改动是文档，跳过。

对候选依次做零 API 门控：固定提交、公开测试可运行、目标测试
原版失败、宿主参考实现通过、补丁隔离、测试前后源码哈希稳定。
环境门控失败应记录并继续，不按预期模型收益调换候选顺序。
先使用 v40 的完整失败索引在已保存日志上离线验证，再为选中
的新任务适配固定测试工具与三组运行器。任何新任务的模型上下文
和付费 1×1×3 运行都要另行授权；未获授权只做离线准备。
