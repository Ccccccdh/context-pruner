# CrewAI r27 可变来源开发小试协议

目的：测试覆盖守卫与任务规模自适应的工具轮保护能否支持不同工具数和跨来源判断。两项任务为三来源货运发运和五来源集群转移。初次零 API 演练中，五来源 Pruner 虽读全工具并给出正确答案，但固定 K=3 造成一次工具组恢复失败；因此在任何付费请求前把 K 改为任务必需来源数，并将本批降级为**开发小试**。此批任务已参与机制修复，不构成独立确认。仍属两角色合成任务族，并非自然软件开发任务。

设计：2 任务 × 3 重复 × 3 臂，共 18 样本；无压缩、Pruner、原生摘要全臂安装同一顺序无关覆盖守卫。第一角色对任务定义的全部来源各至少真实调用一次，允许换序与重复；第二角色独立调用最后一项检查并回答。Pruner 第一角色保护最近 `K=必需来源数` 个完整工具轮（本批分别为 3 和 5），第二角色保持 K=0；这只变更插件上下文保护，不改变任务、模型或守卫。每第一角色最多六次拒绝提前交接。模型 `deepseek-v4-flash`、thinking disabled、单次输出上限 512、每样本摘要上限 4 次，全批供应商请求硬上限 270；每次发送前持久化请求槽，不续跑中断批。

零 API 门：任务结构与答案规则通过校验，`--plan` 不创建批次，18 格 mock 全部运行、严格/语义通过、独立审计干净。负控制应拒绝伪造来源轨迹和缺失逐调用捕获。零 API 通过后写一次最终冻结，API 只接受最终冻结。

独立审计从供应商逐调用捕获中的角色与宿主执行工具重建覆盖，并核 runner 轨迹、完整 Agent/摘要 token 和持久槽；还应核插件第一角色的 K 与任务来源数一致且工具组恢复失败为 0。质量门：两任务三臂来源覆盖各 3/3、零守卫触顶；每任务无压缩严格至少 2/3，Pruner 严格和语义均不低于无压缩。成本门：每任务至少 2/3 配对完整供应商 token 为正且总差为正，全批至少 5/6 为正且总差为正。两门同时成立才算**开发小试**通过；任一失败不在同任务调参重跑。

即使通过，该批仍不能作为通用或自然任务效果，`can_be_quoted_as_saving=false`。
