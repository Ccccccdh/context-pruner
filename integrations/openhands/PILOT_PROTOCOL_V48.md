# v48 多重复冻结说明（Django 17084，3 重复 × 3 组）

本文件替代 [PILOT_PROTOCOL_V47.md](PILOT_PROTOCOL_V47.md) 作为当前批次依据。v47 的实例、提交、可编辑范围、
模型、端点、工具、导航、预算策略、阈值与各项上限**全部不变**；v48 只把**重复次数**从冻结的 1 改为 3。

## 1. 与 v47 的唯一差异

| 项 | v47 | v48 |
|---|---|---|
| `repeats` | `choices=[1]`，默认 1 | `choices=[1,3,5]`，**默认 3** |
| 预期样本数 | 3（1 任务 × 3 组 × 1 次） | **9**（1 任务 × 3 组 × 3 次） |
| summary 统计 | 仅点值 | 增加**重复级配对节省列表 + 均值 + 样本标准差 + 极值** |

**为什么只改重复数**：这样重复间的差异可以归因到**轨迹波动**，而不是协议变化。
任务、臂定义、模型、端点、工具集、导航、预算策略、提示词、评测与审计路径均与 v47 逐字一致。

## 2. 任务与门控

实例 SWE-bench Verified `django__django-17084`，基线提交 `f8c43aca467b7b0c4bb0a7fa41362f90b610b8df`
（Django 5.0.0a1 世代）。可编辑范围只有 `django/db/models/sql/query.py`。

零 API 门控沿用 `runs/stage5-openhands/django-17084-v47-gate-01/gate.json`：
原版 + 宿主补丁 = 125 项 1 error（目标测试失败）；参考修复 = 125 项全绿；测试不改源码。
v48 的 `--check --repeats 3` 已复验：公开回归 124 项全绿、宿主门控 125 项 `errors=1`、
评分副本不改动 Agent 工作区、manifest 90 项源码哈希零不匹配。

## 3. 三组与共用条件

无压缩、OpenHands 原生摘要、Context Pruner v42 各 3 次，共 9 个样本。
每个样本都是**独立会话 + 全新工作区**；臂顺序按 `(repeat + index) % 3` 轮转，
使臂顺序效应在重复间保持平衡。三者共用相同 v44 符号工具、公开源码阅读与编辑工具、
公开回归工具、预算策略、导航与失败反馈，**只比较压缩机制**。

## 4. 端点与预算

端点 `https://api.deepseek.com`，模型 `openai/deepseek-v4-flash`，温度 0，thinking 关闭，
不重试模型请求。每样本最多 36 次 Agent 请求与 16 次摘要请求。

| 项 | 数值 |
|---|---|
| 单次重复实测（v47） | 69 次请求 / 961,923 输入 tokens |
| 3 重复预计 | **约 207 次请求 / 2.9 M 输入 tokens** |
| 3 重复理论上限 | **468 次请求** |
| 预计运行时长 | 约 35–45 分钟（v47 单次约 12 分钟） |

供应商 usage 计入摘要请求；金额由账单核对，SDK 的零价格字段不代表免费。

## 5. 统计口径（本版本新增）

`summary.json` 新增两个块：

- `per_repeat_paired_savings`：逐重复记录 `baseline_input_tokens`、`arm_input_tokens`、
  `paired_savings`、`both_success`；
- `dispersion`：每臂给出 `repeats`、`paired_savings` 列表、`mean`、`sample_stdev`、
  `min`/`max`、`both_success_repeats`。

**主统计仍是全部样本的配对节省率**（含失败、未压缩与负收益样本），
离散度只是补充描述，**不替换主指标**，也不是置信区间。

**为什么这一步必要**：v47 同一次运行内两臂相差 24 个百分点（原生摘要 +65.23%、插件 +41.03%），
单点无法估计波动；3 重复是产出离散度的最小规模。

## 6. 停止规则

出现余额或连接异常**立即停批**，保留全部失败样本，不用成功补跑覆盖；
插件未触发压缩或质量不对等时，不把组间输入差异归因于压缩。

## 7. 本轮的解读边界

- 3 重复解决"波动未知"，**不解决"单任务"**：结论仍限于这一个实例；
- 多任务（≥3 个实例）是本轮之后的下一步，两者不得合并成一个总节省率；
- 峰值上下文与压缩开销必须**单独报告**：v47 峰值仅 −17.7%，未达 README 的 ≥30% 目标；
- 单宿主结果不得外推为跨宿主结论。

## 8. 本机环境前提

付费批次应在**普通 PowerShell 窗口**经 `integrations/openhands/launch_normal_windows.ps1` 启动，
不在 DSH 沙箱内运行：沙箱 ACL 会造成**组间不对称**的编辑器写入失败
（v45 0/2/2、v46 3/3/4、v47 2/2/1）。启动器已实测 `Probe` 通过。
