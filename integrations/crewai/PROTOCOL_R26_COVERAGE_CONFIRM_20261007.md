# CrewAI r26 前瞻确认协议

目标：检验 r25 覆盖守卫能否迁移到三个**未参与 r24/r25 守卫开发或调参**的合成任务。任务为证书轮换发布、库存隔离审核（负向决定）、备份恢复结项。它们使用同一两角色、四来源任务族，因此即使通过，也只能证明此任务族的迁移，不能外推到自然任务或其他 Agent。

设计：3 任务 × 3 重复 × 3 臂（无压缩、Pruner、原生摘要），共 27 样本。三臂都安装相同的顺序无关覆盖守卫：第一角色对四来源各至少实际调用一次，允许换序和重复；第二角色调用最后一项检查并作决定。拒绝提前交接最多六次，每次重发和摘要均全额计费。模型 `deepseek-v4-flash`、thinking disabled、输出上限 512、每样本摘要最多 4 次，全批供应商请求硬上限 360，发送前持久化请求槽，不续跑中断批。

零 API 门：写一次任务集并校验结构、`--plan` 不创建批次、27 格 mock 全部运行且审计通过；审计负控制必须拒绝缺失来源、伪造 runner 覆盖、漏计摘要、成本正而质量失败。最终冻结只在上述通过后生成。

独立审计：核冻结源码、27 格网格、请求槽和完整 Agent/摘要捕获；从每次真实供应商调用的系统角色与 `host_executed_tool` **重建**第一角色覆盖，和 runner 轨迹交叉核对；从冻结答案规则重新判严格/语义质量。只接受四来源全臂 9/9、零守卫触顶。每个任务无压缩严格至少 2/3，Pruner 严格和语义均不低于无压缩。成本要求每任务至少 2/3 配对正且配对总差正，全批至少 7/9 配对正且总差正。质量门和成本门同时满足才是本批确认通过。

任一门失败即如实报告，不调参数重跑同任务。无论结果如何，该批 `can_be_quoted_as_saving=false`：这是同一合成任务族的确认，非通用插件效果证明。
