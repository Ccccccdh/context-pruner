# 插件适用边界（OpenAI Agents 宿主，2026-10-04 收口版 v11）

本文件把 v4–v11 的实测结果收口成一条边界、一条方法论规则和一组未测量项。所有数字来自本仓库已冻结的批次；**跨宿主百分比不合并**。

## 2. 最终边界命题：该任务上的安全分界是**空集**

> 在 OpenAI Agents 宿主 + Django 公开诊断任务 + 冻结预算下，插件在本仓库从未同时满足"插件严格质量 ≥ 基线"与"配对完整总 token 为正"：
>
> - **不改变模型可见文本** → 收益恒为 0：v7（连续工具组、K=2）**0.0000 %**、v9（连续工具组、K=7）**−0.000004 %**（真实载荷 `turn_count ≡ 1`，新近度窗口保护整段历史）；
> - **改变模型可见文本** → 收益出现但质量掉：v11 在**最保守的正投影设置 M = 4** 上省 **+5.81 %**（正 3/3）而质量掉到 **2/3**；M = 2 只会更激进；M = 6 投影与实测都是 **0**（无省略即无收益）。**{2,4,6} 三点内不存在合格设置**；
> - 同批**原生摘要臂**同现象互证：省 **+12.55 %**（正 1/3）而质量同样 **2/3**——**该任务对"模型能看到什么"敏感**；
> - 更激进的省略更差：v10（M=1）省 27.68 % 而质量 **0/3**；v6 质量 **0/3** 且成本 **−176.36 %**；v5 质量 3/3 却因多走一轮 **−79.79 %**。

数字链（v5 零 API 分解，残差 ≈ 9e-13）：多走一次调用 = **+2,335.8** input token（v5 输入回退 **99.85 %**、约合短基线完整总 token 的 **79 %**），重传字节为**收益 −136.7**。

**结论：本宿主上"省 token 且质量不降"的组合没有出现，且已用省略比例消融证明它不是"比例没调好"——最保守的省钱设置仍然掉质量。**

## 3. 方法论规则（对三宿主适用）

> **(1) 零 API 桩不仅能错"轮次数"，还能错"载荷结构"。** 此后所有离线门控必须建立在已记录的真实载荷上（replay），而不是自造桩。依据：v9 的桩在工具项之间插入 assistant 消息 → 桩 `turn_count = 6`、投影 **+34.15 %**；真实载荷工具项连续 → `turn_count ≡ 1`、实测 **−0.000004 %**。v10/v11 改用 replay（对已付费批次的 `input-evidence` 逐边界断言 `message_items`/`item_count`/`tool_outputs`/连续性/结构指纹）后，投影与实测方向一致。
>
> **(2) 冻结文件一经写定不得再改。** 需要修订时另建 `*_FREEZE_AMENDMENT_<日期>.json` 记录"改了哪个字段、原因、新旧 SHA256"，并在批次 manifest 里记录**冻结文件自身 SHA256**，使事后改动可被检出。v11 起执行；此前 v7/v9/v10 的原地哈希刷新已在该修订文件中补记。

## 4. 守卫分类矛盾及其修正（正保护 + 负控制证据）

- 矛盾：守卫把**任务陈述全部文本单元**列为受保护，而缩减里还有"丢弃本次已逐字送达过的消息单元"的规则；请求那一行同时出现在陈述与请求消息中 → 被去重丢掉 → 守卫报 `missing_protected_unit` 整份回退。**同一守卫在 v7 短基线上也报过 5 次**（当时无可省略轮次，故无害）。
- 修正（v9）：受保护集合 = **承载注册字面的单元** + 注册字面单元 + 字面承载行 + 工具输出结构（陈述单元 8 → 2）。
- **正保护**：逐样本、逐模型边界、逐字面，插件 `registered_literal_counts` **不低于同一边界基线臂的计数**（v9/v10/v11 三个付费批次均通过）。
- **负控制**：收窄**按文本内容**判定——承载 `filter operations` 的行受保护、不含字面的请求行不受保护；把注册字面**注入请求行**后该行立即受保护（2 → 3 单元）；人为丢掉字面时 `_carrier_loss` 报损失、过滤器拒绝并计数。

## 5. 已知能取胜的区间（外部证据，属另一个宿主）

OpenHands v58（`integrations/openhands/PILOT_PROTOCOL_V58.md`）在 **933,719 token 前缀**、3 条分叉上测得：分叉后完整总 token **71,469** vs `none` 133,071 / `native_summary` 133,087 → **分叉后 +46.29 %**，全程口径 **+15.51 %**，独立审计 `complete: true`。那里的历史远早于当前轮、且压缩不改变当前轮可见内容。**该测量属 OpenHands 宿主，不与本宿主百分比合并。**

## 6. 没有测量、因此不作断言的输入

| 未测量项 | 为什么不能断言 |
|---|---|
| **{6,4,2} 之外的 M** | 预注册阶梯只有三点；按纪律不为凑正数再调 M。三点内已无合格设置，但更细的 M（如 5）未测。 |
| **"省略哪一边"的变体** | 本仓库只省略**更早**的工具调用；省略"更早但同属一次调查协议"的其他组合、或按 token 预算而非调用次数截断，均未测。 |
| **语义等价质量口径** | 本宿主只用冻结严格合同；v11 的 2/3 未做语义等价判定，因此不能断言"答案事实错误"，只能断言"未达预注册质量口径"。 |
| 其他任务 / 多任务 | v1–v11 的付费结果只有 Django 一个任务，且它在 v1–v4 已参与调参，不是盲测确认批。 |
| 其他宿主 | CrewAI / OpenHands 各自机制、任务与预算；百分比不合并。 |
| 真实代码修复任务 | 本宿主只做公开源码诊断（只读工具、不改代码），无宿主测试门控。 |

## 7. 收口结论

**在 OpenAI Agents 宿主上，插件目前不能被称为"有效节省"**：v11 的省略比例消融把最保守的正投影设置（M = 4）实测为 **+5.81 %（正 3/3）但质量 2/3（基线 3/3）**，M = 6 无收益、M = 2 更激进；v10（M = 1）**+27.68 % 而质量 0/3**；v7/v9 在"不改可见文本"下收益恒 0；v5 质量保住但 **−79.79 %**，v6 两者皆负。**该任务上的"质量 × 节省"安全分界为空集，且已由阶梯消融证明不是比例问题。下一步若要继续，需要换机制方向（例如不改可见文本的结构化索引、或换用对可见文本不敏感的新任务），而不是继续在本任务上调省略比例。**
