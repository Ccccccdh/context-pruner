## 下一候选工作流及前瞻门

候选应采用**真实多角色证据交接**：第一角色按明确顺序读取至少四份相互独立的当前证据（例如配置、运行指标、变更记录、校验结果），第二角色按冻结规则作一个可核验的发布/回滚决定；历史里包含自然产生的过期讨论，但不重复铺设合成“第 N 次历史交接”。每项决策需有独立验收规则、固定事实和失败样本标签。至少四项未参与 r9–r13 调参的任务，避免再次由一项高收益掩盖其余任务。现有仓库 `tasks/stage4a/fixtures` 提供代码与文档素材，但尚未被 CrewAI 宿主执行，**不能冒充真实 CrewAI 模型输入**。

以下门在任何付费请求之前全部满足，任一失败则记录停止原因：

1. **真实载荷**：新任务的首轮与工具边界输入须从实际 CrewAI 宿主运行记录取得，并钉住来源和结构指纹；假模型桩仅可验证接口，不可用于收益上界。当前**没有新任务的真实载荷**。
2. **质量安全候选**：对每个决策边界标出当前任务约束、工具调用及结果、必需字面证据与仍需执行的工具；真实载荷 replay 后，只有这些全部保留且调用配对完整的旧单元可计作安全候选。第一角色的工具序列必须在压缩前后保持相同。
3. **收益上界**：在相同工作量下，扣除钉住、恢复、整份回退与辅助摘要调用，完整 provider token 的乐观上界须 **≥3%**，且至少三项任务各有非零安全空间；不得把少调工具或少调用模型算作收益。
4. **预注册付费小试**：若前三门全过，先冻结新 ID、源 SHA256、任务×重复×三臂矩阵、模型/预算/请求上限、发送数据类别和停止线；失败、触顶、恢复及摘要请求全额计入。严格、语义、首轮事实和工具序列均以基线为下限，完整 token 多数配对为正。小试仍需独立审计，随后再做未参与调参任务确认。
