# 三宿主实验阶段结论（2026-10-03）

本报告把 OpenHands、OpenAI Agents 与 CrewAI 的结果并列。任务、输入规模、压缩机制和质量门控不同，不能把三宿主的节省率合成一个“插件总收益”。

| 宿主与批次 | 样本与质量 | 插件配对输入节省 | 含辅助调用总 token 节省 | 适用范围 |
|---|---|---:|---:|---|
| OpenHands v53（Django 三任务） | 27/27 完成；插件 8/9、基线 6/9 通过选定宿主测试 | **−36.25%**，正 5/9 | **−35.80%** | 公开 Django 代码任务；独立验收 27/27 |
| OpenAI Agents v2 三轮场景变体 | 27/27，三臂 9/9 结构与答案门控通过 | **+57.94%**，正 9/9 | **+55.41%** | 合成工具任务，三轮输入历史不同 |
| CrewAI v2-R2FIX 两层历史变体 | 18/18，三臂 6/6 任务门控通过 | **+13.27%**，正 6/6 | **+11.98%** | 三个合成任务、8/9 条历史两层 |

原生摘要对照在 OpenAI Agents 和 CrewAI 均减少了 Agent 输入，但加入摘要请求后总 token 分别为 −33.87% 与 −42.14%。OpenHands v53 原生组的 +12.06% 输入配对节省发生在 **0 次摘要请求** 的批次，因而不能解释为摘要机制的收益。

## OpenHands 阈值消融的关键事实

v53 只把 v52 的上下文预算统一扩大 1.4 倍：插件 trigger 20,000→28,000、target 16,000→22,400、hard 28,000→39,200，原生上下文 24,000→33,600。实际插件压缩从 v52 的 6 次降到 v53 的 2 次，阈值确已影响触发。插件跨任务配对节省从 v52 的 −5.44% 变成 v53 的 −36.25%，任务和重复间差异仍很大；提高阈值未得到稳定正收益。

离线回放纠正了一项旧判断：v52 的 6 次压缩全部属于 `lookup_allowed_foreign_primary` 三个样本，各 2 次；`referenced_window_wrapping` 没有发生压缩，它的 −67.79% 极端负号来自独立 Agent 轨迹差异，不能作为压缩丢失信息的证据。v53 的两个最大负号样本也在压缩前已消耗超过同重复基线的全程输入，因此当前批次无法将全部额外成本归因于压缩本身。

## 目前可支持的产品判断

两个新宿主的合成任务证明适配器可以正常接入并减少记录到的 token，同时保持这些任务的答案与结构门控。OpenHands 的真实代码任务尚未显示稳定节省。故综合插件应保留不同宿主的独立预算标定与触发策略，不应默认宣称对真实长任务也有正收益。

下一轮最有信息量的实验是：从同一真实任务、同一模型历史前缀分叉，分别继续运行不压缩与候选压缩策略，并对每个分叉做相同的功能测试；将任务成功率、完整费用与输入峰值同时报告。这样能缩小独立起跑导致的导航轨迹波动。跨宿主扩展时先选自然多步任务和公开可复现的质量门控，再按宿主分别分析，不混合样本均值。
