### 严格失败的准确原因（属判据层，不是模型缺陷）

r9 的 9 个严格失败全部是 `region_failover` 的答案里 `headroom=45%` **紧接**下一个证据字段（`capacity_region=ap-south-1`）。冻结判据 `_fold` 把 `=` 折叠为空格后 `capacity_region` 与 `45%` 直接相连，得到 `45%capacity_region`；严格门的 `_ordered_present` 要求字面量末尾有词边界，因此不匹配，而语义判据 `_literal_present` 的宽松边界接受它。9/9 失败样本在**只放松末尾边界**后都通过。即：**同一段文本，语义判据判对、严格判据判错**，属冻结判据自身的折叠/边界不一致；本批按约定不修改已冻结判据、不重打分旧批，如实记录。

## 5. 判定

1. **质量**：严格 6/9、语义 9/9、首轮事实齐全 9/9；插件相对无压缩在三套门指标上都**不劣**（严格 6/9=6/9、语义 9/9=9/9、首轮 9/9=9/9，`quality_non_inferior: true`、`first_pass_non_inferior: true`）。
2. **成本**：插件完整总 token 配对均值 **+8.01%（8/9 正）**，**任务间离散度 22.50 个百分点**；其中 `region_failover` 的 −0.26% 在输出波动量级之内，**不能称为压缩收益**。
3. **机制**：首轮事实齐全**不再依赖事后补救**（补救 0 次，首轮 9/9，钉住 36 次、全前缀回退 0 次）；这是本批相对 r8 唯一改变的东西。
4. **因此本批支持的最强表述是**：*在该模拟运维双角色矩阵上，v9 必需事实钉住机制使插件首轮交接事实齐全达到 9/9 且不再需要补救调用，三套门指标均不劣于无压缩，全批配对成本 +8.01%（8/9 正），但收益仍集中在 1 个任务（+22.25%），另两个任务接近零，**3 任务×3 重复不足以建立跨任务稳定节省**。*

## 6. 边界（必须随数字一起引用）

- 全部为**合成运维任务**：固定工具返回、模拟双角色流程；不含真实代码修复、真实仓库、生产工作流或跨 Agent 通用结论。
- **3 任务 × 3 重复无法建立跨任务稳定节省**：`region_failover` 的配对均值在 0 附近，收益几乎全部来自 `queue_backlog_replay`；引用 +8.01% 必须同时引用 22.50 pp 离散度与逐任务配对值。
- 温度 0 仍有独立轨迹差异；r8 与 r9 是**两次独立付费运行**，其差值不是压缩或钉住效应的直接度量。
- 严格判据的 6/9 与语义判据的 9/9 都必须报告；本批严格失败的成因已定位为冻结判据的 `=` 折叠与末尾词边界不一致（§1），**不修改已冻结判据、不重打分旧批**。
- 钉住把 r8 的部分输入节省转成了首轮正确率；把 +8.01% 与 r8 的 +10.99% 相比时，必须同时给出补救次数（6→0）与首轮齐全（3/9→9/9）。
- 零 API 栅格的可复现性：同一命令重跑得到的 27 行记录在**把墙钟 `latency_seconds` 归零后与冻结栅格逐字段相同**（`tests/test_crewai_handoff_v9.py::test_repeated_grid_runs_are_record_identical` 是进程内版本）。
- 三宿主数据不得合并；r5/r6/r7/r8 的目录、冻结与评分保持原样，本批不重写它们。
- 机制模块的 v9 中间版本（早期一次基于"任务陈述含 ReAct 标记"的合同识别）已被修正为"唯一非 system 且带冻结 `HANDOFF` 标记的消息"，冻结哈希对应的是修正后版本；`--plan` 与 27 样本付费批都在冻结写入之后运行。
